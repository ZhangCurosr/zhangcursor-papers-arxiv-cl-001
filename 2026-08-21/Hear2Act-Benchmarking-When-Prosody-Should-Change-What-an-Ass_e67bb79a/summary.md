# 论文速读：Hear2Act-Benchmarking-When-Prosody-Should-Change-What-an-Assistant-Does

## 一句话总结
本文提出 **HEAR2ACT** 统一评估协议，用480个受控场景测试语音助手能否利用韵律线索做出更好的任务导向对话决策；实验发现当前音频大模型虽能从语音中恢复顾虑信息，但若不将其显式文本化，则难以可靠地转化为下游行动。

## 研究问题与动机
- **评测割裂问题**：现有基准要么只评估韵律感知/情感识别，要么只评估任务导向对话的成败，缺乏将"韵律证据→多轮决策→可验证结果"完整链路纳入统一框架的测试协议。
- **决策价值不明**：难以回答"韵律在什么时候能为任务决策提供词汇之外的情报"以及"模型能否把听到的韵律线索真正用到后续行动中"。
- **感知-行为鸿沟**：即使模型能感知韵律，其感知结果是否能在多轮交互式任务中转化为改进的选择与停止策略，尚不清楚。
- **词汇 vs 韵律的互补性**：当顾虑已在词汇中显式表达时，韵律是否仍有决策价值？二者如何分工？

## 核心贡献（创新点）
1. **提出 HEAR2ACT 基准**：构建了480个包含隐藏三层顾虑（硬约束/强偏好/中度偏好）、11个候选选项、可客观打分的最优解的场景，填补了"韵律感知→任务行动"的评测空白。
2. **配对滚动对比协议**：在同一场景下固定任务与用户目标，仅改变助手的输入访问条件（纯文本、纯音频、文本+音频、文本+真实顾虑状态、文本+音频推断状态），从而精准隔离韵律证据的决策价值。
3. **发现并量化感知-行为鸿沟**：音频LLM能从语音中以较高准确率（Qwen2.5-Omni 达0.85）恢复顾虑状态，但直接利用音频时最优解率仅从14.6%微升至15.3%；一旦将推断的顾虑状态以文本形式注入决策阶段，最优解率跃升至39.6%，逼近真实状态的40.7%。
4. **揭示词汇-韵律的互补边界**：在"显式词汇反馈"条件下，所有输入条件间的性能差距基本消失（最优解率仅波动5-6个百分点），说明韵律价值主要在词汇证据不足时体现，支持选择性利用韵律线索。

## 方法详解
- **场景结构**：48个领域（源自 SGD 服务类别）×10种子 = 480个场景。每个场景含一个表面请求、三个隐藏顾虑层次（L1硬约束、L2强偏好、L3中度偏好）和11个候选选项（8个覆盖顾虑满足模式的组合、1个安全选项、2个违反显式要求的选项）。
- **确定性用户引擎**：给定助手动作（ASK/CLARIFY/RECOMMEND/CONFIRM）、当前对话历史和场景配置，引擎决定哪些顾虑仍未解决、允许披露的信息量以及用户如何回应；反馈随后由文本真实化器转为自然话语，并由 TTS（Qwen3-TTS / VoxCPM2）渲染为语音。
- **两种反馈实现**：
  - **Prosody-mediated（韵律中介）**：硬约束违规在词汇中明示，软顾虑仍隐于词汇，主要通过语调/节奏暗示"当前推荐仍未被接受"。
  - **Explicit lexical（显式词汇）**：顾虑直接以词汇形式出现在用户话语中。
- **输入访问条件**（针对口语助手）：纯文本(T)、纯音频(A)、文本+音频(A+T)、文本+真实顾虑状态(T+S)、文本+音频推断状态(T+Ŝ)、以及两种通用情感识别基线（HuBERT-SUPERB-ER、SpeechBrain wav2vec2-IEMOCAP）。
- **两阶段干预**（T+Ŝ）：第一阶段让模型根据当前用户音频推断顾虑状态并以一句话文本记录；第二阶段移除音频，仅把转录文本与推断状态一起送入决策提示以选择下一动作。
- **评价指标**：最优解率（1st%）、推荐后非负选项接受率（OptSat%）、推荐后满意互动率（SvcSat%）；行为诊断包括 ASK/CLARIFY/RECOMMEND 比例、隐藏顾虑披露数、对话长度、过早锁定次优选项比例。
- **统计方法**：以场景为统计单元，配对bootstrap 95%置信区间（2000次重采样），避免将同一场景的多次滚动视为独立样本。

## 实验与结果
- **数据集规模**：480个场景，扩展为54,240个评估回合（覆盖文本/口语助手、不同渲染器、不同干预条件）。
- **主要模型**：口语助手 Qwen2.5-Omni-7B、Qwen2-Audio-7B-Instruct；文本LLM Claude Opus 4.6、Kimi K2.5、DeepSeek-V3.2、GLM-5、Qwen3-32B。
- **韵律中介条件下的核心发现**：
  - 最优解率：T=14.6% → A+T=15.3%（几乎无提升）；T+Ŝ=39.6%；T+S=40.7%。
  - 通用情感识别（HuBERT）：32.6%，低于任务对齐的音频推断状态（39.6%）。
  - 文本+真实顾虑状态下五模型均值提升：**+36.7个百分点**（26.9%→63.5%）。
- **显式词汇条件下的对比**：各条件间最优解率差距极小（5-6个百分点），说明词汇已充分承载信息时韵律的边际价值低。
- **行为诊断**：
  - 正确顾虑状态使五模型平均 ASK/CLARIFY 次数从1.8次增至4.4次，全部三层顾虑披露率从3%升至30%。
  - 过早锁定次优选项比例从69.7%降至26.7%。
  - 错误标签条件下（全正/全负/打乱）即便提问频率相近（44-45%），最优解率仍大幅下降（35.4-53.3% vs 68.1%），说明收益来自**正确回合级顾虑信息**而非单纯增加提问。
- **最强结果**：T+S 条件在韵律中介场景下达到40.7%最优解率；通用情感基线（HuBERT）亦可达到32.6%，显著高于直接使用音频。

## 相关工作脉络
- **MultiWOZ / SGD / SpokenWOZ**：任务导向对话基准，具备多轮交互与可验证成功，但未隔离韵律线索对序列决策的影响（缺 P/C/N 维度）。
- **StyleTalk / ParaS2S**：控制词汇内容评估口语响应适当性，但仅做单轮评估，缺乏多轮任务轨迹与可验证的最终选择。
- **MULTI-Bench / HumDial-EIBench**：关注多轮情感智能评估，但没有以候选选项为核心的隐藏需求与可验证任务结局。
- **LISTEN / ParaBridge / PALLM**：同样识别"感知-行为鸿沟"，但侧重于副语言分类或单轮响应生成；本文则在受控多轮任务中精确量化该鸿沟的规模及填补路径。
- **EmoWOZ / EmoUS**：为任务对话添加情感标注或用户模拟，但未把"韵律如何改变信息搜集、停止时机与最终推荐"纳入统一评测。
- **本文定位**：首次提供"韵律证据→多轮 elicitation → 停止判断 → 可验证最终选项"端到端可度量的评测框架，同时支持文本与口语助手在同一任务中的对比。

## 局限性与未来方向
- 仅隔离了韵律的一项决策功能（推荐是否仍"未解决"），未覆盖更广泛的偏好结构与韵律其他语用功能。
- 用户话语与语音均为合成，无法完全捕捉真实自然对话的变异性。
- 真实顾虑状态（T+S）作为诊断参考而非部署场景；音频推断状态（T+Ŝ）同时引入了显式表示和额外推理步骤，尚未完全隔离具体机制。
- 未来方向：① 在更自然的语音交互环境中验证框架；② 探索端到端利用韵律的模型架构，减少对显式中间文本表示的依赖；③ 扩展涵盖更多韵律功能与用户偏好结构。

## 研究启发与可借鉴点
- **中间表示桥接感知与行动**：将模型从音频推断出的任务相关状态以文本形式注入决策流程，可显著缩小感知-行为鸿沟，该方法可直接迁移到其他多模态对话系统。
- **配对场景实验设计**：固定任务与用户目标、仅改变输入访问条件的配对滚动对比，能精准量化某一模态或特征的边际决策价值，适用于各种多模态评测。
- **确定性用户引擎 + 结构化顾虑层次**：用L1/L2/L3三层顾虑定义候选选项的满足模式，使"最终选择正确性"可客观打分，避免了主观评价的不稳定性。
- **词汇-韵律互补性的定量刻画**：通过显式词汇 vs 韵律中介两种反馈条件的对照，为"何时依赖哪类线索"提供可操作的判据，可指导多模态路由策略的设计。
- **通用情感识别 vs 任务对齐状态的对比**：证明通用Affect表征（HuBERT/SpeechBrain）有一定收益，但任务对齐的顾虑状态收益更高，提示下游任务应优先定制而非直接复用通用感知模型。

## 关键术语表
- **HEAR2ACT**：统一评估协议，用于衡量韵律线索在何种条件下应改变任务导向助手的决策与最终行动。
- **Prosody-mediated feedback**：用户顾虑主要通过语音语调传达而未在词汇中明示的反馈实现方式。
- **Explicit lexical feedback**：用户直接在话语中陈述顾虑的反馈实现方式。
- **Audio-inferred concern state (Ŝ)**：模型根据音频推断的任务相关顾虑状态，并以文本形式供给下游决策。
- **Ground-truth concern state (S)**：由确定性用户引擎生成的回合级真实顾虑状态标签（包含分级如satisfied/lukewarm/concerned/frustrated）。
- **Optimal-solution rate (1st%)**：多轮对话结束时推荐为三层顾虑全部满足之最优选项的比例。
- **Perception-action gap**：模型能感知韵律线索（高识别准确率）但无法将其有效转化为改进任务决策的现象。
- **Paired rollout evaluation**：在同一场景下对比不同输入条件的实验设计，控制任务与用户目标不变以隔离单变量的决策价值。
