# 论文速读：A knowledge-guided agentic framework for mitigating patient-context ambiguity in health queries

## 一句话总结
本文提出了一种知识图谱引导的智能体框架，在用户查询和下游 LLM 之间插入一个中间层：通过任务特定的知识图谱构建假设集合，以最大信息增益策略主动询问缺失的患者特定变量，将澄清后的上下文与原始查询结合后送入未修改的下游 LLM。该方法在症状诊断检索和饮食安全分类两个基准上分别将 Exact Top-1 准确率提升至少 57.1 个百分点、MCC 显著提升，同时降低了下游模型的预测不确定性。

## 研究问题与动机
- **患者查询的隐含上下文缺失**：患者提交的医疗查询语言清晰但关键的患者特定变量（症状、用药、过敏史、妊娠状态、饮食限制等）未披露，导致同一查询可对应多种合理答案，下游 LLM 不得不依赖未证实的假设作答。
- **现有方法无法解决此类歧义**：改进提示措辞（Rephrase-and-Respond）、增强外部知识检索、优化不确定性估计均只能处理"信息已给出但表达不清"或"模型知识不足"，无法恢复仅存在于患者自身的隐性变量。
- **患者上下文歧义是一种独立歧义类型**：作者将其从语言歧义（linguistic ambiguity）、知识歧义（knowledge ambiguity）和意图歧义（intent ambiguity）中分离出来，强调其核心特征是决策相关变量只能向用户询问，而非从参数或外部语料检索。
- **直接交互中下游模型性能不稳定**：在未澄清的查询上，不同下游 LLM 在相同任务上的输出差异显著，表明模型在信息缺失时需各自依赖不同先验，从而降低结果一致性。

## 核心贡献（创新点）
1. **形式化"患者上下文歧义"（patient-context ambiguity）概念**：将其明确定义为"查询语言清晰、通用医学知识可及，但恰当回答依赖未披露的患者特定变量"的独立歧义类型，区别于已有工作讨论的其他歧义。
2. **提出知识图谱引导的智能体中间层**：在用户界面与下游 LLM 之间插入 Orchestrator+Controller+KG 的三元架构，使用 UMLS 派生的 DxSxKG / FoodSafetyKG 构建假设并选择最具判别力的澄清变量，无需微调下游模型即可显著提升准确度。
3. **设计了受控的"信息缺失模拟"评估协议**：利用 Synthea 合成病历和人工构建的饮食基准，通过 Ambiguity Injection Module（AIM）对完整查询做受控遮蔽（约 49.5% 症状被隐藏），使缺失变量只能通过澄清流程获得，从而严格隔离"信息获取"与"最终生成"的贡献。
4. **引入输出不确定性（entropy）分析作为辅助评估**：对诊断和饮食安全查询进行 500 次重复采样，证明澄清后下游输出在临床类别层面的熵显著低于基线，体现更稳定的预测行为。
5. **验证跨模型一致性改进**：Agent 配置在五个下游模型（GPT-5.5、Claude Opus 4.8、Gemini 3.1 Pro、LLaMA 3.3 70B、Mistral Large）上均取得更高均值与更低标准差，表明其不强烈依赖特定模型选择。

## 方法详解
- **框架结构**：整体分为 Interface（用户交互）、Orchestrator（内层 LLM + 确定性控制器）和外部知识源（Neo4j 图数据库）。接口负责传递查询与答案；Orchestrator 使用 GPT-5.5 作为内层模型解释查询并表达问题；确定性控制器管理假设权重与信息增益计算。
- **假设构建**：将可见查询中的症状/食物表达映射到任务特定知识图谱（DxSxKG / FoodSafetyKG），通过实体解析（精确匹配→同义词→全文索引→内层 LLM 提议 UMLS 规范名）得到概念集合 P；候选假设按匹配概念数 $k_h$、覆盖率 $k_h/m$ 和连接症状数 $n_h$ 加权排序（$s(h)=2k_h + k_h/m - 0.01n_h$），取 Top-8 作为初始假设集 $\mathcal{H}_0$。
- **信息增益驱动的问题选择**：对 $\mathcal{H}_t$ 中每个未提问的二元变量 $v$，计算期望熵减：
  $$v_t^* = \arg\max_{v \in \mathcal{V}_t} \left\{ H(b_t) - \sum_{a \in \{0,1\}} P(a \mid v,b_t) H(b_t \mid a,v) \right\}$$
  其中 $P(a \mid v,b_t) = \sum_{h \in \mathcal{H}_t(v,a)} b_t(h)$，$\mathcal{H}_t(v,a)$ 为与回答 $a$ 兼容的假设子集。
- **权重更新（硬约束）**：收到回答 $a_t$ 后，剔除不兼容假设并重新归一化：
  $$b_{t+1}(h) = \frac{\mathbf{1}[h \in \mathcal{H}_t(v_t^*,a_t)] \cdot b_t(h)}{\sum_{h'} \mathbf{1}[h' \in \mathcal{H}_t(v_t^*,a_t)] \cdot b_t(h')}$$
  无兼容假设时记录"unresolved"状态，不强行生成答案。
- **停止条件**：诊断任务中，当前最高后验 > 0.95（唯一假设时为 ANSWER）；剩余假设覆盖 $\lceil|\mathcal{H}_0|/2\rceil$ 的共同 IS A 祖先为 PARTIAL；否则 ABSTAIN；最多 5 轮。饮食任务中，确认一个风险条件（有 SAFE FOR 例外则 OKAY，否则 NOT OKAY）或所有风险假设被排除即停止。
- **内层 LLM 职责边界**：负责将图定义的变量翻译为患者友好问句、格式化澄清证据记录，但不得修改控制器状态、停止决策或符号化提示。

## 实验与结果
- **诊断基准**：1,034 例合成病例（32 个诊断标签，平均每条 8.22 个症状，~50.5% 可见），通过 DxSxKG（UMLS 2025AA，129,815 诊断节点 / 340,842 症状节点）检索。
  - Exact Top-1 准确率：Agent 57.7%–71.1%，BASIC/RaR 仅 0.6%–11.0%，最大提升 ≥ **57.1 pp**（如 GPT-5.5 从 1.6% 提升至 62.1%）。
  - Exact Recall@5：Agent 90.6%–90.9%，BASIC/RaR 仅 2.0%–16.2%，最大提升 ≥ **77.7 pp**。
  - ICD 级别 Top-1：Agent 78.8%–80.6%，BASIC/RaR 27.2%–45.9%。
  - Agent 中止（ABSTAIN）35 例（3.4%），选择性结果与总体结果差异极小。
- **饮食安全基准**：487 条查询（301 OK / 186 NOT OK），通过 FoodSafetyKG（USDA FoodData Central + UMLS + 14 份临床指南）判定 OKAY/NOT OKAY，MCC 为主指标。
  - Agent 在 5 个模型中 4 个取得最高 MCC；GPT-5.5  MCC 从 0.757（Basic）升至 0.783，Claude Opus 4.8 从 0.607 升至 0.837。
  - 最关键的安全错误（False Negative）显著减少：Claude Opus 4.8 FN 从 42 降至 6；LLaMA 3.3 70B 误报率从 23.6% 降至 18.6%。
- **跨模型一致性**：Agent 配置在所有指标上同时获得更高的均值和更小的群体标准差（如 ICD Top-1 均值 79.5%，标准差 0.57 pp vs BASIC 35.4% / 6.89 pp）。
- **重复采样不确定性**：诊断任务 500 次重复后，Agent 类别熵均值 0.017 bits（BASIC 0.320、RaR 0.338）；饮食任务 Agent 在所有模型×配置组合下熵均为 0 bits（完全一致）。

## 相关工作脉络
1. **Rephrase-and-Respond（RaR, Deng et al., 2024, arXiv:2311.04205）**：仅对查询进行改写重组，不获取新信息；本文证明该策略在患者上下文缺失场景下无法超越直接提示。
2. **CLAMBER（Zhang et al., 2024）**：构建识别和澄清歧义的基准，但关注的是问答中的事实/实体歧义，而非患者特有的个人健康变量。
3. **MediQ（Li et al., 2024, NeurIPS）**：评估 LLM 问诊能力，发现单纯提示 LLM 主动提问并不能稳定提升临床推理性能；本文用结构化知识图谱替代 LLM 自由发问来解决此问题。
4. **CLEAR-KGQA（Wen et al., 2025, arXiv:2504.09665）**：基于知识图谱的澄清 QA，但聚焦于外部事实歧义（如指代消解），而非仅可通过用户询问获取的患者特定变量。
5. **CLAM（Kuhn et al., 2023, arXiv:2212.09748）**：通过 LLM 选择性地澄清模糊问题；属于纯提示驱动方法，同样受限于 LLM 无法自行获知患者未提供的变量这一根本约束。
6. **医疗 LLM 指令微调与 RAG（Liu et al., 2024; Amugongo et al., 2025）**：增强模型参数知识或检索外部文献；本文指出这些手段无法检索过敏、用药等仅存于患者自身的变量，因此需前置交互式信息获取。

## 局限性与未来方向
- 诊断基准基于 Synthea 合成数据，缺乏真实临床环境中共病复杂性、文档变异性和患者自然语言的多样性。
- 饮食安全基准仅覆盖 38 种患者健康上下文，实际部署需更多疾病、药物相互作用和饮食场景的验证。
- 澄清回答由模拟 Oracle（基于隐藏参考信息）提供，未测试真实用户可能出现的理解偏差、不确定回答、非标准术语或多重共病干扰等噪声场景。
- 诊断类别与 ICD 级别评估依赖预设映射表，而非独立临床编码员审核。
- 不确定性分析仅针对每任务 2 个随机样例的 500 次重复，无法代表全量分布。
- 当前框架仅能获取患者自我知晓和报告的稳定属性（诊断、用药、过敏、妊娠等），动态变量（活动量、睡眠、近期营养摄入）和纵向健康记录（EHR/个人时间线系统）暂未覆盖。
- 知识图谱本身存在覆盖与准确性限制：遗漏或错误的关系会妨碍正确假设的检索或限制可选问题范围。

## 研究启发与可借鉴点
1. **"上下文获取与最终生成解耦"的设计范式**：将 Orchestrator（信息获取）与下游 LLM（语言生成）分离，前者负责结构化假设维护，后者只处理已澄清输入。这一范式可迁移至法律、金融等同样需要补充用户特定信息的问答场景。
2. **基于知识图谱的信息增益提问策略**：用确定性的 Shannon 熵减替代 LLM 自由发问，既避免了"提示 LLM 提问不一定有效"的问题（MediQ 发现的），又使问题选择过程可审计、可复现；可借鉴用于构建可解释的多轮交互系统。
3. **Ambiguity Injection Module（AIM）的数据构造方法**：通过规则遮蔽、本体泛化和 LLM 人格化改写产生"已知答案但表面缺失信息"的成对数据，可用于训练/评测各类澄清交互模型。
4. **跨模型性能一致性度量（均值+标准差）**：将"模型鲁棒性"作为一级指标，发现澄清能显著降低因下游模型选择不同带来的输出方差，这一视角可推广至 Agent 系统的可靠性评估。
5. **输出熵分析作为辅助指标**：在准确率之外，用重复采样熵刻画模型输出的稳定性，区分"正确的一致性"和"错误的固执"，可作为可信医疗 AI 的通用评估手段。

## 关键术语表
- **患者上下文歧义（patient-context ambiguity）**：查询语言清晰且通用医学知识可及，但恰当事件取决于未披露的患者特定变量（如用药、过敏、妊娠状态）而引发的歧义类型。
- **知识图谱引导澄清（knowledge-graph-guided clarification）**：利用任务特定的知识图谱显式定义候选假设、判别变量和证据路径，替代 LLM 自由生成澄清问题。
- **期望信息增益（expected information gain）**：以 Shannon 熵减度量，用于在多个可用澄清变量中选择对假设空间歧义消除最大的那个。
- **硬约束权重更新（hard constraint weight update）**：对与所获回答不兼容的假设赋予零权重并重新归一化，区别于软贝叶斯更新。
- **Ambiguity Injection Module（AIM）**：离线生成器，通过规则遮蔽、本体泛化和 LLM 人格化改写将完整查询转化为"表面缺失信息但保留了隐藏答案"的测试样例。
- **DxSxKG / FoodSafetyKG**：分别为症状-诊断和饮食安全任务构建的任务特定知识图谱，前者基于 UMLS 2025AA，后者整合 USDA FoodData Central 与 14 份临床指南。
- **Selective / Overall 指标**：Selective 仅在成功获得答案的样本上计算，Overall 将所有评估样本（含中止）纳入分母，用于衡量覆盖率影响。
- **Rephrase-and-Respond（RaR）**：先将查询改写为更清晰的形式，再利用改写结果作答的比较基线，不提供额外信息获取。

## 可复现要素
- **数据集**：诊断基准基于 Synthea 合成病历（commit c807432，2025-08-24 生成），饮食基准由人工构建模板加规则遮蔽生成；论文声明测试集 SHA-256 哈希已公开，完整基准输入将在同行评审发布时公开。
- **代码**：框架实现基于 Python 和 openCHA；知识图谱构建、实验运行和指标复现代码将在版本化项目发布中提供，包含固定 Python 环境、冻结的逐行预测、SHA-256 清单和离线复现命令；商业 API 凭据和 UMLS 许可文件不随代码分发。
- **关键超参**：诊断任务最多 5 轮澄清、后验阈值 0.95、候选假设保留 Top-8、内层模型固定为 GPT-5.5；饮食任务无固定轮数上限但受图定义问题池约束、候选假设上限 50；权重初始化为均匀分布 $b_0(h)=1/|\mathcal{H}_0|$。
- **模型**：下游五个模型为 GPT-5.5（OpenAI）、Claude Opus 4.8（Anthropic）、Gemini 3.1 Pro（OpenRouter）、LLaMA 3.3 70B（OpenRouter）、Mistral Large（Mistral）；论文使用冻结输出，可通过离线脚本复算指标。
