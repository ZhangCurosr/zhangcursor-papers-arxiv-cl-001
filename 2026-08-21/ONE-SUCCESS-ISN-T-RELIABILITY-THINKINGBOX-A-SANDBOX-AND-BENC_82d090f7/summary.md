# 论文速读：ONE-SUCCESS-ISN'T-RELIABILITY-THINKINGBOX-A-SANDBOX-AND-BENC

## 一句话总结
本文提出 **THINKINGBOX** 沙盒与 **THINKINGBOX-BENCH** 基准，用于评估大模型智能体在有状态业务工作流中的端到端任务完成可靠性；核心发现是：尽管最强模型 GPT-5.4 的 pass@1 可达 65.36%，但其每任务 20 次全成功的 pasŝ20 仅为 25.25%，揭示了"偶发成功"与"可靠完成"之间存在巨大鸿沟。

## 研究问题与动机
- 现有智能体评测基准多聚焦于代码修复、Web 导航、API 调用等易于验证的任务形式，但企业实际工作（如修改订单、处理退款、更新保险理赔）既非代码也非单一工具调用，需多轮对话、状态转换、策略约束与副作用控制。
- 现有方法以"生成合理回复"或"有效工具调用"为代理信号，无法判定智能体是否真正完成了业务目标；即便工具调用成功，也可能选错实体、遗漏确认步骤或产生未经授权的旁路副作用。
- 现有评测（如 τ-bench、AppWorld、MCP-Bench）在可执行评估与用户交互方面各有侧重，但缺乏一个支持"多领域策略条件化工作流 + 隔离会话 + 终态 + 副作用 + 对话"三位一体检查的统一沙盒。
- 重复试验中的可靠性差距尚未被系统量化：多数模型可通过重试发现至少一次成功轨迹，但无法保证每次都能可靠复现。

## 核心贡献（创新点）
- 提出 **THINKINGBOX** 通用沙盒，支持工具/智能体/模拟用户的可重复多轮交互与端到端可执行验证，而非仅对工具调用本身打分。
- 构建 **THINKINGBOX-BENCH** 基准，包含 507 个跨五领域（零售、旅游、车险、新银行内部IT、咨询IT/HR）的有状态工作流，每条任务由任务特定的可执行终态检查而非单一最终答案来评判。
- 设计侧重点为中心的可组合评判函数 $V(x,\rho)=\prod_i c_i(s_T,e,\rho)$，允许不同合法轨迹对应相同正确世界状态，同时拒绝错误、缺失或额外的持久副作用。
- 在 12 个私有/开源模型上以每任务 20 次独立试验进行评测，首次系统化揭示"发现-可靠"鸿沟（pass@20 vs. pasŝ20），并提供细粒度的轨迹级失败分类分析。
- 将 ThinkingBox 从评测扩展为可训练环境：同一任务世界可用于推理、leaderboard 评测、失败分析与强化学习训练奖励构建。

## 方法详解
- **任务世界建模**：每个任务形式化为元组 $x=(b_0,g,T,\mathcal{U},\mathcal{C})$，其中 $b_0$ 为初始后端状态、$g$ 为用户目标、$T$ 为领域工具集、$\mathcal{U}$ 为模拟用户策略、$\mathcal{C}$ 为隐藏的可执行检查集合。
- **POMDP 诱导**：每个任务诱导一个有限时间域部分可观察马尔可夫决策过程 $\mathcal{M}_x$，智能体不直接观测后端状态，仅在观测历史 $h_t=(o_0,a_0,\ldots,o_t)$ 上做出工具调用 $(\tau_t,p_t)$ 或终端标记 `<DONE>`。
- **隔离与会话重置**：每次尝试均从相同的 $b_0$ 重置任务世界，创建隔离 MCP 工具会话，确保两次尝试之间不共享数据库行、缓存状态或副作用；使用基于哈希的确定性终态比较，避免轨迹级别的等价问题。
- **侧重点为中心的可组合评判**：终止后提取侧效应 $e=\Delta_x(s_0,s_T,\rho)$，评判公式 $V(x,\rho)=\prod_{i=1}^{m}c_i(s_T,e,\rho)$ 要求所有检查 $c_i\in\{0,1\}$ 全部通过；30 个额外任务在终态检查基础上增加了最终的响应 rubric（内容属性检查）。
- **模拟用户策略**：固定使用 GPT-5.4-mini 作为模拟用户，采用严格"复制型实体"、"缺失信息仅回答'I don't know'"、"相关性+简洁性"和"角色边界"四条约束，使其成为封闭世界且被动的响应者，确保失败的归因在于智能体而非用户行为。
- **统一 Loop 支持评测与训练**：判据 $V$ 同时输出 pass@k 指标和可训练奖励向量 $r_i(\rho)=c_i(b_T,e,\rho)$，使同一沙盒可切换智能体策略进行离线训练与在线评测。

## 实验与结果
- **评测设置**：THINKINGBOX-BENCH 共 507 个任务（零售 98、旅游 104、车险 100、新银行 104、咨询 IT/HR 101），每个任务 20 次独立试验，共 10,140 次/模型；评测 12 个模型（GPT-5.4/5.2、Claude Sonnet/Opus 4.6、o3-pro、Grok-4.3、DeepSeek-V4-Pro、GLM-5.1、Kimi-K2.6、Mistral-Large-3、Qwen3.5-9B/3.6-27B 等）。
- **最强模型**：GPT-5.4 以 **65.36%** pass@1 领跑整体；各模型按领域差异显著，零售平均约 52%，保险最低约 23%。
- **发现-可靠鸿沟**：GPT-5.4 的 pass@20 = 91.12%（至少一次成功），但 pasŝ20 = **25.25%**（20 次全成功），差距达 66 个百分点；其他模型趋势一致（Claude Sonnet 4.6：pass@20 88.56% vs. pasŝ20 20.12%）。
- **领域难度**：零售最容易（GPT-5.4 76.33%），车险最难（GPT-5.4 62.65%，Claude Opus 4.6 仅 14.65%），新银行与咨询 IT/HR 介于中间；不存在"跨领域鲁棒"的模型（除 GPT-5.4 和 Claude Sonnet 4.6 外，多数模型在特定领域出现断崖式下降）。
- **开源模型**：DeepSeek-V4-Pro 开源最强（43.26%），但 Mistral-Large-3（675B/41B）平均仅 4.66%，证明参数量并非唯一决定因素。
- **失败分析**：主导失败模式为工具使用错误（平均 77.5%），即工具报错/前置条件失败后智能体未能恢复；"无状态变更动作"占 2.5%、"不完整用户解决"占 7.9%、"错误状态更新"占 12.1%。
- **弱评估消融**：80.88% 的失败尝试满足"干净终止+状态变更调用"，67.24% 还满足"终态工具响应无显式错误"，说明传统响应/工具级信号严重高估智能体真实完成度。

## 相关工作脉络
- **ToolSandbox**（Lu et al., 2025）：同样关注有状态工具与对话交互，但未覆盖多领域、多策略的业务场景，也未以终态+副作用检查为核心。ThinkingBox 在此基础上扩展到五个领域并提供可组合的可执行判定。
- **τ-bench**（Yao et al., 2024）：在终端数据库状态上检查政策引导对话，引入 pass@k 与重复可靠性；ThinkingBox 继承重复可靠性框架，同时增加 MCP 兼容工具暴露、更细粒度的侧效应检查与更大规模任务集。
- **AppWorld**（Trivedi et al., 2024）：支持替代解法和旁路变化检测，但聚焦于 App API 与编码场景；ThinkingBox 专注于非代码类业务流程，覆盖更丰富的用户模拟与策略约束。
- **MCP-Atlas**（Bandi et al., 2026）与 **MCPMark**（Wu et al., 2026）：面向真实服务器上的工具发现和 CRUD 任务；ThinkingBox 与其相比更强调多轮用户交互、策略条件化与不可逆业务副作用的检查。
- **τ²-bench**（Barres et al., 2025）：用户与智能体均可在共享世界中行动；ThinkingBox 中用户为纯环境的一部分，不执行状态变更，从而保持评测变量的单一性。
- **BFCL / ToolBench / API-Bank**（Patil et al., 2025; Qin et al., 2024; Li et al., 2023）：以工具选择、参数生成、调用执行为核心评测对象；ThinkingBox 指出这些信号不足以代表端到端业务完成，需结合终态检查才能反映真实能力。

## 局限性与未来方向
- 评测结果依赖于固定用户模拟器（GPT-5.4-mini），该模拟器不会主动推动任务、不会中途改变目标、不会表现出不配合或记忆错误；与真实用户交互的鲁棒性未被测试。
- 507 个任务中 477 个仅检查终态和副作用，对话内容的质量不在可执行检查范围内；30 个补充 rubric 任务亦由固定 GPT-5.4-mini 评判，存在 judge 偏差的可能。
- 任务源自非公开的企业案例库的合成重建，不代表任何单一企业的真实分布；部分具有多种合法解的工作流因构造方式而被排除。
- 模型评测受限于 Azure API 部署协议与 vLLM 本地推理配置的一致性假设，不同推理后端的行为差异未被控制。
- 未来可扩展至可变用户模拟器（调整模型族、合作度、披露行为）、引入多智能体协同场景、以及将 ThinkingBox 沙盒用于离线/在线 RL 训练。

## 研究启发与可借鉴点
- **可复用的沙盒抽象**：将"用户-智能体-工具-侧效应提取-可执行判官"统一到一个可重置的 POMDP 循环中，便于后续将新领域任务快速接入并复用评测基础设施。
- **发现-可靠鸿沟的量化范式**：同时报告 pass@k 和 pasŝk 两个指标，可区分"偶发成功"与"可靠完成"，适用于任何需要重复稳定性的 Agent 评测场景。
- **侧效应为中心的可组合评判**：$V(x,\rho)=\prod_i c_i(s_T,e,\rho)$ 的 conjunctive grading 设计允许不同合法轨迹，同时检测旁路副作用，比单纯检查终态或工具调用序列更具业务实用性。
- **失败模式分类的可迁移性**：四类主导失败模式（工具使用错误/无状态变更/不完整解决/错误更新）可泛化到其他有状态 Agent 评测体系，作为失败归因的标准模板。
- **弱评估信号的辨析价值**：实验表明 67%+ 的失败示例在工具级/响应级信号下看似成功，这提示本团队在设计评测时应在基础信号之上增加终态与副作用验证，避免误报率高估。

## 关键术语表
- **THINKINGBOX**：一个支持工具/智能体/用户多轮交互的通用沙盒运行时，提供隔离 MCP 会话、完整执行轨迹记录与基于终态+侧效应的可执行判定。
- **THINKINGBOX-BENCH**：基于 THINKINGBOX 构建的 507 任务基准，涵盖零售、旅游、车险、新银行 IT 和咨询 IT/HR 五个业务领域，每条任务附带任务特定的可执行检查。
- **pass@k**：在 k 次独立试验中至少一次成功的概率估计，衡量智能体通过重试"发现"成功轨迹的能力。
- **pasŝk**：在 k 次独立试验中全部成功的概率估计，衡量智能体的端到端可靠性。
- **Side-effect-centered judging**：以终端后端状态和工具产生的副作用（而非对话表面形式）为主要评分依据的可组合判据。
- **模拟用户（Simulated User）**：固定在 ThinkingBox 中充当用户角色的 LLM 组件，仅基于任务上下文和可见对话历史被动响应，不掌握后端状态也不执行状态变更操作。
- **MCP（Model Context Protocol）**：一种标准化的工具描述与调用协议，ThinkingBox 通过 MCP-compatible 服务器暴露领域工具。
- **Executable verdict**：通过确定性数据库哈希比较实现的二元判定，判定任务是成功（所有检查通过）还是失败（存在错误、缺失或额外副作用）。

## 可复现要素
- **数据集**：THINKINGBOX-BENCH 507 个任务；论文未声明公开，但提供了代码仓库（https://github.com/microsoft/thinkingbox），数据集细节见论文附录 B。
- **代码**：代码已开源，见 https://github.com/microsoft/thinkingbox。
- **模型权重**：评测使用 Azure API 部署的私有模型（GPT-5.4、Claude Sonnet 4.6 等）及本地 vLLM 部署的开源模型（Qwen3.5-9B、Qwen3.6-27B）。
- **关键超参**：温度 1.0（agent）、0.3（用户模拟器）、0.0（judge）；max_completion_tokens 4096；每任务 N=20 次独立试验；最大用户跟进回合数 10 轮；MCP 会话超时 300s，模型请求超时 600s，最多重试 5 次。
