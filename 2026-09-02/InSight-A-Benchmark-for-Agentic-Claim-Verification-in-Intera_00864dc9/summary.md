# 论文速读：InSight-A-Benchmark-for-Agentic-Claim-Verification-in-Intera

## 一句话总结
本文提出 InSight，一个针对交互式可视化环境中的智能体主张验证基准测试，包含21,349条源自人工分析笔记的主张，要求模型通过主动交互（点击、悬停、滚动）获取证据来判断主张为True、False或NEI，并引入交互效率分数（IES）衡量模型的证据获取行为。

## 研究问题与动机
1. **现有VLM评估依赖静态图像**：当前图表理解基准多基于单张静态图片进行一次性问答，无法反映真实数据分析中"证据通过用户行为条件性揭示"的交互式本质。
2. **缺乏对交互过程的观测**：传统事实核查或静态视觉问答中，模型的推理过程是黑盒，仅能通过事后解释或CoT推断，无法直接审计模型如何寻找和综合视觉证据。
3. **静态基准无法惩罚"被动感知"**：模型可能通过参数知识或猜测在静态截图中给出正确答案，而非真正基于视觉证据进行推理，现有评估无法区分这两种能力。
4. **真实分析工作流的生态效度不足**：现有数据集多采用合成模板或众包描述的静态图片，未保留分析师实际使用的交互式多视图仪表板特性。

## 核心贡献（创新点）
1. **定义交互式视觉主张验证任务**：将事实核查的认知要求扩展到智能体多模态环境，要求模型在部分可观测的交互式环境中通过序列动作获取证据，与现有静态QA或单一图像验证形成本质区别。
2. **构建InSight基准数据集**：从297本人工撰写的高质量保证分析笔记本中提取21,349条主张（41.6% True / 45.0% False / 13.4% NEI），主张源自真实分析叙事而非合成构造，保留Vega-Lite交互式多视图环境的生态效度。
3. **提出交互效率分数（IES）指标**：通过计算有效动作比率（状态改变比例）与准确率相乘，量化模型是否在正确回答的同时进行了有意义的证据探索，弥补传统准确率无法区分"正确但无依据"与"正确且有依据"的缺陷。
4. **提供首个系统性的交互行为分析**：揭示不同规模模型的探索策略差异——GPT-5.5以最少动作（平均3.13次）达成最高准确率，而Gemini 3.5 Flash最活跃但部分预算内未完成探索；小模型（<1B参数）几乎不交互，直接降格为猜测。

## 方法详解
**数据集构建流水线（四阶段）**：
1. **Span提取**：采用Lundgard & Satyanarayan四语义层级模型，仅保留Level 2（统计洞察）和Level 3（视觉/感知洞察）的可验证文本段；通过三次独立LLM运行+trigram重叠投票确保稳定性。
2. **主张分解**：将复合陈述拆解为原子化、去上下文化的可独立验证命题，通过自验证步骤确认 entailment，语义标签通过三次传递多数投票确定。
3. **主张变异**：基于FEVER的对比构造范式生成FALSE和NEI主张：
   - **反义替换**（Antonym substitution）：使用词义反转方向/数量词（如 increased→decreased），生成FALSE；NLI矛盾分数需>0.9。
   - **词内参数替换**（In-lexicon argument substitution）：用同数据集内的替代值替换属性/类别/数值，生成FALSE。
   - **词外参数替换**（Out-of-lexicon argument substitution）：用数据集中不存在的值或属性替换，生成NEI；NLI蕴含与矛盾分数均<0.2。
4. **人类验证**：13位专家标注者对294条主张进行盲评，原始一致率81.3%，Dawid-Skene贝叶斯模型后验平均准确率66.2%（95% CI: [59.5%, 71.8%]），MAP估计77.6%。

**评估设置**：
- 渲染环境：基于Chromium无头浏览器（Playwright）运行Vega-Lite可视化，固定视口小于页面尺寸，强制模型滚动探索；模型仅接收RGB截图，无法访问DOM或HTML源码。
- 动作空间A：scroll(dx,dy)、page_up/down(n)、arrow_keys、drag、click、shift_click、hover(x,y)、answer(label)，label∈{True, False, NEI}。
- 交互协议：每轮接收当前截图s_t和主张c，输出单一动作a_t；总预算T_max=10（另做T_max∈{1, 25}消融）。

**IES指标设计**：
- 有效动作：产生可观测状态变化（s_{t+1}≠s_t）的动作，E_i=Σ1[s_{t+1}≠s_t]。
- IES_i = A_i × (E_i/T_i)，其中A_i为0/1准确率，E_i/T_i为状态改变比率（SCR）。
- 首轮直接回答（T_i=0）的得分定义为0，刻意惩罚无交互的"猜测性正确"。
- 滚动几乎总是计入有效动作，因为视口外视图必须通过滚动发现。

## 实验与结果
**评测设置**：分层采样500条主张（167 True / 167 False / 166 NEI），评估14个模型配置，涵盖Gemini、GPT、Gemma、Qwen四家族，T_max=10。

**主要结果**：
- **最高准确率**：GPT-5.5达57.2%（T_max=10），Gemma 4 31B为47.2%，Qwen 3.5 27B为45.0%；随机基线为33.3%。
- **尺度效应**：Qwen从35B到0.8B准确率单调下降（44.8%→34.0%），Gemma从31B到E2B（47.2%→31.2%）；亚十亿参数模型仅略高于随机，表明存在能力门槛。
- **交互必要性**：Gemini 3.5 Flash在T_max=1时无交互准确率为44.2%，T_max=10时为41.6%，T_max=25时提升至50.0%（非单调），说明10步预算不足以完成多视图探索。
- **IES排名**：GPT-5.5以26.98%领先，Gemini 3.5 Flash为24.93%，Gemma 4 31B为20.57%；Qwen 3.5 0.8B为0.00%（零交互）。
- **标签特异性差异**：大多数模型在NEI上IES最高，GPT-5.5相对均衡；False主张验证对弱模型尤其困难，印证"证伪比验证更难"的文献结论。
- **行为签名**：Gemini 3.5 Flash使用最丰富的动作词汇（scroll 2.51/样本、hover 1.42、click 1.15）；GPT-5.5侧重hover（1.07）和scroll（1.02）但更经济；小模型普遍缺少hover动作，错过tooltip条件性证据。

**失败模式**：过早承诺（小模型1-2步后直接回答）、无焦点探索（大模型大量低效动作）、动作类型僵化（中档模型只用scroll/click，不用hover/drag）。

## 相关工作脉络
1. **静态图表理解基准**：FigureQA、DVQA依赖合成图表；PlotQA、ChartQA转向真实数据但仍为静态单图QA；InSight的核心差异在于保留交互式多视图环境并将推理重构为序列决策过程。
2. **图表主张验证**：ChartCheck引入主张验证范式但仍在静态输入上运作，且主张为基准特制；InSight的主张源自真实分析叙事，通过受控变异生成平衡的TRUE/FALSE/NEI集合。
3. **文本事实核查**：FEVER、SciFact、FEVEROUS引入NEI标签和证据检索框架；InSight将这一认识论框架扩展到部分可观测的多模态环境，证据需主动揭示而非直接可用。
4. **多模态事实核查**：NewsCLIPpings、AVerImaTeC评估图文一致性但为封闭世界静态输入；InSight的核心拓展在于引入交互作为证据获取机制，支持跨视图的证据综合。
5. **智能体基准**：OSWorld、MiniWoB++、VisualWebArena、Browser-Gym评估任务完成度（是否到达目标状态）；InSight聚焦单一紧密定义任务（视觉主张验证），将交互轨迹作为推理代理显式审计，而非仅看最终结果。

## 局限性与未来方向
1. **动作空间抽象**：采用固定高层动作集，可能无法捕捉人类使用的复杂手势交互或特定界面的语义快捷键；不同动作空间设计可能产生不同的交互策略和性能画像。
2. **交互轨迹的非完备性**：轨迹仅作为推理代理，模型可能做出正确动作为错误理由，或内部推理合理但行为失败；轨迹应视为补充而非穷尽的证据源。
3. **IES指标的局限**：任何状态改变动作均计分，无法完全排除"交互但忽视所见"的正确但未扎根预测；更细粒度的扎根评估需主张级证据标注。
4. **未来方向**：显式训练证据搜寻行为（而非一次性视觉推理）、研究多轮视觉探索中的假设形成与更新机制、扩展至多模态论证的系统性研究。

## 研究启发与可借鉴点
1. **IES指标的可迁移设计**：将"有效动作比率"作为附加信号融入现有智能体评测，可甄别"正确但无依据"的预测，适用于任何需要证据获取的交互式任务（如GUI导航、网页信息检索）。
2. **主张变异的受控生成流水线**：通过NLI分数阈值（矛盾>0.9/蕴含<0.2）和XML标记约束的变异策略，可推广至其他领域的事实核查基准构建，确保真假/NEI主张的结构相似性与语义对立性。
3. **部分可观测性的显式建模**：InSight强制"初始截图不可判定任何主张"的设计原则，可有效防止参数知识污染，值得在视频理解、机器人操作等同样依赖探索的任务中借鉴。
4. **交互预算消融实验**：T_max∈{1, 10, 25}的非单调行为揭示（Gemini在10步最差、25步最佳），提醒研究者评估智能体时应测试多预算点而非单一配置，避免误判模型能力。
5. **与团队方向的结合机会**：若团队关注可视化解释生成或仪表板导航，可将InSight的Vega-Lite渲染环境作为测试平台，或在训练数据中引入"交互轨迹监督"信号以提升证据扎根能力。

## 关键术语表
**Interactive Visual Claim Verification**：在交互式可视化环境中，通过主动执行动作序列获取视觉证据，判断自然语言主张为True、False或NEI的任务。
**Interaction Efficiency Score (IES)**：准确率与有效动作比率的乘积指标，衡量模型在正确回答的同时进行有意义环境交互的程度。
**Effective Action**：产生可观测环境状态变化（即新截图不同于当前截图）的动作，用于区分探索性交互与无效操作。
**Not Enough Information (NEI)**：主张验证的第三种标签，表示可视化环境不足以支持或反驳主张，源于证据缺失而非矛盾。
**Semantic Level 2/3**：Lundgard & Satyanarayan四层级语义模型中的两级，Level 2为统计/数值洞察，Level 3为视觉/感知洞察，均为可被可视化验证的层级。
**Contrastive Construction**：基于FEVER范式的命题变异策略，通过反义替换、词内/词外参数替换系统生成FALSE和NEI主张。
**Partially Observable Environment**：环境设计为固定视口小于页面尺寸，证据隐藏在tooltip、多视图或交互后状态中，初始截图无法暴露全部信息。
**Action Trace**：模型在交互过程中生成的动作序列（如click、hover、scroll），作为模型注意力焦点和推理策略的可审计代理。

## 可复现要素
- **数据集**：InSight公开于https://github.com/maevehutch/insight，包含21,349条主张和297个交互式Vega-Lite笔记本。
- **代码**：论文声明开源，构建流水线细节见Appendix A。
- **评估环境**：Chromium无头浏览器+Playwright，固定视口渲染Vega-Lite可视化。
- **关键超参**：交互预算T_max=10（默认），NLI矛盾阈值>0.9，蕴含/矛盾阈值<0.2，span提取三次独立LLM运行。
- **模型配置**：闭源模型使用官方API，开源模型使用标准权重；所有模型仅接收RGB截图，无DOM/HTML/accessibility tree访问权限。
