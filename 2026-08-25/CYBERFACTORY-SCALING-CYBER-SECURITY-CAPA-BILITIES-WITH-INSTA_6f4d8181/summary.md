# 论文速读：CYBERFACTORY-SCALING-CYBER-SECURITY-CAPA-BILITIES-WITH-INSTA

## 一句话总结
CyberFactory 是一个开源的统一框架，将现实世界中的真实 CVE 漏洞转化为可执行的验证任务实例，并通过可复用的漏洞分析技能引导生成交互式训练轨迹，最终训练出 OpenAegis 模型，在 CyberGym 基准上实现 52.4% Pass@1，较基座 Qwen 3.5 提升 22.8 个百分点。

## 研究问题与动机
- **现有开源方案不具可复现性**：前沿开源模型（如 GLM-5、DeepSeek）展示了强大网络安全能力，但未提供可复现的训练方案；闭源模型（如 Mythos）能力更强但不可复现。
- **任务分散缺乏统一框架**：现有开源工作多聚焦孤立任务（如 CTF、单一漏洞修复），缺乏覆盖 PoC 生成、漏洞补丁、CyberQA 的统一多任务训练管线。
- **缺乏可扩展的 agentic 数据**：现有数据多为简单提示生成，缺少模型与环境交互、根据执行反馈迭代修正的可扩展 agentic 轨迹。
- **缩放训练需要强领域先验**：仅靠模型自由探索难以高效生成高质量轨迹，需要注入强领域先验作为指导，否则浪费预算在试探性输入构造上。

## 核心贡献（创新点）
- **提出 CyberFactory 统一训练框架**：首次将真实世界 CVE 漏洞转化为可执行、可验证的任务实例，并连接数据构建、轨迹合成与模型训练的全流程，提供可复现的开源方案。
- **设计可复用的漏洞分析技能（Vulnerability-Analysis Skill）**：编码任务无关的分析流程（源码检查、领域先验引导探索、基于证据的验证），用于指导教师模型生成高质量 agentic 轨迹，而非直接提供答案。
- **实现技能内部化（Skill Internalization）**：通过监督微调将技能引导的流程内化到模型参数中，OpenAegis 推理时无需提供该技能，但仍展现出一致的探索-验证行为模式。
- **提出长上下文结构化压缩方法**：针对 CyberGym 长轨迹场景，在上下文使用率达 90% 时触发压缩，保留已验证证据、失败尝试、待办操作等关键信息，上下文耗尽率从 18.7% 降至 7.4%。

## 方法详解
- **实例构建管线**：
  - **漏洞定位**：从 ARVO、OSS-Fuzz、from-the-wild CVE 三类来源获取漏洞，其中 from-the-wild CVE 难度最高，需通过影响软件版本范围定位修复提交，并进行实例验证（过滤模型已能解决的简单实例）。
  - **描述生成**：对低质量 commit message 使用 LLM 分类后生成漏洞描述，保留高质量 commit message 不变。
  - **验证标准**：采用差分预言机（Differential Oracle），要求 PoC 在修补前版本触发崩溃（CRASH），在修补后版本不触发。
- **问答数据构建**：
  - 采用"答案优先"策略，答案来源于可信源（执行结果、结构事实、权威报告文本），LLM 负责生成问题。
  - 自动检查确保答案可追溯、问题唯一、答案未泄露。
- **技能引导的轨迹合成**：
  - 技能编码独立于具体任务的通用工作流程：检查目标环境与构建约束 → 使用领域先验引导探索候选输入 → 验证证据 → 根据反馈迭代修正。
  - 轨迹满足任务级验证标准后保留用于训练。
  - 采用长上下文压缩：当 token 使用量达 90% 时，将累积轨迹压缩为延续状态，保留验证证据、失败尝试、开放假设、已生成产物、构建状态和待处理操作。
- **模型训练**：
  - 以 Qwen 3.5-397B-A17B 为初始化 checkpoint，进行 3 轮全参数监督微调。
  - 序列最大长度 131,072 tokens，全局 batch size 32，学习率峰值 2×10⁻⁵，cosine schedule，BF16 精度，使用 256 张 GPU。

## 实验与结果
- **评测基准**：CyberGym（Wang et al., 2026b），要求根据自然语言描述和代码库合成 PoC，每个任务给予 1 小时预算。
- **评估指标**：Pass@1（一次尝试即满足差分预言机的任务比例）。
- **主要结果**：
  | 模型 | 参数量 | Pass@1 (%) |
  |------|--------|------------|
  | Qwen 3.5 | 397B-A17B | 29.6 |
  | GLM 5.2 | 744B-A40B | 43.3 |
  | Kimi K2.7 | 1T-A32B | 51.7 |
  | **OpenAegis (ours)** | 397B-A17B | **52.4** |
- **关键发现**：
  - OpenAegis 较基座 Qwen 3.5 提升 **+22.8 个百分点**。
  - 超越参数规模更大的 GLM 5.2（+9.1 pts）和 Kimi K2.7（+0.7 pts）。
  - **技能对教师模型的增益**：GLM 5.2 使用技能后，每次尝试时间从 60 分钟降至 15 分钟，但允许 5 次重试，Pass@1 从 43.3% 提升至 46.5%。
  - **上下文压缩效果**：在 90% 阈值下触发压缩，整体 Pass@1 达 54.8%，长 horizon 任务提升 8.1%，上下文耗尽率降至 7.4%。

## 相关工作脉络
- **CyberGym (Wang et al., 2026b)**：本文主要评测基准，要求智能体仅凭漏洞描述和代码库复现 1,507 个真实漏洞。本文在其框架上进行训练与评测。
- **ARVO (Mei et al., 2026)**：提供已重建的可复现漏洞数据集，本文利用其作为低难度实例来源。
- **CVEfixes (Bhandari et al., 2021)**：从开源仓库自动收集漏洞与修复数据，本文借鉴其漏洞-修复配对构建思路。
- **SWE-bench / SWE-agent (Jimenez et al., 2024; Yang et al., 2024)**：软件工程中智能体交互模式的先驱工作，本文借鉴其 agentic 交互范式并应用于网络安全领域。
- **CyberSecEval 2 (Bhatt et al., 2024)、CyberPal (Levi et al., 2024)**：网络安全评测与 instruction-tuning 相关前作，本文更强调可执行任务与真实漏洞场景。
- **Vulrepair (Fu et al., 2022)**：基于 T5 的漏洞修复模型，本文将其思路扩展至多任务统一框架并引入 agentic 交互。

## 局限性与未来方向
- **评测覆盖范围有限**：当前评估受限于可用 CVE 工件和基准覆盖率，PoC 生成表现突出，但补丁生成和 CyberQA 的严格评测尚未充分展开。
- **语言与项目覆盖不足**：主要集中于英文开源项目，对其他语言和闭源软件覆盖有限。
- **固定时间预算限制**：1 小时预算虽保证可复现性，但对复杂漏洞可能不足，部分目标仍需人工辅助构造输入。
- **未来方向**：扩大漏洞类型、项目和语言覆盖；完善补丁生成与 CyberQA 的严格评测；开发可根据任务自适应选择分析策略的智能体。

## 研究启发与可借鉴点
- **可复用技能引导数据合成**：将领域专家流程编码为"技能"指导教师模型生成高质量轨迹，再通过学习实现技能内部化，避免推理时依赖外部指导——这一范式可迁移至其他需要领域先验的 agent 训练任务。
- **差分预言机作为验证信号**：利用修补前后行为的差异作为可程序化验证条件，实现无人工标注的真值验证，适用于漏洞检测、代码修复等场景。
- **长上下文结构化压缩策略**：在 90% 阈值触发压缩，保留关键状态信息而非简单截断，对需要长时间交互的 agent 任务（如代码生成、安全审计）具有重要参考价值。
- **从真实漏洞构建训练数据**：将现实 CVE 工件转化为可执行实例，比合成数据或竞赛题目更具真实性和挑战性，可用于其他领域的数据构建。
- **行为轨迹分析揭示学习机制**：通过对比教师模型（显式技能）与学生模型（SFT 后）的工具调用分布、验证行为等，验证技能内化效果——这一分析方法可复用于评估其他技能训练方案。

## 关键术语表
- **CyberFactory**：本文提出的统一开源框架，连接数据构建、轨迹合成与模型训练，用于扩展网络安全的开放权重模型能力。
- **OpenAegis**：基于 CyberFactory 训练的多任务网络安全模型，在 CyberGym 上达到 52.4% Pass@1。
- **Pass@1**：在一次尝试中成功解决任务的比例，是本文的主要评测指标。
- **差分预言机（Differential Oracle）**：验证函数，要求候选输入在修补前版本触发崩溃且在修补后版本不触发，确保 PoC 的真实性。
- **Vulnerability-Analysis Skill**：可复用的漏洞分析技能，编码源码检查、领域先验引导探索和基于证据验证的通用流程，用于指导轨迹合成。
- **From-the-wild CVEs**：来自真实世界的 CVE 记录，提供难度最高的实例来源，需通过版本范围定位修复提交。
- **Agentic Trajectory**：模型与工具环境交互、根据执行反馈迭代修正的完整轨迹序列，作为监督微调的训练数据。
- **Context Compaction**：在上下文使用率达阈值时将长轨迹压缩为延续状态的策略，保留关键信息同时释放 token 预算。
