# 论文速读：Rent-a-RAG: Embedding-Space Watermarks for Auditing Third-Party RAG

## 一句话总结
本文提出 DirBucket，一种提供方侧的语义水印与黑盒审计框架，通过将文档经义保留改写并使其嵌入沿提供方密钥方向产生微小偏置，实现了在多源混合、黑盒访问条件下对第三方 RAG 算子未授权重用文档的高精度检测，且不影响检索与生成质量。

## 研究问题与动机
- **第三方 RAG 市场缺乏审计机制**：数据提供方将语料授权给 RAG 算子后，无法观测算子是否缓存、复用其文档，也无法确认答案是否真正来自已购内容。
- **现有水印方法不匹配该场景**：主流 LLM 水印嵌入在生成阶段（由生成方控制解码策略），而提供方无法控制算子的模型、提示与解码；且算子会事后改写答案。
- **多源混合使归因极难**：单次答案可能混合多个提供方的文档，算子是非配合的，审计方仅能通过查询-答案黑盒接口进行推断。
- **现有非水印方案结构性不足**：Lexical/Similarity 启发式在跨提供商重叠事实场景下误报率高；Canary/Honeypot 依赖专门探针文档，在自然工作负载下未必被检索到。

## 核心贡献（创新点）
1. **提出了针对第三方 RAG 市场的威胁模型与审计框架**，明确审计接口（仅查询/答案）、多提供方针对混合归因需求及 FDR 控制目标，与 WARD 的语料级测试定位不同。
2. **提出 DirBucket：基于嵌入空间方向偏置的语义水印**，与 SemStamp 等生成侧水印的本质区别在于水印嵌入在源文档端（提供方离线执行），而非生成时嵌入。
3. **提出对齐感知黑盒审计协议（competitive alignment + anchored scoring + BH/FDR）**，通过"用参考窗口桶索引方向"而非"用答案窗口自身桶索引"的设计，显著提升了对改写漂移的鲁棒性。
4. **在合成与真实领域双基准上验证了端到端检测能力**，是目前唯一在同等任务条件下同时实现高目标检测率与零非目标激活的方法。

## 方法详解
- **桶化与密钥方向（4.1）**：每个提供方 $P_i$ 持有审计密钥 $k_i$，对每个桶码 $b \in \{0,1\}^h$ 通过 keyed PRF $\Phi_{k_i}(b)$ 映射出一个单位方向 $v_{i,b} \in \mathbb{S}^{d-1}$；方向得分定义为 $s(u; v) = \langle u, v \rangle$，零假设下均值接近 0、方差约 $1/d$。
- **基于爬山改写的离线水印嵌入（4.2）**：对源文档逐句处理，每轮生成 $K$ 个候选改写，保留语义相似度 $\ge \tau_{\text{sem}}$ 的候选，从中选取沿当前桶对应方向得分增益 $\ge \delta_{\min}$ 的最大值接受；重复 $\rho$ 轮累积方向偏置（GPT-4o-mini 作改写器，本地 Llama-3.1-8B-Instruct 可达 98% 效果）。
- **对齐-计分-池化审计流程（3.3 + 4.3）**：
  - **窗口化**：将答案按 $(W=28, s=14)$ 切窗，保留在句边界内。
  - **竞争性对齐**：每答案窗与各提供方的参考窗口做余弦匹配，保留最大相似度 $\ge \tau_{\text{sim}}$ 且领先第二名 $\ge \tau_{\text{margin}}$ 的分配，否则丢弃。
  - **锚定方向得分**：对分配到 $P_i$ 的答案窗 $a_{j,\ell}$，以匹配参考窗口 $w^\star_{j,\ell,i}$ 的桶 $b_{j,\ell}=B(E(w^\star))$ 作为方向索引，得分 $s_{j,\ell}^{\text{db}}=\langle E(a_{j,\ell}), v_{i,b_{j,\ell}}\rangle$；使用参考桶而非答案窗自身桶，避免改写漂移导致桶跳变。
  - **池化统计量与 BH/FDR 检验**：$Z_i^{\text{db}} = \frac{\sum_{(j,\ell)\in T_i} s_{j,\ell}^{\text{db}}}{\sqrt{|T_i|/d}}$，转为一侧 p 值后与最小支持门 $T_{\min}=25$ 和 BH 校正（$\alpha=0.05$）联合判定。

## 实验与结果
- **基准**：主基准基于 FARAD（RepLiQA 虚构语料，6 个合成提供方，top-k=5，每 bundle 至少 3 个不同提供方，GPT-4o-mini 生成）。额外基准为真实领域（PubMed 临床摘要、CTI 分析师报告、Legal 案例摘要，各 2 个提供方）。
- **最佳结果**：DirBucket 在主基准 30 个审计中实现 30/30 BH 显著检测，median target pooled Z = 8.42（初始 10 答案即越过 Z=4），23 答案内完成所有目标检测，max non-target pooled Z 保持为 0。
- **对比基线**：KGW-adapted（mean target Z=0.01，oracle 下 Z=13.53 但 max NT Z=5.95，特异性失败）；SemStamp-adapted（oracle 下 Z=1.39，结构性失效）；非水印启发式在 5% FPR 下 TPR 仅 0.13/0.01/0.72。
- **对抗鲁棒性**：中性改写、聚合改写（Z=6.98）、50% 压缩（Z=6.81）均保持 30/30 检测；仅 25% 压缩出现 24/30 检测，但该条件完整性降至 4.00/5、71% 用户偏好原始答案，存在不可避免的"逃逸-质量"权衡。
- **规模扩展**：$m \in \{6,12,20\}$ median Z 稳定在 8.23–8.45，BH 检测 30/30，max NT Z=0。
- **真实领域泛化**：临床 Z=15.64、CTI Z=10.62、法律 Z=5.75，均 30/30 检测，零非目标激活。
- **效用保留**：hit@5 从 0.973→0.962，MRR@5 从 0.839→0.819；GPT-4o 盲评意义保留 4.86/5、自然度 4.96/5；人类评测自然度 4.28 vs 4.34（无显著差异）。
- **部分覆盖**：30% 句子被水印时仍可检测 19/30，FPR 始终为 0。

## 相关工作脉络
- **KGW (Kirchenbauer et al., 2023)**：token 级生成时水印，依赖绿/红 token 结构，在 LLM 改写后 token 结构消失；本文水印在源文档嵌入空间，抵抗 paraphrase。
- **SemStamp (Hou et al., 2024)**：语义水印，但目标为生成文本的后续改写，假设水印嵌入在 LLM 输出中；本文水印嵌入在源文档，由 LLM 重新生成时信号不继承。
- **WARD (Jovanovic et al., 2025)**：黑盒 RAG 语料存在性推断，关注整个语料集是否被使用；本文聚焦文档级复用与多提供方针对归因。
- **RAG-WM (Lv et al., 2025)**：在知识库中插入特殊水印文本以检测整个 RAG 系统被复制；目标与应用场景不同。
- **S-RAG (Zeng et al., 2025)**：面向个人数据成员身份的黑盒审计，非提供方水印/混合归因场景。
- **Canary/Honeypot (Liu et al., 2025; Li et al., 2025)** 与 **Adversarial Prompting (Qi et al., 2025; Peng et al., 2024)**：前者依赖专门探针在自然负载下未必被命中，后者易受提示变化和模型防御影响。

## 局限性与未来方向
- **不可改写文档不适用**：合同、法规条文、安全关键指令等措辞敏感内容无法应用；部分覆盖会稀释证据积累速度但不破坏 FPR 保证。
- **不支持多模态与代码**：当前仅针对可编辑文本语料，表格、图像、音视频、源代码等未覆盖。
- **信任假设转移**：虽无需信任算子自报，但仍需可信审计方持有密钥并诚实执行；未来可通过仅披露编码视图（参考窗嵌入+桶标签+方向）或TEE/安全聚合降低信任负担。
- **审计员独立性与争议解决机制未涉及**：未讨论审计结果如何转化为合同处罚、去中心化审计协议等治理问题。

## 研究启发与可借鉴点
1. **"锚定参考桶方向"设计可直接迁移**：对抗改写漂移的参考锚定策略（用匹配源的桶而非答案自身的桶）是一种通用技巧，可推广至其他黑盒溯源场景。
2. **成本-强度消融表对资源受限部署极具参考价值**：$(K=24, \rho=3)$ 以 50% 成本保留 90% 增益，$Z=10.69$；$ (K=6,\rho=1)$ 保留 49% 增益仍可达 $Z=5.85$；提供了实用的工程取舍依据。
3. **支持门 $T_{\min}$ 的跨基准稳定性分析可作为评估模板**：同一阈值在合成与真实领域均处于稳定平台期，为方法泛化性论证提供了可复用的评估范式。
4. **对抗后处理清洗的"质量-逃逸权衡"定量框架**：用 GPT-4o 盲评量化每条篡改策略的用户感知质量下降，为防御设计者提供了清晰的博弈分析视角。
5. **本地开源模型替代 API 改写**：Llama-3.1-8B-Instruct 达到 API 模型 98% 方向增益且语义保真度匹配，证明该方法可完全离线运行，降低隐私与成本顾虑。

## 关键术语表
- **Black-box Auditing**：审计方仅能通过提交查询和观察答案的方式对 RAG 系统进行检测，无法访问检索日志、提示或缓存状态。
- **Competitive Alignment**：对每个答案窗口在各提供方的参考集中找最佳匹配，仅当胜者在绝对相似度和领先第二名上均超过阈值时才予以分配，避免模糊归因。
- **Directional Evidence (方向证据)**：答案嵌入沿提供方密钥特定方向的余弦投影，作为水印存在性的统计信号。
- **Support Gate ($T_{\min}$)**：判定提供方可被审计的最小对齐窗口数门槛，低于该值不进行统计检验，是控制 FPR 的关键参数。
- **Anchor-by-Reference-Bucket**：检测时以匹配参考窗口的桶来索引方向，而非用答案窗口自身的桶，增强对改写漂移的鲁棒性。
- **Benjamini–Hochberg (BH) Correction**：在多提供方同时审计时控制误发现率（FDR）的统计校正方法，确保跨提供方比较的校准性。
- **Paraphrase Hill-Climbing**：逐轮生成语义等价改写候选，选择使方向得分增量超过阈值的最大增益候选，累积小而安全的嵌入偏置。
- **FARAD Benchmark**：基于 RepLiQA 虚构内容的基准，内含重叠事实的多文档集合，用于模拟真实多提供商 RAG 混合归因场景。

## 可复现要素
- **数据集**：FARAD（基于 RepLiQA 虚构语料，按稳定哈希划分为 6 个合成提供方）；真实领域基准包含 PubMed 临床摘要、CTI 分析师报告、Legal 案例摘要。**论文未声明公开**，但 RepLiQA/FARAD 相关源码可参考原论文引用。
- **代码/权重**：论文未声明开源；水印使用 all-mpnet-base-v2（d=768）编码器、GPT-4o-mini 改写；附录 B.7 测试了 MiniLM-L6-v2、GTR-T5-base 及 Qwen2.5-1.5B。
- **关键超参**：$\tau_{\text{sem}}=0.70$，$\delta_{\min}=5\times10^{-4}$，$K=24$，$\rho=6$（成本敏感场景推荐 $\rho=3$）；审计侧 $\tau_{\text{sim}}=0.82$，$\tau_{\text{margin}}=0.05$，$W=28$，$s=14$，$T_{\min}=25$，BH $\alpha=0.05$；桶化 SimHash $h=96$。
