# 论文速读：How-Far-Can-Synthetic-Data-Take-Thai-OCR

## 一句话总结
本研究通过可控文档重建流程，系统探究了合成数据中哪些因素（字体多样性、二维布局、真实手写字形等）能有效迁移到真实泰文OCR，并基于发现构建了零真实标签的Wayu-Paxa-OCR-Zero模型，该模型在多项基准上超越Typhoon OCR 7B，证明合成数据训练的竞争力。

## 研究问题与动机
1.  **低资源语言OCR标注稀缺**：泰文等语言的公开数据集有限，而手动校正成本高昂，PDF提取常出错（字符遗漏、重排、顺序混乱）。
2.  **合成数据的“真实感”因素混杂**：现有合成方法同时改变多种属性（源域、上下文、字体、布局等），难以厘清各因素对迁移的实际贡献。
3.  **训练粒度影响迁移策略**：页面级（全页预测）与裁片区级（两阶段检测识别）模型暴露的文档上下文不同，可能偏好不同的合成数据特性。
4.  **验证合成数据的极限**：在无法获取真实泰文文档标注的设定下，能否仅凭合成数据构建出具有竞争力的开放OCR模型。

## 核心贡献（创新点）
1.  **可控文档重建流程**：引入一个能独立控制源域（内/外域）、非文本上下文、字体分布、二维布局及手写字符来源的合成数据生成流水线。
2.  **解耦合成数据迁移因素**：通过控制变量实验，明确揭示了字体多样性、二维结构和真实手写字形是关键迁移因素，而非文本上下文影响不一致。
3.  **揭示训练粒度与源域匹配的反转效应**：发现内域（真实泰文页面）重建数据在页面级训练中表现优异（中位数CER 1.82%），但在裁片区级训练中反不如外域（英文）重建数据（15.59% vs 5.52%）。
4.  **基于纯合成数据的高效模型**：构建并训练了Wayu-Paxa-OCR-Zero（0.9B参数），在未使用任何真实泰文页面图像及对应OCR标签的情况下，其性能超越Typhoon OCR 7B模型，并在所有五个评估集上实现显著提升。

## 方法详解
1.  **内/外域重建**：
    *   **In-Domain Synthetic**：直接获取真实泰文页面的OCR标签，擦除原文本像素后，将标签渲染回原区域。保留真实泰文页面的布局、噪声和风格。
    *   **Out-of-Domain Synthetic**：从英文文档（DocLayNet, Crello, PubTabNet）获取文本，将其翻译为泰文（或保留英文标签），再按上述步骤渲染。源域与目标域（泰文）不匹配。
2.  **贴合约束渲染**：使用HarfBuzz塑造泰文文本，独立采样字体和字号，缩小字号直至文本能容纳于原始标注区域内。若溢出则丢弃该页面。
3.  **字体渲染**：根据从8,000页真实泰文PDF测量的字符加权字体分布进行采样。每种字体的同一字符重复出现时轮廓相同。
4.  **真实手写字符渲染**：从约6,000个实例的字形库中独立采样每个支持的泰文字符实例进行渲染，支持字符出现96.3%。不支持的字符回退到字体渲染。保持OCR标签、区域标注、墨迹高度和颜色不变。
5.  **训练设置**：主要使用Qwen3-VL-2B-Instruct。对比两种训练模式：**页面级**（单张完整页面图像，预测全页布局和文本）和**裁片区级**（先由布局检测器提取区域，再对每个裁片进行识别）。

## 实验与结果
1.  **数据集**：内部评估集包括Heldout（301页打印泰文）、Handwriting（200页手写泰文）、Easy Handwriting（200页易辨识手写）。公开基准包括ThaiOCRBench和SEA-DocBench。
2.  **基线模型**：Qwen3-VL-2B-Instruct（基础）、Typhoon OCR (7B)、Typhoon OCR 1.5 (2B)、Gemini 3.7 Flash。
3.  **关键发现（消融实验）**：
    *   移除非文本上下文对识别影响不一致。
    *   移除字体多样性导致手写体CER稳定上升（页面级提升6.70-9.48点，裁片区级提升11.36-13.37点）。
    *   移除二维布局进一步降低手写识别性能。
    *   **内域 vs 外域**：页面级训练下，内域重建将Heldout中位数CER从5.07%降至1.82%；裁片区级训练下，内域重建表现更差（15.59% vs 5.52%）。
4.  **最终模型（Wayu-Paxa-OCR-Zero）性能**：
    *   基于PaddleOCR-VL-1.6（0.9B）训练，使用45,723页合成数据（无真实泰文页面/标签）。
    *   **相对基线提升**：Heldout中位数CER从6.64%降至1.24%；Handwriting从74.87%降至20.55%；Easy Handwriting从73.74%降至14.18%。
    *   **超越更强基线**：在所有五个评估集上均优于Typhoon OCR 7B模型。在Handwriting上接近Typhoon OCR 1.5 (2B)（20.55% vs 19.36%）。在SEA-DocBench上优于Typhoon OCR 1.5。

## 相关工作脉络
1.  **Typhoon OCR系列**：定义了开放泰文OCR的当前前沿，使用了传统OCR、VLM重组和精选合成数据的混合训练。本文定位在于**隔离并量化合成数据本身的贡献**及具体文档属性的作用，而非混合使用真实标注。
2.  **低资源语言OCR合成工作**：如Kolavi等（2025）的Indic文档、Chung & Choi（2025）的满语、Al-Homoud等（2025）的阿拉伯语。本文的**创新点在于系统性解耦多个“真实感”因素**（字体、布局、字形、源域、训练粒度）并进行控制变量实验，而非仅报告单一合成方案的效果。
3.  **现代端到端文档理解模型**：如GLM-OCR、PaddleOCR-VL。本文探讨了与这些**两阶段（检测+识别）系统适配的裁片区级训练**，并与**端到端页面级模型**进行了对比，揭示了训练粒度如何改变最优合成数据策略。
4.  **文档重建/合成技术**：如Guan等（2025）的退化感知历史文档处理。本文的**重点不是文档修复或增强，而是通过重建来产生带精确标签的合成训练数据，并研究其用于OCR训练的迁移性**。

## 局限性与未来方向
1.  **手写体与真实监督仍有差距**：即使使用真实手写字形实例，合成数据训练的手写识别性能（中位数CER 37.91%）与真实手写数据监督（26.05%）相比仍有明显差距，主要源于真实手写风格的多样性。
2.  **严重错误处理不足**：合成数据训练在减少典型页面错误方面有效，但在真实监督下仍存在的“长尾”严重错误（体现为Mean CER远高于Median CER）改善有限。
3.  **训练粒度与源域匹配效应未明**：内域重建在页面级和裁片区级训练下的性能反转现象机制尚不明确，需要进一步研究。
4.  **合成数据规模与覆盖度**：当前使用约4.5万页合成数据，字体分布基于8,000页测量。未来可扩展更大规模的数据集，并覆盖更多样的文档布局、字体和手写风格，以进一步提升泛化能力。
5.  **评估基准**：主要在内部测试集和部分公开基准（ThaiOCRBench, SEA-DocBench）上验证，未来需在更广泛、更多样的泰文文档场景下测试。

## 研究启发与可借鉴点
1.  **控制变量实验设计**：对于合成数据研究，系统地解耦并独立控制“真实感”的各个维度（如本文的源域、上下文、字体、布局、字形）是明确有效因素、避免混淆结论的关键方法，可迁移至其他语言或任务。
2.  **字体分布采样**：基于真实文档测量字符级字体使用分布，并以此分布进行合成渲染，比均匀采样或单一字体更能提升模型对真实文档字体的适应能力。
3.  **训练粒度决定数据策略**：模型架构（端到端vs两阶段）和训练粒度（页面级vs区域级）会显著影响对合成数据特性的需求。在规划合成数据策略时，必须与目标模型的训练方式相匹配。
4.  **零真实标签训练范式**：证明了在缺乏目标语言真实文档标注的情况下，通过精心设计的合成数据流水线（翻译+重建+字体/字形渲染）可以训练出极具竞争力、甚至超越大型专有模型的开放OCR系统，为其他低资源语言提供可行路径。
5.  **手写字符库构建流程**：从少量手写样本中通过检测、对齐、过滤、VLM验证构建小型但高质量的手写字形库，并用于合成渲染，是一种有效补充手写数据稀缺的方法。

## 关键术语表
*   **In-Domain/Out-of-Domain Synthetic**：指合成数据的源文档是否与目标语言（泰文）同源。内域使用真实泰文页面重建，外域使用英文等页面翻译后重建。
*   **Page-level / Crop-level Training**：页面级训练以整页图像为输入预测全页文本和布局；裁片区级训练先检测文本区域（crop），再对每个区域进行独立识别，模拟两阶段OCR系统。
*   **Character Error Rate (CER)**：字符错误率，衡量识别结果与参考文本差异的指标，值越低越好。论文报告中位数（Median）和字符加权均值（Mean）。
*   **Projected CER**：为公平比较页面级和裁片区级系统而设计的评估算法，将预测投影到参考区域后再计算CER，消除输出契约差异带来的偏差。
*   **Handwriting Glyph Bank**：从真实手写图片中提取、验证并整理的泰文字符实例集合，用于合成渲染以引入真实的手写笔画变化。
*   **Fit-Constrained Rendering**：合成渲染时的约束条件，要求将塑造后的泰文标签缩放至能容纳于原始文本区域边界框内。
