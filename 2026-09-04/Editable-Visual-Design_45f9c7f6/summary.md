# 论文速读：Editable Visual Design

## 一句话总结
提出了 **Editable Visual Design**，一种由 Coding Agent 驱动的可编辑视觉设计新范式：将 VLM 作为"创意大脑"进行需求理解、任务规划与美学判断，同时利用图像生成模型作为按需调用的"视觉世界模拟器"合成独立视觉素材，最终通过"先想象、后行动"的闭环工作流生成兼具高品质美学与工程级可编辑性的 HTML/CSS 设计产物。

## 研究问题与动机
1. **纯代码生成缺乏全局美学直觉**：现有 Code LLM 擅长语法与 DOM/Flexbox，但缺乏二维空间感与视觉直觉（two-dimensional spatial sense / visual intuition），生成的设计往往是高度模板化的"大标题+卡片+圆角阴影"三件套，难以跨越"结构正确"到"视觉精致"的鸿沟。
2. **纯像素图像生成不可编辑**：扩散模型虽能压缩人类艺术先验、生成顶级构图/光照/纹理，但生成的光栅图像存在文字拼写错误（misspelled and distorted text），且元素深度纠缠（deeply entangled elements），无法分离为可编辑图层，无法用于文本精确修改、本地编辑与下游交付。
3. **现有方法两极分化**：左脑派（纯代码生成）缺美学、右脑派（纯图像生成）缺工程逻辑，二者各有偏废，亟需一种融合方案。
4. **设计交付物需要可维护性**：真实设计场景要求产物可调整、可交接，而纯位图输出无法满足工程层面的可维护需求。

## 核心贡献（创新点）
1. **提出"创意大脑 + 视觉模拟器"协作机制**：以 Codex（GPT-5.6 Sol）为创意大脑，GPT Image 2 为视觉世界模拟器，前者负责需求理解、设计规划、代码构建与结果评判，后者随时被调用将抽象构思转化为具体视觉效果——本质区别在于将图像生成从"最终交付物"降级为"过程性参考工具"。
2. **"先想象、后行动"的闭环创作流**：智能体首先生成"想象视觉"（imagined visual）建立构图、光照、色彩先验，再独立处理素材生成、原生代码编写与多轮渲染-反思修复——区别于传统"直接生成代码"或"端到端生成图片"的单步模式。
3. **独立素材生成策略避免层纠缠**：本地图形素材按需单独生成（text-free background / isolated subject），不使用图像切割而非直接从想象视觉中提取，确保交付物中无任何生成图像的像素污染——本质区别在于素材是独立渲染而非从位图中抠出。
4. **引入 Agent Design Replay 可追溯创意轨迹**：将智能体从需求拆解、视觉想象、素材提示词到代码演化与反思修复的完整决策链序列化记录，使设计过程透明可追溯——区别于黑盒端到端生成，为人机协作（Human-in-the-Loop）提供交互基础。
5. **输出结构化解耦的 DOM 产物**：最终产物为原生 HTML/CSS，文本、背景、插图图层完全解耦，用户可在 GUI 上独立选择、拖拽、缩放、编辑和导出——实现从"位图输出"到"结构化交付"的范式转变。

## 方法详解
系统由 **VLM（Codex/GPT-5.6 Sol，创意大脑）** 和 **图像生成模型（GPT Image 2，视觉模拟器）** 构成，工作流程含五个阶段：

### 2.1 需求理解与设计规划
智能体解析 brief，确定内容要素、交付物尺寸与视觉场域；调用图像模型生成 **"想象视觉"（imagined visual）**——非结构草图，而是成品效果图，为后续所有步骤提供强美学参照；同时这也是用户最低成本介入点（在代码尚未存在时即可调整方向）。

### 2.2 视觉模拟
VLM 视觉解析想象视觉，提取 **color tone（色彩基调）、compositional distribution（构图分布）、overall style characteristics（整体风格特征）**，作为后续代码构建与视觉设计的全局参考——不要求一对一复现，但提供合理好的设计反馈。

### 2.3 结构编码与生成
- **素材生成**：按需独立生成干净的本地图形素材（text-free background / isolated subject），采用两种方式：①支持时直接请求含 alpha 通道的素材；②否则置于纯色（绿幕）背景后由 matting 脚本分离——确保素材从非想象视觉中独立生成，交付物不含任何像素污染。
- **代码构建**：用原生 HTML/CSS 编写，声明固定像素尺寸页面（non-viewport-dependent，保证各处打开尺寸一致），为每个可能独立移动的 DOM 元素标注为独立图层，建立清晰的排版层次（typographic hierarchy）、grid 对齐与多层布局。

### 2.4 验证与视觉自愈（Verification and Visual Self-Healing）
双轨验证机制：
1. **确定性规则检查**：在无头浏览器环境加载代码，检测元素溢出（style overflow）、元素重叠（overlapping）、图文遮挡、外部资源加载失败、DOM 结构畸形等。
2. **多模态视觉反思**：将实际渲染截图喂给 VLM reviewer，对比原始设计意图，评估视觉平衡、对齐精度与文本可读性。
3. **迭代修复**：发现瑕疵后，智能体生成针对性局部补丁（targeted local patch）微调代码，经 1-2 轮 reflection-and-repair 后达到预期质量标准。

### 2.5 可编辑产物与 Agent Design Replay
- 最终产物由原生 DOM 节点组成，文本、素材、背景图层完全解耦，支持双击编辑文本、拖拽缩放素材、分层导出。
- 同时序列化智能体全部决策过程（需求拆解→视觉想象→素材提示词→代码演化→最终反思修复）为 **Agent Design Replay**，实现创意过程全透明。

## 实验与结果
- **对比实验**：图 3 将方法分别与"纯扩散图像生成"（GPT Image 2 直接输出）和"纯 LLM 代码布局"（Codex on GPT-5.6 Sol 直接编码）在同设计需求下对比。纯扩散方法文字失真、层深度纠缠；纯代码方法结构整洁但画面大片空白、布局混乱。本文方法兼顾色彩氛围与排版精度、图层解耦。
- **多场景展示**：覆盖事件海报（event posters）、信息图（infographics）、营销物料（marketing materials）、长文排版（long-text layout）四类场景。信息密集场景保持字体比例与网格对齐，视觉驱动场景智能组织多层空间。
- **Agent Design Replay 案例**：图 5 展示了两个真实案例——信息密集的野外指南（120 个可编辑图层，13 组，审查捕获并修复了真实布局缺陷）和视觉驱动的旅行海报（6 个图层，1 组，审查无改动通过），证明方法对不同信息密度自适应。
- **定性结论**：未报告定量指标（论文 4.2 节明确说明美学质量难以量化评估，采用案例展示而非分数），强调产出在视觉表现力与工程可编辑性之间的良好平衡。

## 相关工作脉络
1. **Design2Code / WebSight / Web2Code**：多模态前端代码生成的基础基准，关注语法合规与布局保真度——本文聚焦弥补其在**全局美学控制**与**复杂素材生成**上的不足。
2. **LaTCoder**：提出 Layout-as-Thought 分块生成——本文与其共性在于代码驱动，但本文额外引入图像模拟器提供美学先验。
3. **UICopilot / LayoutCoder**：利用 DOM 层级与布局先验引导生成——本文同样注重结构，但更进一步解决纯代码生成缺乏视觉质感的问题。
4. **UI2Codeⁿ**：将生成建模为"执行-视觉检查-迭代优化"闭环——本文延续该自反思思路，但闭环中加入图像生成模拟环节作为前置美学参考。
5. **TextDiffuser / COLE / OpenCOLE / Graphist / PosterCraft**：图像生成路线的代表工作，聚焦文字渲染与层次分解——本文与其本质区别在于：不将生成图像作为最终交付物，而是作为上游输入驱动结构化编码。
6. **GenClaw**：代码驱动生成范式（code → image），将代码视为可控中间画布——本文沿袭其 Agent 协作思想，但演进为图像生成作为中间素材与前置模拟器（image → code），推动从单一光栅图像向图层解耦的结构化产物转变。

## 局限性与未来方向
1. **基础模型能力上限约束**：方法不创造底层模型缺失的能力，而是将任务路由给更合适的模型——若代码智能体写出弱布局代码，页面即弱；图像模型设计感差（技术干净但构图平庸、无焦点、无色彩理念），则智能体缺乏可依托的美学前驱。
2. **多页一致性难以维持**：当前仅验证单页设计；多页画册或完整网站需在类型比例、配色方案、视觉线索等维度跨页保持一致，当前方法的扩展能力取决于底层模型的规划能力。
3. **美学质量难以量化评估**：海报等设计物无 ground truth，构图是否得体、色彩是否传递氛围、字体比例是否深思熟虑均为主观争议领域——论文选择案例展示而非分数报告，视觉质检依赖 VLM 判断代替设计师之眼。
4. **可编辑性难以数值化**：虽可报告图层数量与 DOM 结构，但核心问题是设计师打开文件后能否真正实现其意图——这不可简化为数字。
5. **未来方向**：扩展到多页/完整网站的跨页面一致性保持；进一步探索生成模型作为"决策辅助工具"而非直接输出的协作模式；推进从"位图输出"到"结构化交付"的范式转变；通过 Agent Design Replay 增强人机协作透明度与人机协同设计交互形式。

## 研究启发与可借鉴点
1. **"Creative Brain + Visual Simulator"的分工范式**：将生成模型定位为 Agent 可调用的外部工具（simulator/asset renderer）而非端到端输出器，这一思路可迁移到任何需要美学质量的代码生成任务（如 UI 自动化、报表生成、数据可视化）。
2. **"Imagine First, Then Act"的闭环工作流**：前置生成视觉参考建立美学先验，再指导后续结构执行——这一模式可有效应用于任何"需要美学判断+结构实现"的双重任务，减少纯代码生成中的盲打尝试。
3. **独立素材生成避免层纠缠**：本地图形素材（background、subject）按需单独生成而非从主图切割，从根本上避免了像素污染与层耦合——该策略对图像分割、图层解耦、多模态资产管理等方向有直接参考价值。
4. **双轨验证机制（确定性规则 + 多模态反思）**：无头浏览器中的 DOM/布局规则检查结合 VLM 的视觉美学评判，形成互补——这一混合验证范式可扩展至前端代码生成、UI 自动化测试等场景。
5. **Agent Design Replay 作为可追溯性设计**：将完整决策链序列化记录，既提升过程透明度又为人机协作提供介入点——可借鉴用于设计系统的版本追踪、A/B 设计的迭代对比、或作为设计资产的元数据沉淀。

## 关键术语表
**Creative Brain（创意大脑）**：指 VLM（如 Codex/GPT-5.6 Sol），负责需求理解、设计规划、代码构建与结果评判的决策核心。

**Visual World Simulator（视觉世界模拟器）**：指图像生成模型（如 GPT Image 2），作为按需调用的工具将抽象构思转化为具体视觉效果，而非最终交付物。

**Imagined Visual（想象视觉）**：在代码编写前由图像模型生成的成品级效果图，作为后续所有步骤的全局美学参照先验。

**Asset Generation（素材生成）**：按需独立生成干净的、无背景的本地图形素材（如纯色背景 + matting 提取），确保交付物不含生成图像的像素污染。

**Visual Self-Healing（视觉自愈）**：通过无头浏览器确定性规则检查与 VLM 多模态视觉反思双轨验证，发现并自动修复布局溢出、元素重叠、图文遮挡等缺陷。

**Agent Design Replay（智能体设计回放）**：序列化记录智能体从需求拆解、视觉想象、素材提示词到代码演化与反思修复的完整决策轨迹，实现设计过程透明可追溯。

**Layer Decoupling（图层解耦）**：最终产物中文本、背景、插图等元素作为独立 DOM 节点，用户可单独选择、编辑、拖拽和导出，不受像素纠缠限制。

**Editable Artifact（可编辑产物）**：兼具高品质美学与工程级可编辑性的结构化设计交付物，支持用户在 GUI 上进行直观的鼠标拖拽与布局调整。
