# 论文速读：CROCODIL-Cross-Model-Code-Editing-with-LLMs

## 一句话总结
本文发现LLM在编辑其他LLM生成的"外来代码"时会产生过度编辑，并提出CROCODIL后训练框架，通过相似性奖励与执行奖励的乘积形式配合GRPO优化，在不牺牲功能正确性的前提下将Olmo3 7B的编辑量减少约50%，且该效果无法通过提示工程实现。

## 研究问题与动机
- **跨模型编辑场景普遍但未被研究**：开发团队常使用多个LLM助手，同一名开发者也可能在不同会话间切换模型，导致已生成的代码常需由不同风格的模型进行编辑。
- **现有基准不适用**：已有代码编辑基准（如Can It Edit、EDIT-Bench）仅允许更换编辑模型，无法操控"预编辑代码的作者"这一变量，因而无法回答"编辑行为是否受代码来源模型影响"。
- **过度编辑带来实际代价**：更大的编辑幅度意味着更慢的代码审查、更多的测试执行负担，从而影响整体开发效率。
- **提示工程无法稳定解决**：即使系统提示明确要求"最小化编辑"，仍无法一致性地降低编辑量或提升成功率。

## 核心贡献（创新点）
1. **首次系统刻画LLM跨模型编辑行为**：构建可独立操控"实现者"与"编辑者"模型的Rust PR语料库，发现4个开源模型在16组配对中有14组对自身代码的编辑量显著小于对外来代码的编辑量。
2. **提出CROCODIL后训练框架**：设计由相似性奖励与执行奖励相乘构成的复合奖励函数，通过GRPO显式惩罚过度变更，同时保留功能正确性。
3. **证明提示工程的局限性**：严格提示（Strict prompt）仅在部分实现者代码上降低编辑量，且幅度远小于RL训练模型，甚至在Olmo3 7B和Haiku 4.5的实现上反而增大编辑量。
4. **实现编辑量减半且成功率提升**：在全部任务上，CROCODIL训练的Olmo3 7B RL将编辑距离缩减至基座模型的约一半；在双方均通过测试的任务子集上，仍保持更小编辑量，并在除Olmo3 7B自身外的所有实现者代码上提升构建与测试通过率。

## 方法详解
- **任务形式化**：将函数编辑建模为序列级强化学习问题，策略π_θ接收已实现的预编辑函数f^A_pre-edit、任务描述d和上下文C，生成后编辑函数f^A→B_post-edit。
- **相似性奖励（R_sim）**：衡量模型编辑幅度与开发者原始PR编辑幅度的比例。令c_m、l_m为模型编辑的字符数与行数，D_m = (c_m + 1)(l_m + 1)；开发者编辑量为D_h = (c_h + 1)(l_h + 1)。奖励公式为R_sim = 1 / (1 + α · D_m / D_h)，其中α=0.33控制惩罚陡峭度。该奖励与GR3的长度重缩放思想一脉相承，但以"任务规模"而非"组内均值"作为归一化基准。
- **执行奖励（R_exec）**：由编译成功信号b（0/1）、预编辑函数已有测试通过率p_pre-edit和后编辑函数新增测试通过率p_post-edit加权构成：R_exec = w_b·b + w_pre·p_pre-edit + w_post·p_post-edit，训练时权重设为w_b=0.2、w_pre=0.4、w_post=0.4。
- **复合奖励与优化**：总奖励R_CROCODIL = R_sim × R_exec，使用GRPO（Group Relative Policy Optimization）配合LoRA（rank 32, alpha 64）对Olmo3 7B进行3轮训练，学习率3×10^-5，KL正则系数0.001，批大小32，每提示8次采样，温度1.0。
- **数据收集框架**：从crates.io收集Rust PR，筛选最多变更5个文件且至少75%为Rust的PR，提取20-200行非空非注释行的函数；通过line-coverage collector收集覆盖预编辑与后编辑函数的测试；实现阶段采用draft+repair两阶段流程（最多6轮自修复），并通过Instruct Agent与Patch Agent解耦诊断与修补过程以避免风格泄露。

## 实验与结果
- **数据集**：评估集含549（Qwen3.5）、424（GPT-OSS 20B）、202（Olmo3.1 32B）、68（Olmo3 7B）、453（Haiku 4.5）个任务；训练集含355个跨编辑任务与39个验证任务，来自与评估集无项目重叠的388个仓库中的150个。
- **基线**：Olmo3 7B Base（未训练基座）、Olmo3 7B Strict（严格提示）。
- **核心结果（Table 4）**：在全量任务上，Olmo3 7B RL对各开源实现者的编辑距离均约为Base的50%；在Base与RL均通过测试的子集上，RL仍更小。
- **成功率提升（Table 5）**：除Olmo3 7B自身实现外，RL在全部5类实现者代码上的构建通过率、全测试通过率与平均测试通过率均优于Base与Strict。
- **剔除"不改"样本后的稳健性（Table 6）**：RL模型约19.94%的输出为无变更，剔除后在有实际修改的任务上仍保持更高构建通过率。
- **统计显著性（Table 3）**：16组self-vs-cross对比中14组显示self-edit更小，其中7组在p<0.05水平显著；唯一例外是Haiku 4.5（遵循不同模式）和Olmo3 7B在Olmo3.1/Haiku实现上的反向差异。
- **最强结果**：Olmo3 7B RL对Qwen3.5 35B A3B实现的构建通过率从32.67%提升至41.46%，全测试通过率从16.92%提升至19.07%，平均测试通过率从21.12%提升至26.97%。

## 相关工作脉络
- **CoditT5**（Zhang et al., 2022）：提出显式建模代码编辑的预训练目标，关注编辑能力本身；本文关注减少编辑量而非提升编辑能力。
- **Can It Edit / EditPackFT**（Cassano et al., 2024）：收集Python仓库提交构建编辑基准，但无法区分"预编辑代码作者"；本文语料支持操纵实现者变量。
- **EDIT-Bench**（Chi et al., 2026）：基于VS Code扩展用户指令构建真实编辑任务；本文采用PR diff与测试覆盖的自动化收集策略。
- **SWE-agent / Agentless**（Yang et al., 2024; Xia et al., 2025）：通过工具调用与多阶段流程提升编辑能力；本文聚焦单一模型的后训练 Reward Design。
- **CodeRL / RLTF / StepCoder**：围绕编译器反馈与单元测试设计执行奖励；本文创新在于将"相似性奖励"与执行奖励结合，专门应对跨风格编辑。
- **GR3**（Li et al., 2026）：针对响应长度膨胀设计重缩放奖励；本文将其思想迁移至编辑幅度，并以开发者原始PR编辑量作为归一化基准。

## 局限性与未来方向
- **单一语言局限**：语料与训练数据仅来自Rust crates，Python/JavaScript等弱类型或语法差异较大的语言中的跨编辑模式尚未验证。
- **函数级作用域**：编辑任务限定为单函数（20-200行），跨函数或多文件编辑不在研究范围内。
- **模型池有限**：仅评估5个LLM（4开源+1闭源Haiku 4.5），仅对Olmo3 7B进行RL训练；GPT-5、Claude Opus等大型闭源模型未被测试。
- **Haiku 4.5行为异常**：Haiku 4.5不遵循"self-edit更小"的规律，其跨编辑行为机制未被解释，作者指出这是有吸引力的未来方向。
- **部分失败模式**：相似性奖励可能导致模型在标识符传播等微小编辑任务上过度保守，拒绝执行本应完成的更名传播。

## 研究启发与可借鉴点
- **奖励设计的正交分解**：将"编辑幅度"与"功能正确性"解耦为两个可调节的奖励分量，为代码智能体的多目标优化提供了清晰范式。
- **以开发者原始变更作为归一化基准**：用D_h（PR diff的实际编辑量）替代组内均值，使奖励与任务规模成正比，这一思路可迁移至任何需要"最小化变更"的编辑/修复任务。
- **实现者与编辑者的解耦评估设计**：通过独立构造"实现"与"编辑"两个阶段，并设置严格的数据过滤（重叠<50%、测试覆盖率等），有效隔离了风格泄露与记忆效应，该数据工程方法论可复用于其他LLM行为研究。
- **提示工程作为弱基线的对照价值**：严格提示未能稳定降低编辑量，这一负结果强化了后训练方法在该问题上的必要性，为后续工作提供了清晰的对比基准。
- **LoRA适配器按需加载策略**：训练后保留Base模型，仅在跨编辑任务上加载LoRA适配器，可在不损害自我编辑性能的前提下改善跨模型表现，这一部署模式具有工程实用性。

## 关键术语表
- **CROCODIL**：Cross-Model Code Editing with LLMs，本文提出的后训练框架，通过复合奖励减少LLM对跨模型代码的过度编辑。
- **相似性奖励（R_sim）**：惩罚模型编辑幅度超过开发者原始PR编辑量的奖励分量，公式为1/(1+α·D_m/D_h)。
- **执行奖励（R_exec）**：由编译成功与测试通过率加权构成的奖励分量，衡量编辑的功能正确性。
- **GRPO**：Group Relative Policy Optimization，本文使用的强化学习优化算法，基于组内相对优势进行策略梯度更新。
- **Levenshtein编辑距离**：本文用于量化编辑大小的指标，在字符粒度上计算实现与编辑输出的差异，并经rustfmt格式化与注释去除后处理。
- **self-edit / cross-edit**：分别指模型编辑自身实现的代码与编辑其他模型实现的代码，本文核心对比场景。
- **Instruct Agent / Patch Agent**：修复阶段的两阶段代理设计，前者诊断bug并生成自然语言修复计划，后者生成修复后的代码，避免风格泄露。
- **overlap过滤**：丢弃与开发者原始函数Gestalt-pattern-matching相似度超过50%的实现，防止训练记忆污染。

## 可复现要素
- **数据集**：语料来源于crates.io注册且托管于GitHub的Rust仓库，经过严格筛选与测试收集；训练与评估数据未公开链接，但代码已开源。
- **代码与权重**：CROCODIL代码开源，地址为 https://github.com/EngineeringSoftware/Crocodil；训练使用Olmo3 7B基座与LoRA适配器（rank 32, alpha 64）。
- **关键超参**：GRPO训练3轮，批大小32，每提示8次采样，温度1.0，学习率3×10^-5，KL正则系数0.001；相似性奖励α=0.33；执行奖励权重w_b=0.2, w_pre=0.4, w_post=0.4。
- **实现细节**：draft阶段使用7项上下文（C_FuncSig, C_Callees, C_CallSites, C_Use, C_Impl, C_RepoDesc, C_FuncDesc）；repair阶段最多6轮（Haiku为2轮），使用10,000-token窗口生成描述；训练数据上下文中总token限制为12,288（输出保留6,144）。
