# 论文速读：Aspire-Can-Models-Self-Evolve-from-Vague-Goals

## 一句话总结
论文提出 Aspire，首个面向“模糊目标驱动自演进”的基准与交互环境，要求智能体仅凭自然语言的能力方向自行完成目标规约化、数据构建、训练策略选择与验证决策，并在完全隐藏的专家评测集上检验真实能力提升。实验表明当前智能体能稳定跑通训练闭环，但权重级保留收益稀疏且不稳定，进化出的最强 Agent Harness 仍低于人工工程化的参考版本。

## 研究问题与动机
- 现有 LLM 自演进工作（PostTrainBench、LaMDAgent、SEAL 等）均以人类预先定义好的具体任务、指标与成功标准为前提，智能体仅搜索“如何优化”，无法处理“应该优化什么能力”这一更前端的目标规约化决策。
- 真实部署场景（如 Forward-Deployed Engineer 角色）中，需求往往是宽泛的能力方向，缺乏可直接训练的分解式奖励，且测试/验证信号缺失或不可靠，亟需研究模型如何将模糊目标转化为可操作的学习目标与验证信号。
- 当前基准多停留在执行层面，掩盖了目标规约化这一关键过程；缺少在隐藏评估下衡量“完成训练闭环”与“保留目标对齐的真实能力提升”之间差距的系统性评测。
- 模型权重进化与支撑 Harness 进化通常被分开研究，缺乏在统一环境中对比两者的自演进能力边界与失败模式。

## 核心贡献（创新点）
- 形式化“目标规约化”（target operationalization）过程：将宽泛能力目标转化为可训练目标、学习信号与验证标准，填补自主后训练中被忽视的前置决策轴。
- 推出 Aspire 基准与最小交互环境：提供仅含自然语言目标的协议、隐藏且不可见的 520 题专家评测集，以及统一的 Agent Tool 接口，同时支持模型权重与 Agent Harness 双层演进。
- 揭示“执行更新”与“保留提升”之间的本质差距：通过轨迹分析证明智能体常训练错配数据、过度信任狭窄自评估，局部代理指标的提升难以迁移至隐藏目标评测，且持续搜索可能抹除已有改进。

## 方法详解
- **环境设计**：智能体通过单一抽象工具完成数据搜索/导入/合成、SFT 或 GRPO 训练（支持 LoRA 等）、作业状态查询、自建验证集评估、分支与终止；控制器负责凭证、调度、资源隔离与 Checkpoint 验证，将战略决策与基础设施复杂度解耦。
- **隐藏评估集**：520 道专家从零撰写的题目，覆盖 6 个模糊目标（科学学术推理 75、人文社科知识 110、健康医学推理 100、数学推理 126、逻辑可靠性与指令遵循 89、学术科学写作 20）；严格去重、重叠审计、盲测难度校准与版本固化，智能体不可见题目、参考答案与细粒度反馈，仅协议允许的聚合分数。
- **两种评测协议**：Final-only（仅最终提交 Checkpoint 接受一次隐藏评测，24 次运行取 Avg@2）与 Adaptive-feedback（允许有限次聚合分数查询，用于指导多 Checkpoint 搜索与分支）。
- **安全保留机制**：定义原始分差 $\Delta^{\mathrm{raw}}(k) = \widehat{s}_{\Gamma}(Y(k)) - \widehat{s}_{\Gamma}(Y^{\mathrm{in}})$，仅当最佳候选 $\Delta^{\mathrm{raw}} > 0$ 时才保留进化结果，否则回滚至初始状态，确保记录的非负保留增益 $\Delta^{\mathrm{ret}} \ge 0$。
- **双层演进表面**：Weight evolution 固定 Harness $H_0$ 与决策模型 $D_r$，演化权重 $M$；Harness evolution 固定权重 $M_0$，演化运行时 Prompt、工具策略、工作流与验证逻辑 $H$。

## 实验与结果
- **RQ1（目标规格影响）**：Claude Opus 4.8 在模糊目标下聚合分 27.07，低于官方 PostTrainBench 参考 32.90；GPT-5.6 为 29.58 vs 36.23。模糊目标延长决策模型思考时间（+2,109 秒）与 GPU 空闲时间（+0.61h），减少活跃训练时间（-1.27h），LoRA 使用率从 24.1% 升至 89.8%，搜索重心明显转向目标解读。
- **RQ2（权重自演进）**：Final-only 协议下 24 次运行中仅 1 对 Avg@2 超过基线（Qwen3.5-9B 科学推理 45.33→48.00，+2.67）；Adaptive-feedback 30 个配置-目标单元格中，28 个产出可评测 Checkpoint，但仅 2 个最佳分超基线，唯一通过回滚保留的是 Terra 驱动的 Qwen3.5-4B 数学推理（17.86→20.10）。观察到大模型常将 GSM8K/Hendrycks 数学数据用于非数学目标，且使用单数字标签 MMLU SFT 导致输出格式坍塌（全输出个位数，得分多为 0）。
- **RQ3（Harness 自演进）**：固定 Qwen3.5-4B，在学术科学写作（20 题）上，最强进化 Harness（Sol 创建）Task macro 27.22 / Example micro 25.97，仍低于人工 Qwen-Agent 参考值（28.64 / 27.65）。失败模式包括：Luna 过拟合狭窄自验证清单（8/8）导致隐藏题被错误重构；Terra 遗漏最终答案不变量，计算器调用后空响应导致部分草稿被提交（贡献约 70% 的分数下降）。
- **最强结果与提升幅度**：Adaptive-feedback 中
