# 论文速读：Ignorance-or-Incompetence-Constructing-Knowledge-Gated-Verif

## 一句话总结
本文提出一种知识门控任务构建协议，将任务指令与包含私有约定/参考表/工具算符的紧凑工件分离，使智能体对特定领域知识的依赖变为显式可检验变量；在15个校准任务上，前端Agent配置在提供工件时通过率达68.0%，无工件时降至0%，且使用错误工件仍为0%，证明了知识依赖的可控性与可验证性。

## 研究问题与动机
1. **专业Agent任务的知识依赖难以控制**：真实专业领域任务依赖公共语料库中不存在的私有约定，但现有基准极少显式控制Agent能否访问这些约定。
2. **合成数据的生成能力悖论**：若生成器已知全部规则，任务仅反映其自身能力上限；若规则完全不可用，任务则难以验证——如何使知识成为必要但可追踪的变量？
3. **现有方法的不足**：模型生成指令微调通常在生成器固有能力上遭遇瓶颈；传统数据集蒸馏压缩为权重空间张量，智能体推理时无法访问；SkillsBench等仅观察"有/无"技能的影响，未将其作为任务构造的显式设计属性。

## 核心贡献（创新点）
1. **知识门控任务构建契约**：将任务指令与千字节级工件分离，配合静态泄漏审计确保指令不包含门控内容，与已有工作仅观察技能可用性的区别在于——本文强制约束"指令-工件"边界，使知识依赖可审计而非仅可观察。
2. **两类知识门控设计（约定门控 vs. 算子门控）**：约定门控植入私有不可推导的选择（如内部阈值、归一化表），算子门控放置难以手工编写的算法（如Brandes介数中心性），二者本质区别在于前者严格不可推导，后者仅建立陡峭能力壁垒但仍可尝试重推导。
3. **确定性验证 + 命名标准级评分的双重验证框架**：结构化任务使用确定性求解器计算精确地面真值，开放式输出通过命名标准级rubric实现逐条归因，比单一可执行oracle支持更灵活的任务类型。
4. **配置相对校准筛选机制**：基于三条件不等式筛选任务（前沿配置+工件≥60%，前沿配置-工件=0%，中间配置+工件≤40%），比传统pass-rate过滤更强调条件间分离而非方差控制。
5. **泄漏审计与公平协议**：指令在多条件下字节级相同，含回退子句防止-ablation条件下Agent直接放弃，审计脚本对9/15任务可执行，比现有工作仅做语义审查更具工程可操作性。

## 方法详解
1. **任务/知识分离架构**：每个任务由两部分组成——任务指令（规定输出模式、格式、排序等）和知识工件（领域术语、约定、公式、参考表、低层算符，不含端到端解脚本），二者边界由审计协议检查。
2. **两类门控的构造原则**：
   - 约定门控：植入不可推导的私有选择，如"turnover指标是否排除开 minutes"、分母用235而非240，确保难度严格由知识决定。
   - 算子门控：将难以手写的算法（如Brandes betweenness、Garman–Klass volatility）放入工件工具库，Agent必须重推导脆弱数值。
3. **泄漏审计协议**：静态扫描指令和环境数据中的显式门控常量及工件提及；9/15任务配有可执行审计脚本；指令含回退子句"当无规范时应用通用惯例"，确保-ablation条件下提交可验证答案而非弃权。
4. **配置相对校准筛选公式**：
   $$\mathbb{I}_{\text{retain}} = \mathbf{1}\left[\hat{p}(A_F, +\mathbf{A}) \geq 0.6 \land \hat{p}(A_F, -\mathbf{A}) = 0 \land \hat{p}(A_{\text{mid}}, +\mathbf{A}) \leq 0.4\right]$$
   其中每单元格5次独立试验，阈值为粗粒度质量控制而非统计检验。
5. **验证机制**：结构化输出使用Python确定性求解器和严格数值容差（通常$10^{-4}$）；开放式输出使用乘积奖励$R = \prod_{k=1}^{K}\nu_k$，每个命名标准独立评分，失败可归因。

## 实验与结果
1. **实验设置**：前沿配置$A_F$=Claude Opus 4.8 + Claude Code；中间配置$A_{\text{mid}}$=Qwen3.6-Plus + OpenCode；每任务×配置×条件3种组合各5次独立试验，隔离Docker沙箱运行。
2. **主要结果（15任务校准集）**：$A_F,+A$=68.0%（51/75），$A_F,-A$=0%（0/75），$A_{\text{mid}},+A$=22.7%（17/75）；七项任务通过筛选（legal-clause, paper-index, bom-costing, airline-booking, clinical-variant, mortgage-escrow, dependency-audit）。
3. **扰动工件控制**：bom-costing任务将三个约定改为合理但错误的值（12%→15%复合率等），Opus通过率降至0%，证明依赖的是正确知识而非工件存在本身。
4. **复述探针**：Qwen在单轮无工具环境下对legal-clause和bom-costing均100%正确复述约定并完成计算，但全Agent harness下0%通过，定位失败源于文件发现/工具调用/输出格式合规而非知识缺失。
5. **压缩案例**：paper-index任务将4379B工件压缩至1078B（4倍压缩），通过率仍为100%，证明操作内容可极度精简。
6. **与外部基准对比**：τ²-bench telecom技能可用提升18点（34.2%→51.8%），SciCode提升9.4点，本文零→多数成功转变幅度显著更大。

## 局限性与未来方向
1. **样本量小**：仅15个校准任务、每单元格5次试验，保留决策对单次结果敏感；Wilson置信区间宽。
2. **泄漏审计覆盖不全**：仅9/15任务有可执行审计脚本，静态扫描无法排除语义或间接泄漏。
3. **配置相对性**：筛选结果绑定特定模型-harness组合，无法推广为任务 intrinsic 排名。
4. **复述探针局限性**：剥离了工具调用和沙箱环境，与全harness设置不可直接比较。
5. **未涉及训练验证**：明确声明未使用这些数据训练，下游训练价值需独立验证。
6. **未来方向**：扩展至完整泄漏审计、更多试验、统一harness配置、端到端post-training对比、扩展到不可验证输出的证据下界目标。

## 研究启发与可借鉴点
1. **"指令-工件"分离审计**可作为合成任务构建的标准协议组件，强制约束边界使知识依赖可追踪而非偶然属性。
2. **两类门控的设计区分**（约定vs.算子）为构造不同难度梯度的任务提供了清晰的理论框架，后续可分别针对两类设计不同的训练策略。
3. **复述探针（recitation probe）**是定位Agent失败根源的有效诊断工具——将知识持有与执行能力解耦，值得引入Agent评估流程。
4. **配置相对筛选公式**提供了一个可复用的质量控制模板，阈值可根据目标场景调整，但需注意其configuration-relative的本质。
5. **压缩案例**表明操作内容可极度精简，为后续研究探索"最小必要工件"和压缩-性能曲线提供了方法论基础。

## 关键术语表
**Knowledge-gated task**：任务指令中不包含解决问题所需的全部信息，必须依赖额外提供的私有工件才能正确完成。
**Artifact**：千字节级的紧凑知识库，包含领域约定、参考表、工具算符，不含端到端解脚本。
**Convention gate**：植入私有不可推导选择（如内部阈值、归一化表）的知识门控类型。
**Operator gate**：将难以手工编写的算法放入工件工具库，建立陡峭能力壁垒的门控类型。
**Leak audit**：静态扫描任务指令和环境数据，检查是否意外包含门控内容或工件提及。
**Configuration-relative screen**：基于特定Agent配置的三条件不等式筛选规则，用于保留符合条件的校准任务。
**Recitation probe**：将工件内容提取为单轮问答，检验Agent是否能正确复述私有约定，用于定位失败根源。
**Verifiable reward**：对结构化输出使用确定性求解器精确验证，对开放式输出使用命名标准级rubric逐条评分。
