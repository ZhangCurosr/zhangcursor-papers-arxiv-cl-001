# 论文速读：Ignorance-or-Incompetence-Constructing-Knowledge-Gated-Verif

## 一句话总结
本文提出了一种**知识门控（Knowledge-Gated）任务构建协议**，通过将任务指令与包含私有领域惯例/算子的紧凑工件（Artefact）严格分离，并辅以静态泄漏审计与确定性验证，使模型对特定私有知识的依赖变为显式且可检验的控制变量。在15个校准任务上，前沿Agent配置在无工件时通过率为0%，加入工件后跃升至68.0%，验证了该协议能有效构造“无知（Ignorance）”与“能力不足（Incompetence）”可区分的可控评测/训练数据。

## 研究问题与动机
- **私有惯例不可达却必需**：专业Agent任务常依赖公共语料中缺失的内部阈值、归一化表或特定算子，但现有基准极少控制Agent是否真正接触这些惯例，导致评测结果混杂了检索、工具调用等无关能力。
- **合成数据的能力天花板**：模型自生成指令微调通常卡在生成器自身能力上限（plateau at generator’s inherent capability）；传统数据集蒸馏产出的是权重空间张量，Agent在推理时根本无法访问。
- **难构造与难验证的悖论**：若生成器已掌握解题所需全部规则，任务附加值有限；若规则完全不可得，任务又会退化为无法验证的开放题。如何让构建者能“故意”植入不可推导的私有知识，同时保留对正确答案的精确验标，是核心矛盾。

## 核心贡献（创新点）
1. **知识门控任务构建契约**：指令与千字节级工件物理/文本分离，指令绝不提及工件，并通过可执行泄漏审计（9/15任务）确保门控内容未被意外暴露；相比现有工作依赖环境隐含推导，本文首次将“私有知识访问”作为显式、可审计的实验变量。
2. **双轨验证与细粒度归因协议**：结构化输出采用独立Python求解器提供精确Ground Truth；开放式交付物采用命名准则级Rubric（全通过语义 $R=\prod \nu_k$），失败可精准定位到具体准则，解决了以往Agent任务难以兼顾“高门槛”与“可验证”的痛点。
3. **配置相关的校准筛选机制**：提出基于三细胞通过率阈值的经验筛选规则，从15个候选任务中保留7个满足门控行为的任务；明确了筛选结果仅表征协议行为、不宣称训练收益，为高质量合成数据构建提供了可复现的质量门禁。

## 方法详解
- **任务/知识分离架构**：每个单元由 **(i) Task**（输入、输出模式、格式/排序要求、成功标准）与 **(ii) Knowledge Artefact**（领域术语、私有惯例、公式、参考表、底层工具算子；不含端到端解法）组成。工件由人类策展人从大规模领域语料中手工精炼至KB级，指令仅表述“需要做什么”。
- **两类知识门控**：
  - *惯例门（Convention gates）*：植入不可推导的私有选择（如内部阈值235/240、特定别名、归一化约定），模型能给出合理答案，但只有工件指定版本才是正确。
  - *算子门（Operator gates）*：将手难以编写或易出错的复杂算法（如Brandes介数中心性、Garman–Klass波动率）封装入工件工具库，建立陡峭的能力门槛。
- **泄漏审计（Leak Audit）**：-A条件下指令字节级一致，含 fallback 子句引导应用通用惯例以避免空回复。静态扫描检查指令与环境是否暴露门控常数或提及工件；9个任务提供可执行审计脚本。
- **校准筛选（Calibration Screen）**：对每个候选任务在3种配置下各跑5次试验，计算经验通过率 $\hat{p}$。保留规则：
  $\mathbb{I}_{\text{retain}} = \mathbf{1}\left[\hat{p}(A_F, +A) \geq 0.6 \;\land\; \hat{p}(A_F, -A) = 0 \;\land\; \hat{p}(A_{\text{mid}}, +A) \leq 0.4\right]$
  其中 $A_F$ 为前沿配置，$A_{\text{mid}}$ 为次级配置。结果明确配置相关，不声称是任务固有难度排名。
- **验证机制**：结构化任务用独立实现重算参考值，浮点容差通常 $10^{-4}$；开放式任务采用全通过Rubric，每个 $\nu_k=0$ 可归因。本文15个报告任务全部使用确定性验证路径。

## 实验与结果
- **数据集/任务**：15个校准任务（混合自研合成任务与SkillsBench适配样本），涵盖法律条款风险、出版物索引、BOM成本汇总、航班预订审计、临床试验队列、抵押贷款托管等。
- **评估配置**：前沿 $A_F$ = Claude Opus 4.8 + Claude Code (BenchFlow claude-agent-acp)；次级 $A_{\text{mid}}$ = Qwen3.6-Plus + OpenCode。均运行于隔离Docker沙箱，每单元格5次独立轨迹。
- **核心结果**：
  - $A_F$ 下：无工件(-A)通过率 **0%**，有工件(+A)通过率 **68.0%**（51/75），提升 **68个百分点**。
  - $A_{\text{mid}}$ 下：+A通过率 **22.7%**（17/75）。
  - **干扰工件控制**：对bom-costing任务使用3个数值惯例被改为“合理但错误”值的工件，Opus通过率降至 **0%**，与无工件一致，证明效应来自内容正确性而非文档存在本身。
  - **重述探测（Recitation Probe）**：Qwen在单轮内联数据+无工具环境下能100%正确重述惯例并解题；但在完整Harness下通过率为0%。表明其失败主要源于工具调用/文件发现/输出合规等执行层问题，而非知识缺失。
  - 校准筛选后保留 **7个任务**（legal-clause, paper-index, bom-costing, airline-booking, clinical-variant, mortgage-escrow, dependency-audit）。
- **公开基准对照**：$\tau^2$-bench加入流程手册后GPT-4.1提升17.6点，SciCode加入背景后Claude-3.5-Sonnet提升9.4点；本文协议实现的是从“绝对零通过”到“多数通过”的阶跃式变化。

## 相关工作脉络
- **SkillsBench / $\tau^2$-bench / SciCode**：展示提供外部技能文档或领域背景可提升Agent性能（提升18–36点区间），但缺乏指令/工件分离与泄漏审计，依赖关系是隐含的；本文将其显式化并可通过±A ablation严格检验。
- **SWE-bench / SWE-smith / SWE-Gym**：侧重从GitHub issue-patch或代码仓库生成可执行环境，依赖环境本身的可推导性；本文强调植入“不可推导”的私有惯例，绕过此类可推导性瓶颈。
- **传统 Dataset Distillation**：通过梯度匹配或轨迹对齐压缩海量语料为训练张量；本文工件以文本形式在推理时直接注入上下文，不做权重空间优化，属于上下文蒸馏近亲但增加了强制门控协议。
- **Agentic Context Learning**：研究Agent从可见上下文中恢复未明确指定的规范；本文反向操作，植入一个从指令/环境完全不可推导的规范，并使其成为受控实验变量。
- **RLVR & 通过率筛选（Reinforce-ada, Online difficulty filtering）**：强调训练时需避开通过率0%
