# 论文速读：Write, Execute, Refine: From Skill Followers to Skill Optimizers via Reinforcement Learning from Execution Feedback

## 一句话总结
论文提出 WER（Write-Execute-Refine）框架，将“技能优化”解耦为一个独立可训练的策略，通过冻结执行代理、使用程序化验证器提供组内相对奖励，并利用跨阶段的自启动经验装配机制，使模型学会从执行轨迹中提取可复用的过程性指导。在 BFCL v4 与 τ²-bench 上，该 4B 参数优化器将 Pass@1 分别提升至 76.63% 和 50.72%，显著优于同架构未训练基线及多款通用大模型。

## 研究问题与动机
- **专家技能有效但代理自撰技能退化**：SkillsBench 显示专家编写技能可将平均通过率从 33.9% 提升至 50.5%，但代理自撰技能反而比“不加分隔技能”低 8–11 个百分点，暴露出“遵循流程指导”与“从执行证据改进指导”是两种不同能力。
- **推理时回路无法训练写作模型**：现有推理时技能修订（如 EvoSkill、SkillRevise）仅修复当前工件，未更新底层的技能写作能力；每次新任务仍依赖基座模型重新诊断日志并翻译失败原因，且标准预训练/指令微调无法直接优化这种执行接地反思能力。
- **错误修正代价高且自验证难以恢复**：注入 10% 看似合理实则错误的经验即可使 τ²-bench Pass@1 从 82.5 降至 77.2，而自验证几乎无法弥补该损失（83.3→83.2），说明单一回合的推理时修补不足以教给模型正确的修订策略。
- **缺乏将执行经验结构化为训练状态的机制**：尽管 SkillMaster、SkillOS、Skill-R1 等已证明技能改进本身可被学习，但如何组织多阶段执行经验、分配信用并构建跨阶段训练状态，仍是未解问题。

## 核心贡献（创新点）
- **将技能修订建模为独立的执行条件策略**：提出 Skill Optimizer π_θ，仅输出文本技能文档而不参与环境动作，与冻结执行器彻底解耦，使优化目标聚焦于“从轨迹到过程性指令”的映射能力。
- **设计阶段级自启动（Phase-Wise Self-Bootstrapping）机制**：通过保留混合结果记录（同一技能在同一任务上既成功又失败），将成功/失败轨迹配对并拼合为下一阶段的细化状态，使优化器持续学习自身历史输出的执行后果，而非重复从零起草。
- **提出组内相对优化与无锚点 GRPO 更新**：采用组内相对优势消除任务难度偏差，并结合格式、任务、长度三项奖励；不使用 KL 惩罚或参考策略，避免锚定初始化分布抑制新的修订风格习得。
- **实证专用修订训练显著超越通用推理能力**：仅 4B 参数的 WER 优化器在 BFCL v4 达到 76.63% Pass@1，以相同工作流大幅优于未训练同 Backbone（+9.35/+10.29），并以 1.88 个百分点领先最强通用模型 GPT-5.5，证明技能修订是可学习的独立能力。

## 方法详解
- **细化状态与策略定义**：细化状态记为 $x = (q, \mathcal{C}, h, s, e)$，其中 $q$ 为用户查询，$\mathcal{C}$ 为可见工具定义与环境描述，$h$ 为交互历史，$s$ 为当前技能，$e$ 为上轮执行证据。优化器策略为 $s' \sim \pi_\theta(\cdot|x)$，冷启动时 $s$ 由 GPT-5.1 零样本生成，后续轮次仅改变 $s, h, e$ 的来源。
- **冻结执行与双通道观测**：候选技能 $s'$ 注入冻结代理 $\pi_A$ 后在沙盒环境 $\mathcal{E}$ 中执行 $n$ 次，产出轨迹 $\tau = (a_1,o_1,\ldots,a_T,o_T,y)$。观测分两路：(1) 原始轨迹原文保留，供优化器定位具体步骤缺陷；(2) 程序化验证器比对最终环境状态与参考解，给出确定性奖励。
- **组合奖励设计**：$R(s') = \frac{1}{3}(R_{\mathrm{fmt}} + R_{\mathrm{task}} + R_{\mathrm{len}})$。$R_{\mathrm{fmt}}$ 要求输出可解析且推理块与技能体分块；$R_{\mathrm{task}}$ 为验证器在多轮 rollout 上的聚合结果；$R_{\mathrm{len}}$ 惩罚空推理或超出预算的推理。$R_{\mathrm{fmt}}$ 随训练衰减。
- **组内相对优势与梯度更新**：对同一 $x$ 采样 $K$ 个候选，优势 $\hat{A}_k = R_k - \mu(\mathbf{R})$（可选除以 $\sigma(\mathbf{R})$）。采用截断 GRPO 代理目标 $\mathcal{I}(\theta) = \mathbb{E}_x[\frac{1}{K}\sum_k \min(\rho_k \hat{A}_k, \mathrm{clip}(\rho_k,1-\epsilon,1+\epsilon)\hat{A}_k)]$，无 KL 项与参考策略，直接以相对信号驱动修订风格演化。
- **跨阶段经验装配**：阶段结束后将记录 $(x, s', \{\tau_j\}, R)$ 存入经验缓冲；仅保留混合结果（如 $n=2$ 时得分为 1 的记录），因成功/失败路径唯一差异来自技能缺口，可构成强对比信号。下一阶段状态以拼接而非摘要方式重建：保留原技能 $s$、恢复上下文 $\mathcal{C}$，并将成功轨迹置于 success block、失败轨迹置于 failure block，直接喂入优化器。由此形成随阶段增长的修订树，训练分布自然向“近乎充分但略有缺陷”的技能收敛。

## 实验与结果
- **数据集与评估**：BFCL v4 multi-turn（200 实例，50 训练/150 测试，覆盖 File System、Trading、Travel、Vehicle 四域）与 τ²-bench（Airline、Retail、Telecom）。主指标为 Pass@1（单次尝试成功率），每基准评测 3 次取平均。
- **基线对比**：No Skill、GPT-5.1 Seed Skill、Qwen3-4B（未训练同骨干）、Skill-R1、Trace2Skill；另与 DeepSeek-V4-Flash、GPT-5.5、Gemini 3.5 Flash、Claude Sonnet 4.6 对比。
- **主要结果**：WER 较 No Skill 在 BFCL v4 提升 +7.80（68.83%→76.63%）、τ²-bench 提升 +3.85（46.87%→50.72%）；较同骨干未训练版本提升 +9.35（BFCL v4）与 +10.29（τ²-bench）。WER 在 BFCL v4 全部四域中取得最优或并列最优，在 τ²-bench 的 Retail 与 Telecom 域第一。
- **通用模型对比**：WER-trained Qwen3-4B（76.63%）以 1.88 个百分点领先最强通用模型 GPT-5.5（74.75%），File System 与 Travel 域领先，Vehicle 域持平。
- **阶段与深度分析**：3 个训练阶段平均 Pass@1 单调上升（69.35%→71.29%→76.63%）；推理时修订深度呈边际递减，前两轮即捕获绝大部分增益，第三轮略降（76.63%→75.33%）。
- **定性分析**：连续修订逐步暴露并修正不同缺陷（如首轮修复文件创建缺失，次轮修复数值聚合逻辑），验证了“新失败模式逐轮显现”的自启动机制有效性。

## 相关工作脉络
- **推理时技能修订（EvoSkill、SkillOpt、SkillRevise、Execute-Distill-Verify）**：侧重于单次或多次迭代优化当前技能文本，但不更新底层的技能写作模型；WER 定位差异在于训练一个专用的 Skill Optimizer 策略，使修订能力可迁移至新任务。
- **技能增强的 Agent RL（SAGE、Skill1、SkillRL、ReSkill）**：通常联合更新任务代理与技能库，或将技能内部化至模型参数；WER 保持执行器冻结，仅训练外部文本修订策略，避免奖励黑客与执行器漂移。
- **学习式技能管理（SkillMaster、SkillOS、Skill-R1）**：分别在事后反事实探针、仓库级插入/删除操作、代内/代间组对比等信用 horizon 上学习技能决策；WER 的核心差异在于采用组内相对优化分配信用，并通过“成功/失败配对轨迹拼接”实现跨阶段经验构造。
- **提示/文本优化（OPRO、PromptAgent、DSPy、TextGrad）**：依赖搜索、任务反馈或文本梯度优化静态工件；WER 引入程序化验证器与 RL 信号，使优化过程直接接地于状态化工具环境的真实执行后果。

## 局限性与未来方向
- **评测环境局限**：仅在与 BFCL v4 和 τ²-bench 配套的确定性验证器上验证，尚未检验开放评估场景、未见工具接口或不同冻结执行器下的迁移效果。
- **上下文可扩展性未知**：当前严格保留完整轨迹导致状态规模随交互长度线性增长，未在更长 horizon 任务、多模态轨迹或大型技能仓库上评估，可能成为部署瓶颈。
- **未来方向**：扩展至更复杂的工具环境与多模态轨迹；研究在不损失诊断信号前提下的经验压缩与选择机制；探索将本工作习得的修订能力反向 bootstrapping 至通用大模型的通用推理管道。

## 研究启发与可借鉴点
- **执行器与优化器解耦范式**：冻结 executor、单独训练 text-only 优化器的设计天然隔离了动作空间与文本空间的耦合风险，可直接迁移至代码生成、SQL 编写、API 编排等“文本指导→程序执行”类代理系统。
- **混合结果保留与轨迹配对装配**：只保留“同技能同任务下既有成功又有失败”的记录，并原样拼接成功/失败 block，构成天然的局部对照实验，为 curriculum 构建与经验重放提供了强监督信号设计范式。
- **无 KL 锚定的组内相对 RL**：当目标行为（如修订风格）与基座初始化分布差异较大
