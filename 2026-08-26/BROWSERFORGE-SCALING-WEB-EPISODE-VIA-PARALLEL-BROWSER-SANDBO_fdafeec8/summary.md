# 论文速读：BROWSERFORGE-SCALING-WEB-EPISODE-VIA-PARALLEL-BROWSER-SANDBOX

## 一句话总结
本文提出 BrowserForge，一个通过在开放网络上并行运行数百个浏览器沙箱来规模化生成纯 GUI 网络交互轨迹数据的框架。该框架利用 Common Crawl 开源 URL 源突破现有数据集的网站覆盖瓶颈，经双代理合成（Proposer‑Solver）与规则+模型清洁流水线处理后，构建出包含 203,238 条轨迹、每条来自独立网站的语料库；在此基础上对紧凑多模�l 模型进行监督微调，使 Online‑Mind2Web 成功率从 25.66% 提升至 33.33%，并稳定改善静态 Multimodal‑Mind2Web 的步级准确率，证明数据规模与网站多样性是提升纯屏幕代理性能的关键。

## 研究问题与动机
- **核心问题**：训练纯截图感知的 Web 代理需要大规模、高多样性的交互轨迹，但现有公开数据集仅包含数千条轨迹且局限于数十至数百个固定网站；自动化合成管道虽能增加轨迹数量，却仍被限定在预定义网站列表或教程来源上，无法同步扩展网站多样性。
- **现有方法不足**：
  1. 文本感知路线（HTML/无障碍树）存在跨站点泛化脆弱、token 消耗高的问题。
  2. 屏幕感知路线虽能避免上述缺陷，但缺乏足够数量且覆盖真实开放网络的训练数据。
  3. 已有轨迹合成工作（如基于教程、种子列表或固定环境的管道）均受限于数据来源，代理实际看到的网站种类增长停滞。
  4. 如何以低成本、高吞吐的方式将开放网络中的真实页面转化为可执行的、带验证的交互轨迹，尚属开放问题。

## 核心贡献（创新点）
1. **提出 BrowserForge 框架**：通过开放网络 URL 源、并行浏览器沙箱集群管理器、Proposer‑Solver 双代理合成循环三部分协同，将数据规模与网站多样性解耦于固定网站列表，实现轨迹生成的可扩展性。
2. **设计 Proposer‑Solver 双代理合成回路**：Proposer 基于页面状态生成多个候选任务并经反思筛选出可执行任务；Solver 基于统一动作空间执行任务并记录轨迹，形成“无监督开放页面→可执行任务→带验证轨迹”的自动化转换。
3. **构建规则+模型清洁与统一思维链重写流水线**：先以规则过滤未正常终止或格式错误的轨迹，再用大模型判定任务是否真正完成，最后用 Seed‑2.0‑Pro 将留存轨迹的推理重写为一致性的 chain‑of‑thought 格式，显著提升训练数据质量。
4. **发布大规模开放网络轨迹语料库**：收集 203,238 条轨迹，每条来自独立网站，覆盖宽度远超已有数据集，并在 Online‑Mind2Web 与 Multimodal‑Mind2Web 上验证了其对紧凑模型的增益效果。
5. **提供系统的归因分析与消融实验**：通过固定模型与训练预算、仅替换数据源的控制实验，证明性能提升来源于开放网络数据源及其网站多样性，而非训练配方本身；缩放实验显示性能随语料大小单调增长，且清洁流水线的每个组件均贡献可观收益。

## 方法详解
BrowserForge 分为四个模块：

1. **开放网络 URL 源与清洁**
   - 从 Common Crawl 采样候选 URL，经四类过滤保留真正可交互的页面：
     - **可达性与类型过滤**：丢弃无法解析/加载的 URL，排除静态端点（如媒体文件下载）。
     - **内容过滤**：剔除过短或近空白的页面，保留含丰富交互信号的多媒体内容。
     - **黑名单过滤**：移除与评测基准重叠或已知敏感主机，避免数据污染。
     - **IP 级可访问性验证**：从沙箱集群自身 IP 重新验证 URL，确保集群机器实际可渲染。
   - 为扩充视觉与语言分布，沙箱配置不同分辨率、User Agent 与界面语言。
   - 每个保留的 URL 被渲染为（截图、URL、标题、无障碍树）元组，其中无障碍树仅在合成时用作信号，推理阶段完全不可见。

2. **并行浏览器沙箱编排**
   - 集群管理器维护四类状态：机器列表、共享 URL 工作队列、浏览器沙箱池（每个沙箱独立且通过 Chrome DevTools Protocol 寻址）、工作线程池。
   - 工作线程循环抢占空闲沙箱、从队列取 URL、驱动合成回圈并将结果写回存储，形成高吞吐的生产‑消费模式。
   - 共享队列保证慢速/卡顿页面仅占用自身线程，其余沙箱继续处理队列，避免全局阻塞；单节点可承载多浏览器配置，启动成本被分摊；运行时可动态扩容机器，队列自动重平衡。
   - 支持最高 300 个并行沙箱。

3. **Proposer‑Solver 任务合成**
   - **Proposer**：读取页面状态（无障碍树、截图、URL/标题），先用 Qwen3‑VL‑235B 生成三个基于可见元素的候选任务（提示词明确排除需注册、登录或支付的任务），再让模型反思并选出最可执行的一个任务。多候选生成与筛选机制过滤掉模糊或不可能完成的任务，提高可用轨迹产出率。
   - **Solver**：基于开源浏览器控制代理（browser‑use），以多模态模型为驱动，通过“规划‑执行‑反思‑验证”闭环收集轨迹，维护历史步骤记忆。每步观察当前截图与结构化交互元素集合，输出上一步评估、更新记忆、下一步目标及一个或多个落地动作（点击、输入、滚动等）。
   - **统一动作空间**（表 1）：包含 click、type、select、scroll、key、wait、go_back、visit_url、finish 九类动作，屏幕坐标归一化为 [0, 1000] 整数，跨分辨率统一。
   - 每次运行存储为结构化轨迹（运行记忆 + 每步 JSON 观测/思维/动作），原始共收集 203,238 条轨迹，平均每轨迹 8.8 步，合计约 180 万交互步。

4. **轨迹清洁与统一推理格式**
   - **基于规则的过滤**：丢弃未以 Finish 动作正常终止或动作序列格式错误的轨迹。
   - **基于模型的评判**：用 Qwen3‑VL‑235B 结合任务描述与轨迹最后三张截图判定任务是否真正完成，拒绝不合格轨迹。两步联合过滤后仅保留约 30% 的原始交互步（约 60 万已验证步）。
   - **统一思维链重写**：从已验证步中采样 20 万步，用 Seed‑2.0‑Pro 将 Solver 原始冗长且风格各异的推理重写为一致的 chain‑of‑thought 格式，构成最终训练语料。

## 实验与结果
- **数据集**：BrowserForge 语料库，203,238 条轨迹（每条来自独立网站），最终用于训练的 20 万步统一 CoT 数据。
- **评估基准**：
  - **Online‑Mind2Web**：300 道真实网站端到端任务，以 WebJudge‑7B 自动裁判评分成功率（SR）。
  - **Multimodal‑Mind2Web**：静态固定轨迹协议下的步级准确率，含 Cross‑Task、Cross‑Website、Cross‑Domain 三分支。
- **基线**：专有 GUI 代理（Browser‑Use、GPT‑5+UGround 等，仅作上限参考）；开源多模态基础模型（Qwen3‑VL 系列零样本）；现有开源 Web/GUI 代理方法（ScaleCUA、GUI‑Libra、WebStar 等）。
- **主要结果**：
  - **Online‑Mind2Web 成功率**：BrowserForge‑4B 从基线 25.66% 提升至 **33.33%（+7.67）**；BrowserForge‑9B 从 29.33% 提升至 **38.00%（+9.33）**。9B 模型超越 GUI‑Libra‑8B（36.7%，采用 RL 训练）、GPT‑5+UGround（33.3%）及 Browser‑Use（30.0%）。
  - **Multimodal‑Mind2Web 步级准确率**：BrowserForge‑4B 平均 Pass@1 达 **43.8%**（基线 38.2%），Pass@4 达 **54.4%**（基线 44.1%）；9B 模型平均 Pass@1 达 **45.1%**，Pass@4 达 **56.3%**，在所有分支上均一致提升。
  - **数据源对照实验**：在固定 Qwen3.5‑4B 与 3 epoch 预算下，用同等规模 20 万条开源轨迹训练的平均步准确率仅为 32.74%（Pass@1）与 43.48%（Pass@4），而 BrowserForge 数据分别达到 **41.33%** 与 **52.59%**，印证提升来自开放网络数据源及其多样性。
  - **缩放趋势**：以相同骨干在 10³、5×10⁴、10⁵、2×10⁵ 子集上微调，性能随语料规模单调上升，曲线呈近似幂律且未在 20 万步处饱和。
- **最强结果**：BrowserForge‑9B 在 Online‑Mind2Web 上达到 38.00% 成功率，较基线提升 9.33 个百分点，超过多数规模更大的开源代理与多个专有参考。

## 局限性与未来方向
- **依赖大模型进行任务生成与清洁**：Proposer 与模型评判均使用 Qwen3‑VL‑235B，成本较高且可能引入模型偏好偏差；未来可探索更轻量或蒸馏化的生成/评判模块。
- **清洁后保留比例有限**：原始轨迹仅约 30% 的步通过双重过滤，仍有较大噪声未被剔除或可能误删有效轨迹；可研究自适应阈值或增量清洁策略。
- **评估基准相对有限**：仅在 Online‑Multimodal‑Mind2Web 上充分验证，未覆盖更多动态真实网站或长尾任务；未来需在更广阔的在线环境中检验泛化性。
- **任务类型受限**：Proposer 提示词排除了需登录、注册或支付的任务，限制了数据在账户敏感型场景的覆盖；后续可结合匿名化测试账户或沙箱化账号体系扩展任务谱系。
- **未与强化学习配方结合**：本文仅使用监督微调，而 GUI‑Libra 等方法采用 RL；未来可探索数据质量与奖励信号结合的混合训练。
- **集群资源需求较高**：支撑 300 个并行沙箱需要可观的机器与 CDP 调度开销，限制了在小规模团队中的直接复现；可研究更轻量的异步或分批调度变体。

## 研究启发与可借鉴点
1. **开放网络作为数据源的战略价值**：将 Common Crawl 等开源快照作为候选 URL 池，而非固定种子列表，可从根本上突破网站多样性瓶颈；该思路可迁移至移动 UI、VR/AR 界面等其他交互模态的数据采集。
2. **Proposer‑Solver 双代理回路设计**：先生成多候选再反思筛选，能有效降低无效执行比例；类似“ proposal‑reflection‑selection”范式可复用于其他需要从无标注环境中生成可执行指令的场景（如机器人操作、文档处理）。
3. **统一思维链重写在异构轨迹清洗中的作用**：在保留正确执行结果的前提下，用统一格式重写推理过程能显著提升训练信号一致性；该方法可与数据去重、难度分级结合，形成更完整的合成数据后处理流水线。
4. **控制变量归因实验设计**：固定骨干模型与训练预算，仅替换数据源来隔离数据效应，能有力证明数据质量的价值；这种实验范式应成为数据驱动研究的标准评估环节。
5. **沙箱集群的高利用率编排模式**：共享工作队列 + 线程池抢占 + 动态扩缩容的设计，可在异构任务时长分布下维持高吞吐；该架构可推广至任何其他需要大规模并行仿真/渲染的任务（如视频生成、游戏代理训练）。

## 关键术语表
- **BrowserForge**：通过并行浏览器沙箱在开放网络上规模化生成纯 GUI Web 交互轨迹的数据合成框架。
- **Proposer‑Solver**：双代理合成回路，Proposer 负责从页面生成可执行任务，Solver 负责执行任务并记录验证后的交互轨迹。
- **Online‑Mind2Web**：基于真实在线网站的端到端任务成功率评测基准，采用自动裁判进行打分。
- **Multimodal‑Mind2Web**：在静态固定轨迹协议下评估步级准确率的基准，涵盖跨任务、跨网站、跨域三个分支。
- **Common Crawl**：大规模定期刷新的公开网络快照数据集，提供海量真实网站 URL 供采样。
- **Accessibility (a11y) tree**：网页无障碍树，表征页面结构化的交互元素层级；本文仅在合成阶段用作信号，推理时不使用。
- **Chain‑of‑thought (CoT) 统一重写**：将轨迹中风格各异的推理文本改写为一致的结构化思维链格式，以提升训练监督的一致性。
- **归一化坐标 [0, 1000]**：将屏幕位置映射到固定整数区间的动作表示方式，使同一动作规范跨不同渲染分辨率通用。
