# 论文速读：SAGE: From Direct Answering to Evidence-Grounded Inference for Chinese Ancient Document Understanding

## 一句话总结
SAGE提出了一种基于证据的多智能体推理框架，将中文古籍理解从"直接单步生成"重构为"证据获取-声明验证-受限重规划"的可诊断过程，在AncientDoc基准上配合Qwen3.5-9B在8项指标中7项达SOTA，超越了大量参数规模大得多的单体LVLM。

## 研究问题与动机
1. 现有LVLM在中文古籍理解中采用不透明的单步直接生成范式，阅读、证据获取、推理与验证被压缩为一个黑盒步骤，导致回答过度自信且缺乏证据支撑、错误难诊断。
2. 中文古籍具有竖排版式、繁异体字、无标点、密集注释、古典语义高度隐晦等独特复杂度，远超现代文档理解任务，需要多阶段视觉-语言-历史知识融合推理。
3. 真实学术实践中，专家通过系统阅读、识别视觉线索、查阅参考、验证声明并在证据不足时主动弃答，现有系统缺乏这种有界证据搜索与不确定性表达能力。
4. 单纯依靠扩大模型参数规模并不能有效提升古籍理解可靠性，需要转向结构化、可验证的推理过程设计。

## 核心贡献（创新点）
1. 将中文古籍理解重新定义为证据支撑推理问题而非直接回答任务，系统需同时输出最终答案A、收集证据E、证据报告R、弃答标志z和执行轨迹τ。
2. 提出SAGE多智能体框架，通过角色专业化的三个智能体（规划、执行、验证）在受限共享状态运行时下协同完成任务感知规划、工具中介证据获取、声明级验证与受限重规划。
3. 设计了声明级验证机制：将候选答案分解为原子声明并逐一评估{SUP, CON, INS, N/A}四种支持关系，聚合为证据报告以驱动运行时决策。
4. 实验证明结构化证据推理的收益超过模型缩放：Qwen3.5-9B + SAGE在AncientDoc上7/8指标超越GPT-4o、Gemini 2.5-Pro、Qwen2.5-VL-72B等大规模闭源/开源模型。

## 方法详解
1. **Scholarly Planning Agent**：接收查询Q和初始预算b_0，预测任务类型y（OCR/翻译/推理QA/知识QA/语言QA），生成结构化计划P_0 = (y, a_0, ρ_0, b_0)，其中a_0为动作序列、ρ_0为证据需求与验证标准；重规划时基于当前证据状态和剩余预算自适应更新计划。
2. **Evidence-Grounded Execution Agent**：在约束动作空间{read, normalize, extract, retrieve, synthesize}中执行计划，形式化为(X_k, E_k) = Exec(I, Q, P_k, s_k)，其中X_k为页面文本、E_k为累积证据（知识QA额外包含检索证据）；生成候选答案Â_k = Solve(Q, X_k, E_k, P_k)，视为待验证假设而非最终输出。
3. **Scholar Verifier Agent**：将候选答案分解为原子声明C_k = {c_1, …, c_n}，逐一评估v_i = Verify(c_i, Q, X_k, E_k) ∈ {SUP, CON, INS, N/A}，聚合为证据报告R_k = Aggregate(C_k, V_k, X_k, E_k)，包含支持覆盖率、不支持/矛盾声明比例、置信度及弃答建议。
4. **Constrained Shared-State Runtime**：维护状态s_k = (y, P_k, X_k, E_k, Â_k, R_k, b_k, τ_k)，应用控制规则d_k = Rule(s_k) ∈ {STOP, REPLAN, ABSTAIN}；当证据充足时停止、证据不足且预算允许时重规划、证据始终不足或预算耗尽时弃答。
5. **工具接口**：Page Reader（基于Qwen-VL-OCR，按从右到左、从上到下读取竖排文本）、Char Normalizer（OpenCC繁简转换与异体字归一化）、Term Extractor（规则式术语抽取）、Local Evidence Retriever（冻结本地知识库，最多检索8条片段，使用精确匹配/子串/年份等价/字符重叠等透明规则）。
6. **预算约束**：各任务最大工具调用次数为OCR:3、翻译:5、推理QA:5、知识QA:7、语言QA:6，所有轨迹完整记录。

## 实验与结果
1. **数据集与指标**：AncientDoc基准，主实验评估翻译、推理QA、知识QA、语言QA四个理解任务，使用CHRF++和BERTScore F1（BS-F1）；OCR任务因主要依赖外部页读工具质量而被排除。
2. **主干模型**：InternVL3-8B、Qwen2.5-VL-7B、Qwen3.5-9B，每个 backbone 均与匹配的直接回答基线对比。
3. **主要结果**：SAGE在三个骨干模型、全部八项指标上均稳定超越匹配基线；Qwen3.5-9B + SAGE在翻译（CHRF++: 16.01 vs 7.71, +8.30；BS-F1: 75.29 vs 68.03, +7.26）、知识QA（CHRF++: 11.81 vs 6.80, +5.01；BS-F1: 71.12 vs 66.83, +4.29）、语言QA（CHRF++: 7.72 vs 1.83, +5.89；BS-F1: 65.35 vs 55.63, +9.72）上提升显著；在8项指标中7项达SOTA，唯一例外是推理QA BS-F1略低于Qwen2.5-VL-72B Direct。
4. **消融实验**（Qwen3.5-9B）：移除规划器导致推理QA BS-F1从69.10降至67.06、知识QA从71.12降至67.80；移除验证器导致推理QA BS-F1从69.10降至68.98、知识QA从71.12降至70.08；移除本地检索对知识QA影响较小（71.12→70.89），表明主要增益来自页面证据组织和验证而非外部知识。
5. **轨迹分析**：知识QA在90.39%样本中调用抽取与检索，推理QA仅9.42%；重规划后支持率从69.23%提升至74.45%，验证器置信度从67.99%提升至71.59%。

## 相关工作脉络
1. 与AncientDoc基准（Yu et al., 2025）的关系：AncientDoc定义了中文古籍理解的评测体系，但采用直接回答范式评估最终输出；本文聚焦推理过程本身——系统如何获取证据、验证声明、在证据不足时弃答并提供轨迹诊断。
2. 与WenyanGPT、TongGu等古代中文模型的关系：这些工作聚焦领域预训练与指令微调，属于模型中心方法；SAGE是模型无关的推理时框架，不训练新模型，而是通过多智能体协调提升任意LVLM的后处理能力。
3. 与DocVQA、TextVQA、OCRBench、MMLongBench-Doc等现代文档理解基准的关系：这些基准主要面向现代文档和场景文本；本文针对古籍特有的竖排、繁异体字、无标点、密集注释等挑战，提出适配的证据获取工具链。
4. 与AC-EVAL、C³ Bench、Fùxì、WenyanBENCH等古文理解文本基准的关系：这些是纯文本基准；本文处理多模态古籍图像理解，需同时完成视觉阅读、文字归一化与语义推理。
5. 与HisDoc1B、BABM-LLM等历史文档资源的关系：这些提供数据或领域模型；本文提供系统级推理框架，可与这些资源互补使用。
6. 与主流LVLMs（GPT-4o、Gemini 2.5-Pro、Qwen2.5-VL-72B、InternVL3-78B等）的关系：本文证明在相同输入条件下，结构化证据推理+验证的增益可超越单纯扩大模型参数规模，重新定位了古籍理解的瓶颈从"模型能力"转向"推理可靠性"。

## 局限性与未来方向
1. 当前评估仅限于AncientDoc基准的任务类型和数据分布，尚未在更广泛的历史文献集合、不同文档版式及其他古老语言上验证泛化性。
2. 验证器和轨迹支持统计均为系统生成的诊断信号，缺乏人工事实性标注，应解释为运行时行为指标而非答案正确性的决定性证明。
3. SAGE引入了额外的推理成本（规划、工具调用、验证与可能的重规划），在低延迟场景中可能受限。
4. 未来方向包括探索更强的证据来源（如跨文档检索）、人工 grounded 验证机制、以及更高效的执行策略以降低推理开销。

## 研究启发与可借鉴点
1. **证据支撑推理范式可迁移至其他高可信度专业领域**：法律文档分析、医学文献理解、金融报告解读等场景同样需要"获取证据→验证声明→必要时弃答"的结构化过程，而非直接生成，SAGE的流程设计可直接迁移。
2. **受限共享状态运行时架构值得复用**：通过统一状态管理、约束工具接口、预算控制和完整轨迹记录实现可诊断的多阶段推理，这一架构模式可应用于其他Agent系统，避免无界工具调用和不可控生成。
3. **声明级验证（claim-level verification）替代整体答案评估**：将答案分解为原子声明并逐一评估支持度，比整体打分更细粒度、更可诊断，可迁移至任何需要可解释性和事实一致性的生成任务。
4. **任务感知规划与预算感知重规划机制**：根据任务类型自适应选择证据路径（知识QA走检索、翻译/语言QA走页面），避免固定流水线；这一设计原则适用于多类型任务系统，可提升工具调用的精准度。
5. **冻结本地证据池的实验设计原则**：预构建并冻结外部知识源以防止评估时数据污染，确保实验差异仅反映框架效果；这一原则可用于其他RAG系统的基准测试，保障可比性。

## 关键术语表
**Evidence-Grounded Inference**：证据支撑推理，指系统在生成回答前系统性地获取并验证支持证据，而非直接单步生成的推理范式。
**Scholarly Planning Agent**：学术规划智能体，负责分析用户查询、预测任务类型并生成预算感知的证据获取策略计划。
**Claim-Level Verification**：声明级验证，将候选答案分解为原子声明并逐一评估其与可用证据的支持/矛盾/不足关系。
**Constrained Shared-State Runtime**：受限共享状态运行时，维护统一证据状态、约束工具接口、预算控制和执行轨迹记录的系统级基础设施，协调规划-执行-验证循环。
**AncientDoc**：中文古籍理解的视觉-语言模型基准，涵盖OCR、翻译、推理QA、知识QA和语言QA五个任务类型。
**Bounded Replanning**：受限重规划，当验证器判定当前答案证据不足时，在剩余预算内触发新一轮证据搜索与答案生成。
**Local Evidence Pool**：本地证据池，预构建的冻结离线知识库，通过透明匹配规则为知识密集型问题提供检索增强证据。
**Abstention**：弃答，当证据始终不足、输出未通过验证或预算耗尽时，系统主动拒绝给出答案的运行决策。
