# 论文速读：Evaluating-Language-Models-on-Cross-Language-Code-Functional-Equivalence

## 一句话总结
本文提出了 PolyHuman 数据集（涵盖 CPP、Java、Python 三种语言的人工编写程序），首次系统评估了 LLM 在跨语言代码功能等价性判断上的能力，揭示了现有基准测试高估模型语义理解的问题，并分析了模型失败的根本原因。

## 研究问题与动机
- 现有功能等价性基准测试主要聚焦单一语言或依赖合成变换代码，可能通过表层相似性线索（如词法相似度、变量重命名）被"破解"，无法真实反映 LLM 的语义推理能力。
- 跨语言等价判断（如代码迁移、翻译后验证）要求模型超越语法差异理解深层语义，但尚无研究系统评估 LLM 在此场景下的能力。
- 人工编写的程序比合成变换的程序具有更高的结构和表达多样性，需要更深入的行为推理，但现有工作未充分考察此类真实场景。
- 不同 LLM 可能存在系统性的预测偏差（如过度接受或过度拒绝等价性），且模型决策是否依赖相似性线索尚不清楚。

## 核心贡献（创新点）
- 提出 PolyHuman 数据集：首个基于竞争性编程平台的人工编写多语言程序配对数据集，涵盖 CPP、Java、Python，包含 5,035 道题目和 15 个子任务（5,000 对代码），区分等价的 Pass-Pass 和非等价的 Pass-Fail 配对。
- 首次系统性评估跨语言功能等价性判断：覆盖 9 个 LLM（开源与闭源），统一 Prompt 和评估协议，揭示不同模型在跨语言场景下的系统性预测偏差。
- 提供细粒度失败分类体系：通过人工分析 81 个系统 disagreed 案例，建立知识失败与抽象层次推理失败（预语义/语义级/实现级）的分类学，揭示模型推理瓶颈。
- 建立多因素量化分析框架：使用逻辑回归揭示难度、代码长度、相似性信号（Lexsim、CodeBLEU、CodeBERT 等嵌入）对模型决策的独立影响，证明相似度仅起次要作用。
- 提出可操作的改进建议：针对研究者（需更真实的基准）、Agent 系统设计者（互补模型集成）和编程实践者（复杂控制流场景需人工审核）给出具体指导。

## 方法详解
- **数据集构建**：从 CodeContests（13,610 道编程题）中筛选 CPP、Java、Python 语言的解决方案，每道题随机采样 2 个正确（Pass）方案和 1 个错误（Fail）方案，构建同语言和跨语言的等价/非等价配对。功能等价的定义为通过所有在线评测用例。
- **评估模型**：9 个 LLM，包括 GPT-o4-mini、GPT-OSS-20B、Llama-3.1-8B、Llama-3.2-3B、Mistral-7B、Qwen2.5-Coder-7B/14B、CodeLlama-7B/13B。使用确定性解码（temperature=0）。
- **Prompt 设计**：零样本提示，明确要求模型推理程序行为而非依赖表层相似性，输出限制为二元判断（Yes/No）。
- **特征提取**：提取问题难度（A-G 级）、代码长度（LOC）、相似度信号（Lexsim、CodeBLEU、CodeBERT、GraphCodeBERT、UniXcoder、BGE-Code 嵌入距离）。
- **统计分析**：Spearman 相关系数评估相似性信号与预测结果的关系；二项逻辑回归建模各因素对 Yes 预测的独立贡献；Wilcoxon 符号秩检验和 Friedman 检验评估语言效应。
- **错误分析**：对 900 个实例进行三次独立评估（多数投票），识别 162 个不稳定案例和 81 个系统性错误案例；引入 Chain-of-Thought (CoT) 提示获取推理过程；手工分类失败模式为三类：知识失败（17例）、抽象层次推理失败（38例）、标签错误（17例）。

## 实验与结果
- **基线数据集**：EquiBench（OJ-A：200 等价 + 200 非等价，平均 LOC 82；OJ-V：200+200，平均 LOC 70）、SeqCoBench（采样 500 对，平均 LOC 7.79）。
- **GPT-o4-mini 表现**：
  - 合成数据集表现优异：SeqCoBench 准确率 0.97，OJ-V 准确率 0.91。
  - 人类编写代码大幅下降：OJ-A 准确率 0.82，PolyHuman Python 子集 0.80（Pass-Pass）vs 0.93（Pass-Fail），显示系统性偏差。
- **跨语言性能**（Table 4）：
  - GPT-o4-mini 跨语言等价判断准确率：CPP↔Java 0.85，Java↔Python 0.82，Python↔CPP 0.81。
  - 非等价判断：Java(F)↔CPP 0.93，Java(F)↔Python 0.90 等。
- **决策偏差分析**（Table 5）：
  - GPT-o4-mini：对三种语言均呈现正 Gap（偏向拒绝等价），Gap 值：CPP 0.072，Java 0.075，Python 0.088。
  - Mistral-7B 等极端偏向等价（负 Gap 约 -0.99）。
  - Qwen2.5-Coder-14B 最平衡（CPP Gap=0.013，Java Gap=0.005）。
- **影响因素**（Table 6）：
  - 难度显著影响预测：EQ 对中难度越高 Yes 率越低（β=-0.350）；NEQ 对中难度越高 Yes 率越高（交互项 β=0.804，OR=2.234）。
  - CodeBLEU 显著增加 Yes 概率（β=0.212，OR=1.236），表明残留相似性偏差。
  - Python 代码偏向保守（β=-0.450，OR=0.637）。
- **失败分析**（RQ4）：
  - 81 个系统错误中 55 个为真实模型失败（38 抽象层次推理失败 + 17 知识失败），17 个为数据标签问题。
  - 抽象层次失败细分：实现级细节错误最多（21 例，29.2%），其次是预语义过早结论（11 例）和语义级误解（6 例）。
  - Claude-Opus-4.7 在抽象推理上更强（单独解决 17 例），Gemini-3-Flash 在知识相关案例上更强（单独解决 12 例）。
  - 9 个 GPT-o4-mini 错误可通过 CoT 提示纠正。

## 相关工作脉络
- **EquiBench** [46]：评估 LLM 功能等价性判断的基准，但 OJ-V 子集通过变量重命名变换构造非等价对，易被相似性捷径解决；本文首次在跨语言和人工编写代码上挑战此任务。
- **SeqCoBench** [21]：基于 Python 的 20 种语义保持/破坏变换数据集，但代码规模小（平均 LOC 7.79）且为单语言；本文 PolyHuman 覆盖多语言和真实人类实现多样性。
- **跨语言代码克隆检测** [24, 28]：关注代码相似性而非严格功能等价，且多基于合成数据；本文聚焦严格功能等价判断，要求更深语义推理。
- **代码翻译错误研究** [27]：发现 LLM 在跨语言翻译中引入 bug，但未系统评估等价判断能力；本文填补此空白。
- **代码理解 LLM 评估** [16, 19]：关注生成、摘要、bug 修复等任务，功能等价作为底层能力未被深入检验；本文揭示其语义推理的局限性。
- **模型集成策略** [51]：本文发现的模型互补性（如 Claude 擅长抽象推理、Gemini 擅长知识验证）为多 Agent 系统设计提供实证依据。

## 局限性与未来方向
- **内部效度威胁**：Online Judge 测试套件可能无法覆盖所有边缘情况，导致标签错误（本文发现 17/900 例，约 1.9%）。
- **外部效度威胁**：PolyHuman 来自竞技编程平台，代码算法密集且注重性能，可能不能完全推广到真实工程代码场景。
- **模型选择限制**：主要评估 3B-20B 开源模型加 GPT-o4-mini，未覆盖所有最新闭源模型。
- **数据污染**：CodeContests 是公开数据集，可能已出现在模型训练数据中，导致性能高估（保守估计）。
- **未来方向**：开发更多样化的真实世界程序基准；减少模型对表层相似性的依赖；提升推理跨语言一致性和运行稳定性；探索互补模型集成和多 Agent 策略。

## 研究启发与可借鉴点
- **数据集构建方法**：从竞技编程平台（CodeContests）利用正确的 Pass/Fail 标签自然构建等价/非等价配对，避免合成变换的人为痕迹，可作为其他语义任务的数据构建参考。
- **系统性偏差度量**：引入 AccNonEq - AccEq 决策 Gap 概念量化模型预测倾向，比单一准确率更能揭示模型行为特征，值得在其他二元分类任务中推广。
- **多维度失败分类体系**：将失败分为知识失败与抽象层次推理失败（预语义/语义/实现级），为 LLM 代码理解能力的机制分析提供可复用的分析框架。
- **CoT 辅助错误修正**：发现部分错误可通过 Chain-of-Thought 提示纠正（9/81 例），提示推理链显式化可缓解部分推理缺陷，可在后续研究中进一步探索结构化推理路径设计。
- **互补模型集成启发**：不同模型在不同失败类型上表现互补（Claude 强于抽象推理、Gemini 强于知识验证），为多 Agent 系统的角色分工和验证流程设计提供实证依据。

## 关键术语表
- **功能等价性**：两个程序在所有有效输入下产生相同输出的性质，是代码理解的核心语义能力。
- **PolyHuman**：本文提出的基准数据集，包含 5,035 道竞技编程题的 CPP/Java/Python 人工编写配对代码。
- **决策 Gap**：非等价对准确率减去等价对准确率的差值，正值表示过度拒绝等价，负值表示过度接受等价。
- **链式思维（Chain-of-Thought, CoT）**：要求模型逐步推理再给出最终判断的提示策略，用于揭示模型的推理过程。
- **CodeBLEU**：基于词法、语法和语义相似度的代码相似度评价指标，本文用于量化模型对结构性相似性的依赖。
- **抽象层次推理失败**：模型在预语义（过早结论）、语义级（误解关键行为）或实现级（细节追踪错误）推理过程中出现的失败。

- **数据集**：PolyHuman 基于 CodeContests 构建，数据公开链接为 https://doi.org/10.5281/zenodo.21800077。
