# 论文速读：TOWARDS-EXPERT-FINANCIAL-QA-VIA-SELF-IMPROVING-RAG

## 一句话总结
本文提出 Self-Improving RAG，一种面向专家级金融问答的多智能体协同框架，通过检索、推理与裁判三_agent_配合及反馈驱动的自动重试机制，解决单轮 RAG 在金融场景下缺乏自我纠错与审计追溯能力的问题；在 FinanceBench 上达到 86% 的 Oracle-Guided 准确率，并实现 36.4% 的 Lazarus Rate（重试恢复率）。

## 研究问题与动机
1. **单轮 RAG 无法识别与修正自身失败**：传统检索增强生成系统仅执行一次检索-生成流程，在高 stakes 领域（如金融）返回错误答案的危害远大于不提供答案，且缺乏纠错机制。
2. **金融“封闭花园”约束（Walled Garden）**：合规要求检索必须严格限定在授权文档库内，禁止像通用系统那样在检索失败时回退到网络搜索，迫使系统必须设计库内自修复策略。
3. **金融问答的三重特殊挑战**：表格与财报中的数值推理、基于财年/报告期的时间过滤、股票代码/子公司/更名实体的消歧。
4. **现有自适应检索方法缺乏重试恢复能力**：Adaptive-RAG 等侧重于初始路由，CRAG 依赖外部搜索，均无法满足金融场景对闭域合规与可解释审计的刚性需求。

## 核心贡献（创新点）
1. **多智能体结构化自我修正框架**：将 RAG 解耦为 Retrieval、Reasoning、Judge 三个专用 agent，由 Orchestrator 根据 Judge 反馈触发策略升级重试，区别于 Self-Refine 等单模型自我批评范式，实现跨检索、生成、评估三阶段的定向诊断与恢复。
2. **强落地约束的裁判验证机制**：Judge Agent 输出 grounding、completeness、numeric faithfulness 三维质量向量，并对数值 Faithfulness 赋予高权重（0.5），采用严格集合覆盖逻辑判定数值是否被证据显式支持，区别于通用 LLM Judge 的模糊评分。
3. **审计优先（Audit-First）设计**：所有 agent 决策均记录时间戳、溯源证据、置信度与推理轨迹，满足金融监管对事后审查与合规留痕的要求，区别于多数追求极致延迟而不提供可解释链路的 RAG 系统。

## 方法详解
- **系统状态与循环**：第 $t$ 次尝试的状态表示为 $\mathcal{S}_t = \langle E_t, a_t, \mathbf{s}_t, \tau_t \rangle$，系统最多执行 $B+1$ 次尝试，保留历史最高分答案 $a^*$ 作为最终输出，保证单调不降。
- **Retrieval Agent（检索）**：采用混合管道（dense BGE-large + BM25 + cross-encoder rerank）。重试时检索数量逐级扩展：第 1 轮 top-k=10，第 2 轮=20，第 3 轮=30 并开启 Relevant Segment Extraction（RSE）合并相邻高分文本块。基于 S&P 500 股票代码词表与正则规则进行启发式路由，避免引入重型分类器。
- **Reasoning Agent（推理）**：生成带显式引用的答案，提示策略随重试次数升级：STANDARD → CONSERVATIVE（鼓励弱证据下承认不确定性） → DETAILED（要求逐步推理与严格溯源）。
- **Judge Agent（裁判）**：评分函数 $\mathbf{s}_t = [\mu_g, \mu_c, \mu_n]^\top$，聚合为 $U_t = 0.3\mu_g + 0.2\mu_c + 0.5\mu_n$。数值忠实度 $\mu_n$ 采用程序化提取与严格集合覆盖：答案中所有归一化数值必须能在检索证据中找到对应项，防止近_miss_幻觉。
- **Orchestrator（编排）**：采用动态阈值衰减 $\tau_t = \max(\tau_0 - 0.1(t-1), 0.3)$，首轮要求高置信（0.5），后续允许适度放宽以体现“已付出额外检索/推理努力”的容忍度。若阈值永不达标则返回历史最优答案，所有决策全程日志化。
- **收敛性**：形式化证明表明多轮尝试的系统失败概率随轮数呈乘积衰减，满足 $\mathcal{P}_{fail} = \prod_{t=1}^T P(\mathbb{D}_t=0 \mid \mathcal{S}_{t-1})$。

## 实验与结果
- **数据集与设置**：FinanceBench（150 道 SEC 10-K/10-Q 问答，66% 需数值计算）；生成模型 GPT-4o-mini，检索 BGE-large-en-v1.5 + ChromaDB + BGE-reranker-large；重试预算 $B=2$，$\tau_0=0.5$。
- **主要结果（Oracle-Guided）**：Single-pass RAG 准确率 53% → Self-Improving RAG 达 86%，绝对提升 +62.3%（95% bootstrap CI [80, 91]）。
- **按题型拆解**：Domain-relevant 题型提升最大（+81.1%，达 96%），Metrics-generated 提升 +54.7%，Novel-generated 提升 +50.9%。
- **Lazarus Rate**：盲评模式下 22% 的问题被 Judge 触发重试（33/150），其中 36.4%（12 题）成功纠正，验证了自我修正的实际恢复能力。
- **部署模式对比**：盲 Judge 模式下最终接受率为 31%，暴露出无金标辅助时质量估计的难度；Oracle 模式与 Deploy 模式的差距提示裁判模型强度是进一步提升的关键瓶颈。
- **消融实验**：移除 Prompt Escalation 导致准确率下降 -10.6%（贡献最大）；预算降至 $B=1$ 下降 -25.5%；移除确定性数值校验意外提升 +2.1%，作者归因于格式/舍入过于敏感引发不必要的二次错误，建议后续引入单位感知归一化。
- **核心发现**：固定混合检索管道配合 Judge 驱动的重试即可取得强结果，无需复杂的动态路由，兼顾性能与完全可解释性。

## 相关工作脉络
1. **Self-RAG (Asai et al., 2023)**：训练反射 token 实现自检；本文无需任何微调，直接在推理时通过多 agent 交互完成修正，更利于冷启动与跨域迁移。
2. **CRAG (Yan et al., 2024)**：失败时回退至网络搜索进行更正；本文受金融“封闭花园”合规约束，彻底禁用外部搜索，完全依赖库内证据升级重试。
3. **Adaptive-RAG (Jeong et al., 2024)**：按问题复杂度学习初始路由；本文聚焦路由之后的“失败补救”，证明在强裁判+重试机制下，简单固定管道可替代复杂 learned router。
4. **Reflexion (Shinn et al., 2023)**：跨 episode 的言语强化学习自我修正；本文在单次会话内完成多轮修正，延迟可控且无需奖励建模与长期训练。
5. **Self-Refine (Madaan et al., 2023)**：单模型自我批判-精炼循环；本文拆分为专用检索/推理/裁判 agent，引入领域专属的数值程序化验证与审计日志，更适合高合规要求场景。

## 局限性与未来方向
- **盲评裁判可靠性瓶颈**：部署模式下仅 31% 接受率，说明当前 Judge 在无金标时仍易误判或过度保守。
- **延迟代价**：触发重试时端到端延迟约 15–25 秒（单轮 5–8 秒），不适合实时交互，更适合作为分析师辅助工具。
- **数值精确匹配未改善**：自我修正主要恢复语义完整性，对提取误差、算术错误或单位混淆的修复有限。
- **评测规模受限**：FinanceBench 仅 150 题，消融差异（如 -10.6% / +2.1%）置信区间较宽，统计显著性需更大集验证。
- **未来方向**：用强化学习替代启发式阈值衰减；引入单位感知归一化修复确定性校验异常；拓展至法律、医疗等同样需审计的高 stakes 领域；在 agent 边界引入人类介入点。

## 研究启发与可借鉴点
1. **动态阈值衰减 + 历史最优保留**的设计可无缝迁移至其他高 stakes RAG 场景，既保证安全性又提供明确的“努力-容忍”权衡接口。
2. **Lazarus Rate** 作为独立指标量化“纠错恢复率”，比单纯报告最终准确率更能揭示系统的韧性与 retry 机制的真实价值，值得在后续工作 adopt。
3. **轻量金融词表 + 规则路由** 证明了在强垂直领域约束下，手工构建的领域先验往往比端到端 learned router 更稳定、更可解释，可复用于法律条款问答或医疗指南检索。
4. **“固定管道 + 裁判重试”可替代动态路由** 的发现对工程实践极具指导意义：与其追求复杂的意图分类，不如投资更强的 Judge 与更稳健的重试策略，大幅降低系统维护成本。
5. **审计追踪设计模板**（时间戳、溯源链、置信度、决策分支）可直接复用至团队其他需满足合规审查的 Agent 产品中。

## 关键术语表
- **Self-Improving RAG**：通过检索、推理、裁判三 agent 协同并在低分触发时执行策略升级重试的反馈驱动框架。
- **Lazarus Rate**：首次尝试被判错误的问题中，经重试成功纠正的比例，衡量系统的自我修复能力。
- **Walled Garden Constraint**：金融合规强制要求检索仅能在授权文档库内进行，禁止外部信息源回退的约束条件。
- **Relevant Segment Extraction (RSE)**：将同一文档内相邻的高分 chunk 合并为连贯段落，避免碎片化上下文损害推理完整性。
- **Finance Lexicon**：包含实体别名、财务指标同义词及单位/周期归一化规则的轻量词表，用于查询预处理与数值比对。
- **Oracle-Guided vs Deployment Mode**：前者 Judge 可访问金标答案评估，后者 Judge 盲评；二者差距反映真实部署中质量估计的挑战。
