# 论文速读：JUDGESTEALER-Extracting-LLM-Judging-Capabilities-across-Eval

## 一句话总结
本文提出 **JUDGESTEALER**，首个针对黑盒 LLM 评判能力的查询高效提取框架，利用点评分、成对比较和列表排序三种评估协议之间的强交叉一致性，仅通过少量点评分查询即可高效复制 LLM 的评判能力。

## 研究问题与动机
- **核心问题**：LLM 作为评估器（LLM-as-a-Judge）和奖励模型（Reward Model）已成为重要知识产权，但其开放的 API 接口易遭受模型提取攻击，导致能力被非法复制。
- **现有方法不足**：
    1. 现有提取攻击主要针对传统 DNN 或 LLM 的特定功能（如代码生成），**未专门针对 LLM 的评判/评估能力**设计攻击。
    2. 现有方法通常假设受害者架构已知或需要 logits，**不适用于仅返回硬标签（hard labels）的真实 API 场景**。
    3. 对**多种评估协议（点评分、成对比较、列表排序）的联合提取支持有限**，分别查询代价高昂，在低查询预算下性能显著下降。
    4. 缺乏对**现实世界防御措施**（如异常检测、反蒸馏扰动、所有权追踪）的有效鲁棒性验证。

## 核心贡献（创新点）
1.  **首个多协议 LLM 评判能力提取框架**：提出了 JUDGESTEALER，是第一个能在黑盒设置下统一复制 LLM 点评分、成对比较和列表排序三种评判能力的提取框架。
2.  **查询高效的跨协议监督利用机制**：发现并利用了不同评估协议间高度的**交叉协议一致性**（平均超 88%），通过采集点评分数据并将其转换为其他协议的训练信号，**无需额外受害者查询**即可扩展监督范围，大幅提升查询效率。
3.  **动态信息输入选择机制**：设计了结合**语义多样性**、**预测不确定性**和**潜在评判偏差**的综合选择分数，动态筛选高信息量实例进行查询，避免冗余采样，优化查询预算分配。
4.  **对抗灾难性遗忘的自适应平滑与多协议整合训练**：引入基于离散高斯分布的**自适应评分平滑**机制以保留分数序数结构，并通过**多协议整合训练**在序列适应后融合所有协议数据，有效缓解灾难性遗忘。
5.  **全面的基准测试与防御鲁棒性验证**：在 GPT-5.4、Claude Sonnet 4.5 等主流 LLM-as-a-Judge 及专用奖励模型 UniRRM 上进行了广泛实验，并验证了方法对异常检测、反蒸馏扰动和所有权追踪等防御的鲁棒性。

## 方法详解
JUDGESTEALER 采用两阶段工作流程：

**阶段一：点评分提取**
1.  **动态样本选择**：对于未标注的候选实例集 $\mathcal{G}$（每个实例包含一个查询及多个响应），计算综合选择分数 $\Gamma(G) = \lambda_1 D(G) + \lambda_2 U(G) + \lambda_3 B(G)$。
    *   **语义多样性 $D(G)$**：基于嵌入表示的余弦距离和局部密度估计，确保查询覆盖输入空间的不同区域，排除孤立异常点。
    *   **预测不确定性 $U(G)$**：利用当前代理模型 $M_\Phi$ 输出分布的归一化熵衡量，高熵表明样本靠近决策边界，更具信息量。
    *   **潜在评判偏差 $B(G)$**：通过计算代理模型对**冗长偏差**（添加无意义前缀导致评分变化）和**位置偏差**（交换成对响应顺序导致分布变化）的敏感度来量化。
2.  **受害者查询与数据收集**：对选中的实例，在黑盒点评分协议下查询受害者 $M_\nu$，收集评分 $y_i$，构建点评分数据集 $S$。
3.  **代理模型训练与自适应平滑**：使用平滑后的目标分布 $\tilde{\mathbf{e}}_y = (1-\lambda) \mathbf{e}_y + \lambda \mathbf{g}_y$ 训练代理模型，其中 $\mathbf{g}_y$ 是 centered at $y$ 的离散高斯分布，平滑系数 $\lambda$ 可学习，以保留分数的序数邻近结构。

**阶段二：多协议扩展**
1.  **跨协议转换**：**无需额外查询**，将已收集的点评分数据 $G^*$ 转换为：
    *   **成对比较数据 $\mathcal{C}$**：根据评分比较直接推断偏好关系 ($a_j \succ a_k$ if $y_j > y_k$)。
    *   **列表排序数据 $\mathcal{R}$**：根据评分降序排列响应构建排名标签。
2.  **渐进式多协议训练**：
    *   分别在成对比较数据集 $\mathcal{C}$ 和列表排序数据集 $\mathcal{R}$ 上微调代理模型。
    *   **多协议整合**：为避免灾难性遗忘，将点评分、成对比较和列表排序数据合并为统一训练集 $\mathcal{T} = S \cup \mathcal{C} \cup \mathcal{R}$，使用加权损失 $\mathcal{L}_{con} = \alpha_{point}\mathcal{L}_{point} + \alpha_{pair}\mathcal{L}_{pair} + \alpha_{list}\mathcal{L}_{list}$ 进行联合微调，权重 $\alpha$ 由各类数据集大小比例决定。

## 实验与结果
- **数据集与受害者模型**：使用 Alpaca 和 GPT4All 数据集构建候选实例。受害者包括专有模型 **GPT-5.4**、**Claude Sonnet 4.5**，开源模型 **Qwen3-235B-A22B**、**DeepSeek V4 Pro**，以及专用奖励模型 **UniRRM-8B**。
- **代理模型**：主要使用 **Llama-3.2-1B-Instruct** 和 **Qwen3-1.7B**，并扩展至 0.6B-32B 不同规模。
- **基线**：Vanilla (随机采样)、LoRD (基于强化学习的提取)、Lion (对抗性知识蒸馏)、Proxy-KD (中间白盒代理蒸馏)。
- **主要结果**：
    - 在 **LLM-as-a-Judge** 设置下，JUDGESTEALER 在 480 项指标中有 475 项优于所有基线。
    - 代表性提升：在 GPT-5.4 (Alpaca) + Qwen3-1.7B 上，点评分 $Acc_{\pm1}$ 从 0.4865 提升至 0.5905 (+21.4%)，成对比较 Accuracy 从 0.6240 提升至 0.7707 (+23.5%)，列表排序 Accuracy 从 0.6300 提升至 0.6345。
    - 在 DeepSeek V4 Pro (GPT4All) 上，点评分 Accuracy 相对提升达 **93%** (0.2800 vs 0.5400)，成对比较 Accuracy 达 **87.0%**，列表排序 Accuracy 达 **71.6%**。
    - 在 **奖励模型 UniRRM** 上，使用 Qwen3-1.7B 时，点评分 MAE 达 0.6354，成对比较 Accuracy 达 0.8356，列表排序 Acc@Top 达 0.7967，均优于最强基线。
    - **跨规模与策略有效性**：在 0.6B 至 32B 不同规模的 Qwen3 模型上均有效，且在全量微调与 LoRA 适配下性能相当。
    - **CoT 推理设置**：在受害者提供思维链的情况下依然有效。
- **查询预算**：即使仅使用 0.5% 的候选实例进行查询（约 90 次），点评分 $Acc_{\pm1}$ 仍可达 ~50%，成对比较 Accuracy 超过 70%。
- **防御鲁棒性**：成功规避基于正态性检验的**异常检测**；对**反蒸馏扰动**防御不敏感（性能下降 <0.01）；**所有权追踪**水印未能有效转移到提取的代理模型中。

## 相关工作脉络
1.  **KnockoffNet / Activethief / Inversenet 等**：早期针对 CNN 的功能提取攻击，依赖于合成数据或特定架构假设，不直接适用于黑盒 LLM 评判能力提取。
2.  **Model Leeching [2] / Extracting [27]**：针对 LLM 功能提取的研究，但主要关注代码生成等单一任务，未涉及多协议评判能力的复制。
3.  **LoRD [28]**：近期针对 RLHF 对齐 LLM 的提取工作，采用局部强化学习策略梯度优化，与本文的跨协议监督转换和主动选择策略不同。
4.  **Lion [16] / Proxy-KD [5]**：基于对抗性知识蒸馏或中间代理模型的提取方法，本文在实验中将其作为主要对比基线，证明 JUDGESTEALER 在多协议下更具优势。
5.  **PRADA [17] / SEAT [48]**：基于查询序列异常检测的防御方法，本文实验表明 JUDGESTEALER 的选择机制能产生类似正常用户的查询分布，从而规避检测。
6.  **ModelGuard [39] / ModelShield [36]**：基于输出扰动和水印的所有权保护方案，本文验证了现有防御对 JUDGESTEALER 的限制有限。

## 局限性与未来方向
- **攻击性质**：聚焦于黑盒功能提取，未探讨参数/架构提取等更深层威胁。
- **防御评估**：对防御的测试基于论文中复现的简化版本，实际生产环境中的防御可能更为复杂和动态。
- **通用性边界**：高度依赖“交叉协议一致性”假设，对于一致性较低的弱评估器或特定领域/非标准评分协议，效果可能受限。
- **伦理与滥用**：攻击的成功凸显了 LLM 评估服务在知识产权保护和安全性方面的脆弱性，亟需更强大的防御机制。
- **未来方向**：探索对抗更先进防御（如动态查询检测、强化水印）的策略；研究在非黑盒或部分信息场景下的提取方法；设计针对评估能力的专门防护协议。

## 研究启发与可借鉴点
1.  **交叉属性利用**：发现并利用模型内部不同功能或协议间存在的**强一致性/关联**，是提升数据利用效率、实现“一次查询，多重收益”的有效思路，可迁移至其他需要多任务/多模式输出的模型提取或蒸馏场景。
2.  **多维主动学习选择**：将**多样性**（探索）、**不确定性**（利用边界）和**风险/偏差敏感性**（评估模型弱点）结合为统一选择分数，是一种更全面的主动学习/查询选择策略，适用于资源受限的黑盒模型优化。
3.  **序数知识保留**：在分类任务中，对 one-hot 标签施加**序数感知平滑**（如离散高斯分布），并将平滑系数设为可学习参数，有助于模型学习目标的内在结构关系，可应用于其他具有序数性质的预测任务。
4.  **防御驱动的设计考量**：在攻击设计中主动融入**规避检测**的机制（如密度过滤保证查询分布自然），提升了攻击的实用性和隐蔽性。这对于评估实际系统的安全性具有参考价值。
5.  **多协议/多任务联合训练防遗忘**：在逐步引入新监督信号后，进行**多协议/多任务数据整合与联合重训练**，是防止灾难性遗忘、实现能力协同增强的有效训练范式。

## 关键术语表
- **LLM-as-a-Judge**：利用大型语言模型根据提示词中的评估标准，对文本响应进行自动评分、比较或排序的范式。
- **Reward Model**：从偏好数据中学习到的标量奖励函数，常用于 RLHF 对齐过程，也可用于点评分、成对比较等评估任务。
- **Model Extraction Attack**：攻击者通过查询黑盒模型的 API，收集输入-输出对，训练一个本地代理模型以复制原模型特定功能的攻击方式。
- **Cross-Protocol Agreement**：指 LLM 在不同评估协议（点评分、成对比较、列表排序）下做出判断时表现出的高度一致性，是本文方法的核心前提。
- **Pointwise Scoring**：单一协议，对单个响应独立给出评分。
- **Pairwise Comparison**：单一协议，比较两个响应的优劣，输出偏好关系。
- **Listwise Ranking**：单一协议，对一组响应进行整体排序。
- **Catastrophic Forgetting**：深度学习模型在学习新任务时，对先前已学任务性能的显著遗忘现象。
- **Adaptive Smoothing**：将硬标签平滑为软标签的技术，本文中使用可学习系数的离散高斯分布，以保留评分的序数结构。
