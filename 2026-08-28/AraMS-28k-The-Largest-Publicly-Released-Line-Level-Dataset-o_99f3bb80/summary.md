# 论文速读：AraMS-28k-The-Largest-Publicly-Released-Line-Level-Dataset-o

## 一句话总结
本文提出了 AraMS-28k，即目前已公开的最大规模阿拉伯语历史手稿行级数据集，包含 14 部书籍、3,043 页和 28,600 行标注文本，并创新性地引入边注锚点（insertion anchor）标注以恢复手稿的非线性阅读顺序。

## 研究问题与动机
- 阿拉伯语历史手稿手写文本识别（HTR）领域缺乏大规模、来自真实手稿的行级数据集，现有资源多为现代手写字迹或合成数据，无法反映历史手稿的退化、连字变化和边注现象。
- 已有公开数据集中，即使标注了边注区域，也未能记录边注与正文的具体对应关系——识别边注区域或页面级阅读顺序 ≠ 记录某一行边注应插入正文的哪个具体位置。
- 参考转录本通常带有完整元音符号（diacritics），而手稿正文往往无元音符号，现有数据集未显式记录这一差异，导致训练目标与视觉输入失配。
- 现有资源规模有限：如 Muharaf 全库约 1,644 页/36,311 行，但仅公开了 1,216 页/24,495 行，且同样缺乏行级插入锚点标注。

## 核心贡献（创新点）
1. **AraMS-28k 数据集发布**：目前已公开的最大规模真实阿拉伯语历史手稿行级数据集（14 书、3,043 页、28,600 行），覆盖 Nasakh、Ruq'ah、Maghrebi 三种手写体及一部石印本，附带固定 train/val/test 划分。与 Muharaf 等现有资源相比，本文规模居公开数据之首且唯一提供行级边注锚点。
2. **行级插入锚点（insertion anchor）标注**：首次公开在历史阿拉伯语手稿语料中记录边注与正文行级对应关系的标注方案，使下游可精确恢复手稿非线性阅读顺序；约 30% 边注行可获可信锚点，其余保留 null 而非强行猜测。
3. **双转录本设计（raw + normalized）**：每条记录同时发布完整元音化的 gt_raw 与去元音符号的 gt_normalized，显式解决参考转录本与手稿视觉输入之间的元音符号失配问题。
4. **两阶段构建与质控流程**：提出页面验证（PV）与行验证（LV）双轨机制，PV 阶段由两名独立审阅者逐行人工核查，LV 阶段以自动对齐置信度作为筛选门槛，兼顾质量与规模。
5. **基线 HTR 结果与跨脚本泛化梯度**：基于 Kraken 和 HATFormer 给出基线 CER，并量化从分布内页到未见脚本（Maghrebi）的泛化差距，为后续研究建立可复现的评测基准。

## 方法详解
- **来源与多样性设计**：数据集取自经典医学、伊斯兰法学、逍遥学派哲学与神学等领域 14 部书籍，13 部为手抄本（覆盖 Nasakh、Ruq'ah、Maghrebi 三书体），1 部为石印版（book_10）以扩展版面与印刷形式多样性。
- **RefLAM 标注管线**：采用 RefLAM [1] 参考对齐管线，流程为：①用 Muharaf 上训练的分割模型将每页切分为行；②用多模态大语言模型（MLLM）进行 OCR，区分正文与边注；③将假设转录与独立来源的干净参考文本对齐，生成每行置信度分，低置信度行进入人工复审。
- **两阶段质控**：PV 阶段（7 书、548 页、11,438 正文行）由两名审阅者对每页每行进行完整人工核查；LV 阶段（7 书、2,495 页）仅保留与参考文本完全对齐的正文行（confidence=100），未达阈值的行直接剔除，不纳入发布。两者分开报告，供下游按需选用。
- **插入锚点标注规则**：边注行若与正文存在明确无可争议的附着点（由前后正文词汇 before/after 精确定位），则标注 margin_anchor.line 字段（正文行索引）；当前 corpus 共 629 行边注，其中 189 行（≈30%）获可信锚点，其余 70% 保留 null 而非强制猜测。
- **双转录本生成**：gt_raw 来自学术校勘本的全元音化版本；gt_normalized 通过 RefLAM 内部使用的同一归一化算子处理——去除 harakat 与 tatweel、合并 alef 变体、折叠空白，产出与无元音手稿视觉内容一致的转录本，作为 HTR 训练推荐目标。
- **划分策略**：按书级划分，14 书分为训练（9 书/19,739 行）、验证（2 书 Naskh/PV）、测试（3 书，每脚本各 1 书/PV），确保未见脚本评测纯净性。

## 实验与结果
- **数据集规模**：AraMS-28k 共 14 书、3,043 页（PV 548 页 + LV 2,495 页）、28,600 行（正文 27,971 行 + 边注 629 行），三书体加 1 石印版；PV 子集完整覆盖每页所有行，LV 子集仅含参考对齐完美匹配的正文行。
- **基线模型**：使用 Muharaf 预训练的 Kraken 与 HATFormer 在训练集上微调，在测试集上以 gt_normalized 为目标计算字符错误率（CER）。
- **主要结果**：
  - Kraken 整体 CER：23.31%；各脚本：Ruq'ah 11.65%、Naskh 22.62%、Maghrebi 32.71%。
  - HATFormer 整体 CER：26.74%；各脚本：Ruq'ah 13.26%、Naskh 25.37%、Maghrebi 37.88%。
- **跨脚本泛化梯度**（HATFormer 诊断实验）：在训练集书中预留 10% 页（约 2.5k 行）作分布内评测，CER 降至 6.48%；未见 Ruq'ah 书 ≈ 翻倍至 13.26%，未见 Naskh 书 ≈ 四倍至 25.37%，未见 Maghrebi 书达 37.88%。
- **关键结论**：脚本与预训练分布（Muharaf 以 Ruq'ah 为主）的亲疏是性能差距的主因，而非训练量；Maghrebi 因在公共预训练集中严重缺失导致泛化显著更差。移除中间 Muharaf 微调会使分布内 CER 从 6.48% 升至 7.44%，证实多源历史阿拉伯语预训练的有效性。

## 相关工作脉络
- **Muharaf [6]**：最大规模真实阿拉伯语手稿语料（全库 1,644 页/36,311 行，仅公开 1,216 页/24,495 行），覆盖多脚本但无行级插入锚点；AraMS-28k 在公开规模与标注精细度上均超越其公开子集。
- **RASAM [3]**：首个专注 Maghrebi 脚本的语料（≈300 页/7,540 行），与 AraMS-28k 的 Maghrebi 覆盖最为接近，但规模小一个数量级且无边注锚点。
- **RASM2018 [2]**：历史阿拉伯语科学手稿行级转录（≈120 页/2,613 行），仅有页面级区域标注，无行级正文-边注链接。
- **KHATT [4]**：规模较大（4,000 页/13,435 行）但为现代手写字迹合成，缺乏历史手稿的退化与连字特征。
- **OpenITI MAKHZAN [5]**：多语言覆盖面最广（1,497 页），但无行级插入锚点，且面向更广泛阿拉伯文字家族而非专门针对历史手稿 HTR。
- **VML-HD [7] / BADAM [8]**：分别标注约 680 页（亚词级）与约 400 页（基线检测），任务定位非行级 HTR，且不涉及边注锚点。
- **IAM [11] / RIMES [12]**：英语/法语手写基础语料，塑造了行级 HTR 评测范式，但未针对阿拉伯语手稿典型的双区（正文-边注）版面设计。

## 局限性与未来方向
- LV 子集受对齐过滤约束，可能偏向扫描质量较好、书写较规整的手稿，不能代表全部历史变体；作者已显式分离报告 PV/LV 以提示此偏差。
- 约 70% 边注行因无法可靠定位而保留 null 锚点，限制了阅读顺序恢复任务的样本量。
- 测试集每种脚本仅含一本书，per-script CER 可能受书籍特有特征（如 ink fade、scan quality）混杂，难以纯归因于脚本难度。
- 边注行仅占 corpus 的 ≈2.2%（629/28,600），训练类如边注检测的模型时需注意类别不平衡，需借助重采样或类别加权。
- 未来方向包括：引入脚本相似度度量（如 letterform edit-distance）以量化预训练分布亲疏、控制 pretraining/script-finetuning ablation、扩展更多脚本/语言、以及针对插入锚点恢复与版面分析设计正式评测协议。

## 研究启发与可借鉴点
- **参考对齐驱动的大规模手稿标注管线**：RefLAM 的"MLLM OCR → 参考对齐置信度 → 分层人工复审"流程，证明了借助外部权威参考文本可将大规模历史手稿标注周期压缩至一周量级，适用于其他语种手稿的快速语料构建。
- **双轨质控设计（PV vs LV）**：分离"全量人工核查"与"自动对齐筛选"两档质量保障，既保留大尺度数据规模，又为高质子集提供明确标注，下游可按任务需求选取相应 guarantee level。
- **元音符号归一化作为显式设计**：将参考转录本与视觉输入之间的元音符号失配转化为 gt_raw/gt_normalized 双字段，提醒下游应避免隐式假设 OCR 输出与视觉信号的一致性，该思路可直接迁移至其他带变音符号的文字系统。
- **插入锚点作为非线性阅读的细粒度标注**：边注-正文行级链接比页面级区域标注更具语义价值，可为多语言手稿（如拉丁文、希伯来文）的 margin annotation recovery 提供标注范式。
- **跨脚本泛化梯度的诊断实验设计**：预留训练书内 10% 页用于 in-distribution 评测，与完全未见脚本的 out-of-distribution 结果形成对照，为量化"分布亲疏 vs 训练量"的相对贡献提供了可复现的评估协议。

## 关键术语表
- **HTR (Handwritten Text Recognition)**：手写文本识别，将手写图像转录为可搜索文本的核心任务，本文聚焦历史阿拉伯语手稿。
- **Insertion anchor (插入锚点)**：标注边注行应插入正文的精确位置（以前后正文词汇 before/after 及行索引 line 表示），用于恢复手稿非线性阅读顺序。
- **gt_raw**：完整元音化参考转录本，源自学术校勘本，保留所有 tashkeel/diacritics，适用于元音还原研究。
- **gt_normalized**：经归一化处理后的转录本，去除元音符号、合并 alef 变体、折叠空白，与无元音手稿视觉内容一致，推荐作为 HTR 训练目标。
- **Page-validated (PV)**：页面验证子集，由两名审阅者对每页所有行进行完整人工核查，质量保障最高。
- **Line-validated (LV)**：行验证子集，仅保留与参考文本完全对齐的正文行（confidence=100），规模更大但偏向清晰规整样本。
- **RefLAM**：Reference-grounded Line Annotation Manager，本文采用的参考对齐标注管线，结合 MLLM OCR 与独立参考转录实现自动对齐与置信度评估。
- **Ruq'ah / Naskh / Maghrebi**：阿拉伯语三大主要手写体传统；Ruq'ah 为黎凡特晚期奥斯曼时期主导日常手写，Naskh 常用于宗教文本，Maghrebi 为马格里布地区独特书体，在公共预训练集中严重缺失。

## 可复现要素
- **数据集**：AraMS-28k 与 AraMS-28k-HTR 均已公开，托管于 Hugging Face Datasets 与 Zenodo，DOI: https://doi.org/10.5281/zenodo.22095333，协议 CC BY-NC-SA 4.0。
- **代码/权重**：微调超参数与代码已随仓库发布；Muharaf 预训练 checkpoint（Kraken [15]、HATFormer [16] 基座）公开可用。
- **关键超参**：
  - HATFormer：AdamW（β₁=0.9, β₂=0.999, ε=10⁻⁶, weight decay=0.01）；学习率 5×10⁻⁵；batch size=8；warmup 500 linear steps；gradient clipping=5.0；最多 20,000 steps，每 1,000 step 保存checkpoint并按 val CER 选取。
  - Kraken：Muharaf 预训练 checkpoint 初始化；epoch 1 冻结 backbone（2,468 steps, batch=8）；学习率 5×10⁻⁴ cosine decay；early stopping patience=15 epochs，上限 100 epochs；seed=42。
- **固定划分**：train/val/test 按书级分配，test_seen_pages.txt 与 real_damage_lines.txt 随发布一并提供，确保结果可精确复现。
