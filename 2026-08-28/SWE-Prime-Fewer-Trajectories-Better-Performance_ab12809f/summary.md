# 论文速读：SWE-Prime-Fewer-Trajectories-Better-Performance

## 一句话总结
本文提出 SWE-Prime，一种多粒度两阶段数据选择方法，通过轨迹级和语义片段级筛选，从大规模成功轨迹中提取高质量、有代表性的子集用于编码智能体的监督微调（SFT），仅需使用 10% 的轨迹数据即可超越在全量数据上训练的模型性能。

## 研究问题与动机
- **任务成功不等于高质量监督**：现有工作（如 SWE-Gym、SWE-smith、R2E-Gym）仅基于执行验证保留成功轨迹进行 SFT，但成功轨迹可能包含无效、冗余或高风险步骤。
- **轨迹层面质量问题**：成功轨迹可能缺乏标准问题解决模式（如 observe-edit-verify 工作流）、工具调用失败率高、存在连续冗余操作、利用 Git 历史泄露信息作弊、或产生过度宽泛的补丁。
- **片段层面低价值行为**：即使轨迹整体质量高，内部某些语义片段（segment）可能对最终修复无贡献，仍适合作为 SFT 监督信号。
- **数据多样性缺失**：仅按质量分数选择可能导致聚类偏向少数问题类型，造成监督冗余和覆盖不足。

## 核心贡献（创新点）
1. **提出多粒度两阶段数据选择框架**：在轨迹级和语义片段级渐进式筛选高质量 SFT 监督数据，与现有仅依赖任务执行结果的工作形成本质区别。
2. **引入语义片段（Semantic Segment）作为细粒度行为单元**：将连续步骤按意图分组评估其对最终修复的贡献、学习性和风险，而非孤立评估单个步骤，填补了长轨迹行为评估的粒度空白。
3. **设计轨迹级五维度质量评估体系**：综合工作流模式（observe-edit-verify）、工具调用成功率、连续冗余检测、Git Hack 检测、结果质量（补丁最小化），全面量化轨迹适用性。
4. **提出基于聚类的数据代表性选择策略**：使用 HDB-SCAN 对问题描述进行语义聚类，在各类别内按质量排序选择，兼顾质量与覆盖多样性。
5. **实现选择性 SFT 损失函数**：所有片段保留在序列中以维护上下文连贯性，仅选中的片段对助手响应 token 计算训练损失，有效隔离高质量监督信号。

## 方法详解
**整体框架**：SWE-Prime 分两阶段渐进式筛选，Stage 1 从成功轨迹池中选出高质量、有代表性的子集，Stage 2 在保留轨迹内识别高价值语义片段。

**Stage 1：轨迹级选择**
- **过程质量评估**（四个信号）：
  - 工作流接地（$S_{\text{workflow}}$）：检查是否在执行前探查仓库、最终编辑后通过测试验证。
  - 工具调用成功率（$S_{\text{tool}}$）：计算成功率并在轨迹池中的百分位排名。
  - 连续冗余控制（$S_{\text{redundancy}}$）：检测相邻步骤工具名和参数是否完全相同。
  - Git Hack 检测（$S_{\text{git}}$）：检查代理是否在修改代码前通过 Git 历史操作获取了参考补丁内容。
- **结果质量评估**：
  - 文件级范围分数：$S_{\text{file}} = \min(F_{\text{gold}}/F_{\text{model}}, 1)$
  - 行级范围分数：$S_{\text{line}} = \min(L_{\text{gold}}/L_{\text{model}}, 1)$
  - 结果分数：$S_{\text{result}} = S_{\text{file}} \times S_{\text{line}}$
- **轨迹综合得分**：
  - $S_{\text{traj}} = \frac{1}{5}(S_{\text{workflow}} + S_{\text{tool}} + S_{\text{redundancy}} + S_{\text{git}} + S_{\text{result}})$
- **数据代表性评估**：
  - 使用 Qwen3-Embedding-8B 编码问题描述，应用 HDB-SCAN 聚类语义相似问题，在各聚类内按 $S_{\text{traj}}$ 排序选择候选轨迹。

**Stage 2：片段级选择**
- **片段切分**：
  - 使用滑动窗口处理超长轨迹，采用边界感知切分机制：当前窗口的最后一个不完整片段带入下一窗口重新评估，确保语义连贯性。
  - 为每个窗口提供前置窗口的问题摘要、已确立事实和已识别风险，保持切分一致性。
- **片段评分**：
  - 三个评估标准：对最终修复的贡献（定位、上下文收集、修改、验证、错误恢复）、局部可学习性（清晰的证据-动作-反馈模式）、行为风险（无关探索、无信息失败、不安全操作、硬编码解）。
  - LLM 根据问题描述、轨迹上下文和参考补丁为每个片段 $s_{i,j}$ 分配质量分数 $q_{i,j} \in [0, 10]$。
- **片段过滤与选择性 SFT**：
  - 二值选择掩码：$m_{i,j} = 1$ if $q_{i,j} \geq \delta$，否则 $m_{i,j} = 0$。
  - 选择性 SFT 目标函数：
    $$\mathcal{L}_{\text{SFT}} = -\frac{1}{N_{\text{sel}}} \sum_i \sum_j m_{i,j} \sum_{t \in \hat{A}(s_{i,j})} \log p_\theta(y_{i,t} | y_{i,<t})$$
  - 所有片段保留在序列中作为上下文，仅选中片段对助手响应 token 计算损失。

## 实验与结果
**数据集**：
- SWE-rebench OpenHands Trajectories：67,074 条由 Qwen3-Coder-480B-A35B-Instruct 生成的轨迹，其中 32,161 条成功解决问题。

**基础模型**：
- GLM-4.7-Flash（30B total / 3B activated）
- Qwen3-30B-A3B-Instruct-2507（30.5B total / 3.3B activated）
- Qwen3-Coder-30B-A3B-Instruct（30.5B total / 3.3B activated）

**评测基准**：
- SWE-Bench Verified：500 个人工验证任务
- SWE-Bench Pro：731 任务公开划分

**基线方法**：
- Raw Model：原始模型无 SFT
- Resolved-Trajectory SFT：全量 32,161 条成功轨迹标准 SFT
- Random-10%：随机选择 10% 成功轨迹

**主要结果**：
- **Qwen3-30B-A3B-Instruct-2507**：SWE-Prime 在 SWE-Bench Verified 上达到 39.6%（相对提升 57.1%），在 SWE-Bench Pro 上达到 18.88%（相对提升 130.0%）；相比全量轨迹 SFT（36.8% 和 16.83%）分别提升 2.8 和 2.05 个百分点。
- **GLM-4.7-Flash**：SWE-Prime 在 Verified 上达到 51.4%（+27.2%），在 Pro 上达到 26.95%（+140.2%）；相比全量轨迹 SFT（41.4% 和 24.62%）分别提升 10.0 和 2.33 个百分点。
- **Qwen3-Coder-30B-A3B-Instruct**：SWE-Prime 在 Verified 上达到 53.2%（+18.8%），在 Pro 上达到 34.75%（+17.6%）；相比全量轨迹 SFT（51.0% 和 31.05%）分别提升 2.2 和 3.7 个百分点。
- **最大提升幅度**：相对于全量成功轨迹 SFT，SWE-Prime 在 SWE-Bench Verified 上最高相对提升达 24.2%，在 SWE-Bench Pro 上最高相对提升达 12.2%。

**超参数分析**：
- 轨迹保留比例：10% 为最优（5%: 46.2%, 10%: 50.2%, 20%: 49.6%, 30%: 49.2%）
- 片段分数阈值：7 为最优（5: 46.8%, 7: 53.2%, 8: 49.6%, 9: 47.0%）

**行为分析**：
- SWE-Prime 训练模型相比全量轨迹 SFT：冗余降低最多 0.188，observe-before-edit 率提升最多 9.6 个百分点，工具成功率提升最多 0.094，平均交互轮次减少 4.1-12.7 轮。

## 相关工作脉络
1. **SWE-Gym (Pan et al. 2024)**：从真实 GitHub issue 构建可执行任务并收集测试验证轨迹，仅基于任务执行结果保留成功轨迹，未考虑轨迹内部质量差异。
2. **SWE-smith (Yang et al. 2025b)** 和 **R2E-Gym (Jain et al. 2025)**：使用合成数据生成和混合验证器扩展任务和轨迹收集规模，但仍以执行验证为主要筛选标准。
3. **SWE-Factorory (Guo et al. 2025)**：自动化多语言环境构建和任务验证，聚焦数据规模扩展，未涉及数据质量精细化评估。
4. **SWE-Lego (Tao et al. 2026)**：在数据构建后过滤失败工具调用的步骤，但仍保留所有成功轨迹，未进行轨迹级质量筛选和片段级细化。
5. **SWE-Master (Song et al. 2026)**：通过 post-training 释放软件工程师代理潜力，侧重训练策略而非数据选择质量。
6. **本文定位**：SWE-Prime 从"任务成功"转向"监督价值"，在多粒度层面（轨迹+片段）和多维度（过程质量+结果质量+代表性）进行数据选择，填补了现有工作在高质量 SFT 数据筛选方面的空白。

## 局限性与未来方向
- **评估基准局限**：仅在 SWE-Bench Verified 和 SWE-Bench Pro 上验证，未在其他软件代理基准（如 SWE-Bench Lite、Multi-Prog）上测试泛化性。
- **片段评估依赖 LLM**：Stage 2 的片段评分使用 LLM 进行，可能引入评估不一致性或成本开销。
- **数据源单一**：仅使用 SWE-rebench OpenHands Trajectories 单一数据源，未探索多源数据融合。
- **超参数敏感性**：轨迹保留比例和片段阈值需预先确定，对不同数据集可能需要重新调优。
- **未来方向**：可扩展至多语言代码库、结合强化学习进行在线数据选择、探索自动阈值确定策略。

## 研究启发与可借鉴点
1. **多粒度数据选择思路可迁移**：在 agent 训练、代码生成、数学推理等长轨迹任务中，均可借鉴"轨迹级+片段级"渐进筛选策略，区分任务成功与学习价值。
2. **过程质量多维信号设计**：工作流接地、工具成功率、冗余检测、泄露检测等信号可复用于其他 agent 训练场景的质量评估体系构建。
3. **选择性 SFT 损失设计**：保留完整上下文但仅对选中片段计算损失的策略，适用于任何需要区分"上下文"与"监督目标"的训练场景。
4. **聚类辅助代表性选择**：使用 embedding + 聚类保证数据多样性的方法，可在其他 SFT 数据筛选任务中复用，避免质量导向选择的偏差问题。
5. **边界感知片段切分**：滑动窗口+边界片段延续机制可推广至其他需要语义分段评估的长序列场景。

## 关键术语表
**SWE-Bench**：软件工程师基准测试套件，评估 LLM 解决真实 GitHub issue 的能力，包含 Verified（人工验证）和 Pro（更大规模）版本。
**Semantic Segment**：语义片段，将连续步骤按共同意图分组的行为单元，用于细粒度质量评估而非孤立步骤。
**Observe-Edit-Verify Workflow**：观察-编辑-验证工作流，代码修改前先探查仓库上下文、修改后通过测试验证的标准问题解决流程。
**Git Hacking**：Git 黑客行为，代理利用仓库历史中的参考补丁信息指导代码修改的作弊行为。
**Selective SFT**：选择性监督微调，仅对选定高质量片段计算训练损失而保留所有片段作为上下文。
**HDB-SCAN**：层次密度聚类算法，用于对问题描述进行语义聚类以保证数据选择的代表性。
