# 论文速读：RIDESKILL: A HIERARCHICAL ALGORITHM FOR GENERALIZED RIDE SHARING WITH LLM-DRIVEN AUTOMATIC EVOLUTION

## 一句话总结
本文提出 RideSkill，首个面向拼车（ride-sharing）任务的 LLM 辅助自动进化算法框架，通过技能库、组合器与顺序重定位器的三层架构，实现了对不同车队规模、车速、载客量、订单密度及平台目标的多场景零样本适应，推理阶段无需 LLM 调用，满足实时性要求。

## 研究问题与动机
- **拼车调度的复杂性**：多个乘客具有不同 OD 对，需在不确定场景下将订单高效打包并分配给共享车辆，状态与动作空间随车辆数和订单数指数扩张。
- **MARL 方法的泛化缺陷**：现有 MARL 方案在固定场景下表现良好，但一旦平台目标（如从收入最大化转向服务质量最大化）或环境条件（车队规模、车速、容量）改变，策略无法自适应，需重新训练，且多智能体设定下其他智能体策略变化导致环境非平稳，迁移困难。
- **LLM 方法的适用性不足**：近期将 LLM 直接用于决策或匹配的方法不支持车辆共享（扩展了状态和动作空间），且推理时需频繁调用 LLM，难以满足实时调度延迟要求；而基于 LLM 的自动算法设计方法仅针对单车网约车（无拼车），尚未扩展至拼车场景。
- **平台目标的动态演化**：实践中平台目标可能随市场条件和监管要求快速变化，静态策略无法适应，亟需一种无需重新训练即可适配新目标和场景的通用方法。

## 核心贡献（创新点）
1. **首个 LLM 驱动的拼车调度自动进化框架**：将 LLM 引入拼车任务的算法设计，通过进化搜索自动生成技能、组合器与重定位器，解决了此前 LLM 方法仅支持单订单网约车的问题。
2. **分层技能组合架构**：提出"技能库–组合器–重定位器"三层结构，组合器根据当前环境和目标动态为每辆车选择 Top-b 技能并加权融合，重定位器顺序处理空闲车辆以避免多车同时涌入同一热点区域。
3. **GDPO 风格群体相对适应度设计**：针对不同任务奖励尺度差异巨大的问题，采用受 GRPO 启发的群体相对优势（group-relative advantage）作为适应度，使不同目标/场景下的政策评估具有可比性，避免低奖励尺度任务被高奖励尺度任务淹没。
4. **LLM 自检查反馈机制**：在进化搜索结束后引入自审计模块，区分技能描述错误、适应度函数错误和策略对目标无响应等问题，并提供对应的修复路由，提升进化结果的可靠性和可解释性。
5. **可选的车队公平性预算机制**：基于车辆历史累积收入的偏差动态调整匹配分数预算，使低收入车辆获得更高匹配权重，在不显著降低整体性能的前提下改善司机间收益公平性。

## 方法详解
RideSkill 采用三层分层架构，所有组件均通过 LLM 辅助的 $(\mu+\lambda)$-ES 进化算法离线训练，部署时零 LLM 调用：

1. **技能库（Skill Repository）**：维护 $K$ 个原子技能 $\mathcal{B}=\{s_1,\ldots,s_K\}$，每个技能是一个独立的评分函数 $s_k(x_i, o_j, \phi_{\text{ep}}, \phi_{\text{step}}) \in \mathbb{R}$，输出车辆–订单对的边际价值，并配有自然语言说明卡（目标、描述、机制）。训练时 LLM 自行设计技能目标、机制和自 authored 适应度函数，通过仿真滚动评估，并使用余弦相似度去重防止冗余技能累积。
2. **组合器（Combiner）**：映射函数 $\pi_c(x_i, \phi_{\text{ep}}, \phi_{\text{step}}, w) = \alpha_i \in \mathbb{R}^K$，根据当前环境状态和平台目标 $w$（以每步事件描述到标量奖励的函数形式给出）为每辆车输出各技能的原始分。选择 Top-$b$ 正分技能，经 softmax 归一化得到权重 $\tilde{\alpha}_{i,k}$，再对每个候选订单计算融合匹配分：$a_{i,j} = \sum_{k \in \mathcal{K}_i} \tilde{\alpha}_{i,k} \cdot \frac{s_k(x_i,o_j,\phi_{\text{ep}},\phi_{\text{step}}) - \mu_k}{\sigma_k + \epsilon}$，其中 $\mu_k, \sigma_k$ 是技能 $k$ 在该车辆可行候选集上的均值和标准差（逐技能标准化防止不同尺度技能相互淹没）。最终通过二分图匹配（整数线性规划）求解分配。组合器通过"探针事件"机制推断目标 $w$ 的形状：构造结构不同的合成事件（如完成 vs 未完成、2人 vs 1人、长行程 vs 短行程等），调用 $w$ 读取差分值以估计各奖励项系数。
3. **重定位器（Repositioner）**：对空闲车辆逐个处理（随机顺序），每辆车评估候选区域集 $\mathcal{G}_i$（当前位置、邻居、全局热度最高的 $H$ 个区域）并输出重定位分 $\nu_g$，选择最高分区域 $g^*$ 后递减该区域的 $\kappa_{g^*}$（有效需求/供给状态），实现逐步扩散避免多车同时涌入同一热点。适应度定义为相同种子下开启/关闭重定位的 episode return 差值 $\mathrm{G}^{\text{repo}} - \mathrm{G}^{\text{off}}$，确保正增量直接反映重定位的真实收益。
4. **训练流程**：三阶段 LLM 辅助 $(\mu+\lambda)$-ES，每代从 $\mu$ 个父代中选优（含每任务组预留精英），LLM 执行交叉（概率 $p_{\text{cross}}$）或突变生成 $\lambda$ 个子代，每代注入一个全新个体保持多样性；候选经 AST 沙箱编译和字段验证，失败则反馈并逐步降温重试；评估采用 GDPO 风格群体相对适应度 $F_l = \frac{1}{|\mathcal{T}|}\sum_m \frac{G_l(\mathcal{M}_m) - \mu^{(m)}}{\sigma^{(m)}}$；搜索结束后自审计（Phase 1 检查技能意图对齐，Phase 2/3 检查目标响应性）。

## 实验与结果
- **数据集与仿真器**：基于纽约市真实出租车数据（Taxi & Commission, 2024），在 RideGym 模拟器上构建拼车仿真；训练集为 2026-04-06 至 04-12 的 8:00–20:00，验证/测试集为 04-13 和 04-14 同期。
- **评估维度**：跨 5 个轴线的广义化测试——小时（12 级别）、车队规模（200–1500，7 级别）、车速（20–50 km/h，7 级别）、载客量 $\leq 4$（1–4，4 级别）和 $>4$（5–8，3 级别）；锚点目标下仅单变量偏离训练分布（其余为同分布）。
- **基线**：模型类（Nearest、KM、GS）、MARL 类（REDA、BMG-Q、MFRL）、LLM 类（Zhang et al. 2026 open/close-loop）。
- **主要结果**：RideSkill（全栈）在全部 5 个轴线上均取得最优或次优成绩。以队长 1000、容量 4、速度 35 km/h 锚点场景为例：Reward 为 7654±1497，服务率 0.92±0.06，完成率 0.83±0.05，等待时间 1.12±0.15 min，拼车绕路时间仅 0.16±0.02 min，利用率 0.90±0.10；相比之下 best MARL baseline（MFRL）Reward 6850±1042、绕行时间 1.13±0.61 min，best rule-based（Nearest）Reward 6051±906、绕行时间 1.77±0.30 min。RideSkill 较单技能平均基线（single-skill）Reward 提升约 57%（4876→7654），绕行时间降低约 86%（1.12→0.16 min）。
- **消融结论**：去掉重定位器（RideSkill w/o reps）性能下降但仍远超单技能；单技能平均表现最差，验证了组合器跨场景灵活性的必要性；在容量 $>4$ 场景下 MARL 基线完全失效（固定网络输入尺寸），RideSkill 保持领先。
- **公平性**：$\rho=1.0$ 时各车队收入标准差显著降低，且与 $\rho=0$ 相比 Reward 下降不足 2%。

## 相关工作脉络
- **经典规则/优化基线**（Nearest、KM、GS）：依赖手工设计的代价模型和固定目标，无法适应变化的场景或目标；RideSkill 通过进化自动生成技能并动态组合，超越其静态性。
- **MARL 调度方法**（REDA、BMG-Q、MFRL）：学习长期策略但存在维度灾难，且在车队规模、容量、目标变化时需重训练；RideSkill 将策略封装为可迁移的技能组合，零样本适应不同配置。
- **LLM 直接决策方法**（Lyu et al. 2026a; Zhang & Xiao 2026）：推理时每车每步需 LLM 调用，延迟不可接受；RideSkill 仅离线用 LLM 设计算法，部署时纯代码运行，延迟为零。
- **LLM 自动算法设计**（Zhang et al. 2026）：采用 LLM 进化搜索生成调度启发式，但仅针对单订单网约车，未处理拼车的可行性订单组合、车辆异构性等挑战；RideSkill 首次将 LLM 进化扩展至拼车，并引入技能库+组合器的分层设计应对指数级动作空间。
- **Reward/目标迁移方法**（如 Barreto et al. 2026 GDPO 思想）：GRPO 用于 RL 多奖励优化；本文将其移植到进化搜索的适应度评估，解决跨任务奖励尺度不可比问题。

## 局限性与未来方向
- **LLM 能力依赖**：实验显示 GLM-5.1（67B）虽仍优于所有基线，但性能低于 Claude Opus 4.8（309B），表明 pipeline 效果受底层 LLM 容量制约，较小模型可能难以生成高质量技能和探针逻辑。
- **重定位器的启发式公平预算缺乏理论保证**：收入偏差预算机制 $\beta_i = \exp(-\rho z_i)$ 为经验设计，论文承认无理论收敛性保证。
- **仅支持线性组合目标**：当前组合器通过探针估计奖励系数，适用于线性可分解目标；对于非线性、阈值型或序列依赖目标（如"连续 3 单完成后给予奖金"）的支持能力未验证。
- **未来方向**：扩展至其他城市出行任务（如微出行、货运调度）；支持 episode 内动态变化目标；探索开源自适应 LLM 以降低成本。

## 研究启发与可借鉴点
1. **LLM 作为进化算子的可编程操作符**：用 LLM 替代传统 ES 的 Gaussian 突变/交叉，基于父代性能分析定向生成子代，可复用于其他算法设计场景（如路由策略、调度规则、强化学习 reward shaping）。
2. **群体相对适应度（GDPO-style）跨尺度归一化**：当任务间奖励量级差异大时，用组内 z-score 归一化替代绝对回报排序，可推广至多目标进化、多任务强化学习等领域。
3. **自检查反馈回路**：进化结束后让 LLM 审计自身输出与测量行为的一致性，区分描述错误/适应度错误/目标盲从，并提供修复路由，提升自动化算法设计的可靠性，适用于任何 LLM 生成代码的场景。
4. **顺序决策避免多智能体 flocking**：重定位器采用随机顺序逐个决策并衰减已选区域的有效需求，类比 chain-of-thought 逐步推理，可借鉴于资源分配、区域调度中避免多主体同时涌入同一目标的冲突问题。
5. **技能库模块化设计**：将复杂策略拆解为可解释原子技能 + 动态组合器，既保留人类可审计性，又赋予系统跨场景泛化能力，可作为"可解释 AI + 自适应决策"的通用范式。

## 关键术语表
**Ride-sharing**：允许多个不同 OD 对的乘客共享同一车辆的出行服务，核心挑战在于订单打包与车辆调度的联合优化。
**Skill（技能）**：具有明确文本描述、固定输入输出和程序实现的原子调度策略，如最近匹配、绕路最小化、服务率最大化等。
**Combiner（组合器）**：根据当前环境和平台目标，为每辆车动态选择 Top-b 技能并以 softmax 加权融合的分层决策模块。
**Repositioner（重定位器）**：顺序处理空闲车辆，将其迁移至即将产生需求的区域，通过逐步衰减已选区域有效需求避免多车 flocking。
**GDPO-style fitness（群体相对适应度）**：受 GRPO 启发的跨任务归一化适应度，用组内 z-score 消除不同目标奖励尺度的影响。
**Self-check（自检查）**：进化搜索结束后 LLM 对 champion 进行意图–行为一致性审计，输出 match / description\_wrong / fitness\_wrong 三种裁决之一。
**Probe event（探针事件）**：结构不同的合成事件对，用于推断组合器对黑盒目标函数 $w$ 各系数的敏感度。
**Fairness budget（公平性预算）**：基于车辆历史累积收入偏差的动态乘法因子，低收入车辆获得更高匹配权重以促进车队收益公平。

## 可复现要素
- **数据集**：NYC Taxi & Limousine Commission Trip Record Data（2024），开放可用；训练/测试时间段及划分在论文中明确声明。
- **模拟器**：RideGym（Zhao et al. 2026），提供标准化 Gym API；代码已开源。
- **代码**：论文附录声明代码在 https://anonymous.4open.science/r/RideSkill-6AAD 开源（双盲评审匿名链接）。
- **关键超参**：$(\mu+\lambda)=(4+4)$，$p_{\text{cross}}=0.35$，每代 1 个 parentless injection；Phase 1：$K=10$ 技能，5 代/技能，6 场景/代，$\tau=0.98$；Phase 2/3：8–20 代（自适应早停），18 任务/代（场景×目标混合），每 reward family 保留 1 elite；LLM 温度 0.9，沙箱修复尝试 ≤3 次。
- **推理配置**：每车 top-60 候选订单，组合 top-b=3 技能。
