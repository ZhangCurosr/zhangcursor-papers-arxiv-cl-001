# How Benchmark Graph Construction Shapes Multi-Hop KG Navigation: A Controlled Audit of PathQuestion and PathQuestion-Large

Eduin E. Hernandez<sup>1</sup>\* Sergio A. Diaz<sup>1</sup> Luis F. Garcia<sup>2</sup> Nurassyl Askar<sup>2</sup> Stefano Rini<sup>1</sup> <sup>1</sup> National Yang Ming Chiao Tung University, Hsinchu, Taiwan <sup>2</sup> Independent Researcher

## Abstract

Multi-hop knowledge-graph question answering (KGQA) benchmarks are often treated as fixed language-and-reasoning tasks, but for navigation-based methods, difficulty also depends on the graph in which those tasks are instantiated. This makes graph construction a consequential but often entangled part of the navigation task. To isolate this effect, we audit PathQuestion (PQ) and PathQuestion-Large (PQL) as graph-navigation benchmarks under a controlled intervention: we hold questions, topic entities, released answers, released path annotations, and family-level splits fixed while replacing each released task-filtered graph with the larger source KG distributed with the benchmark. Source restoration expands the effective navigation search space and graphconsistent answer and path multiplicity while sharply reducing unguided reachability to released answers. We evaluate whether these structural changes persist across navigation policies using structural references, frozen small-language-model navigation policies, and trained MINERVA policies. Across both frozen and trained policies, restoration substantially reduces released-answer accuracy and trajectory fidelity, while graph-consistent evaluation recovers only part of the loss. These results show that benchmark graph construction is part of the navigation task specification rather than merely an implementation detail and can materially shape measured behavior even when the released QA task is held fixed.

## 1 Introduction

Multi-hop knowledge-graph question answering (KGQA) asks a model to combine a naturallanguage question with a sequence of graph relations to reach one or more answer entities. PathQuestion (PQ) and PathQuestion-Large (PQL), introduced with the Interpretable Reasoning Network (IRN) (Zhou et al., 2018), are long-standing benchmarks for this setting and have been used to study multi-relation reasoning over compact knowledge graphs. For graph-navigation methods such as MINERVA (Das et al., 2018), however, the graph is not passive background context: it directly defines the legal actions available at every reasoning step. A benchmark can therefore become easier, harder, or simply different when its graph is filtered, even if the question text and intended relation chain do not change. The present study asks a different question: what changes when the released Question-Answer (QA) tasks are placed back into the larger source/original knowledge graphs that accompany the benchmark artifacts? We treat this graph restoration as a controlled intervention rather than as a benchmark redesign.

Each PQ/PQL question specifies a topic entity and an intended sequence of relation types leading toward one or more answers. We refer to this sequence as a relation chain, and to a concrete alternating sequence of entities and relations realizing that chain in the graph as a path. Related surface questions that correspond to the same underlying navigation problem are grouped into a structural family to prevent related variants from crossing split boundaries and to give each family equal weight in evaluation. For each QA instance, we keep fixed the natural-language question, topic entity, evaluation horizon, released valid-answer set, one or more released relation chains, structuralfamily identity, and split assignment. We then change only the active navigation graph from the released task-filtered graph $G _ { F }$ to the distributed source graph $G _ { S }$ . The primary evaluation continues to use the released answer and path annotations in both conditions, isolating the effect of changing the graph from changes to the evaluation target. Separately, we enumerate graph-consistent answers and paths: endpoints and path realizations obtained by following the same released relation chains in the active graph.

This distinction is important because PQ/PQL contain repeated surface variants, multiple valid answers, cyclic or immediately backtracking reference paths, and, in PQL, a small number of QA instances with more than one released relation chain. Collapsing these cases into a single designated path, removing repeated-node trajectories, or evaluating every textual variant as an independent structural problem can distort both the measured difficulty of the benchmark and the apparent behavior of the evaluated models. We therefore reconstruct the benchmarks using family-level split control and multi-reference annotations while preserving the released trajectories.

Contributions. Our contributions are threefold:

• INTERVENTION. We formulate source restoration as a matched intervention that isolates the effect of graph construction by holding the released QA task fixed while changing only the active navigation graph.

• RECONSTRUCTION. We provide a familycontrolled reconstruction of PQ/PQL that preserves multiple released references and cyclic trajectories while making graph-induced answer and path multiplicity explicit. As the original benchmarks lack an explicit redistribution license, we release the reconstruction code rather than the reconstructed datasets.<sup>1</sup> The code reproduces the benchmark versions used in this study from the original released artifacts.

• EMPIRICAL EVIDENCE. We evaluate the intervention using structural references, frozen small-language-model navigation policies, and trained MINERVA policies, measuring both answer accuracy and trajectory fidelity with the path-fidelity metrics introduced for traceable KG navigation in prior work (Hernandez et al., 2026b). We complement these fixed released targets with graph-consistent diagnostics that identify newly realizable answers and paths in the restored graph.

Across these settings, source restoration consistently changes answer reachability and trajectory fidelity, showing that benchmark graph construction is a consequential part of the navigation task specification.

## 2 Related Work and Benchmark History

Original construction and mixed-hop variants. PathQuestion and PathQuestion-Large were introduced with IRN as separate 2-hop and 3-hop benchmarks generated from Freebase subsets by extracting relation paths and rendering them through handcrafted templates with synonym and paraphrase variation (Zhou et al., 2018). IRN characterizes PQL as the more challenging variant because it uses a larger KG while providing fewer training instances. Thus, “Large” refers to the graph rather than to the number of QA examples. The released artifacts additionally distinguish hop-specific taskfiltered KGs from larger source/original KGs, a distinction that motivates the controlled restoration studied here. UHop (Chen et al., 2019) later combined the 2-hop and 3-hop variants as PQ+ and PQL+ to evaluate unrestricted-hop reasoning and learned stopping, while also noting the benchmarks’ small graphs, repetitive relations, and template-generated language. SRN (Qiu et al., 2020) adopted a similar mixed-hop setting under the names PQ-M and PQL-M, formulating the task as weakly supervised sequential decision making. Our reconstruction follows this mixed-hop setting while adding family-level split control and retaining all released annotation references associated with each reconstructed QA instance. Because these systems use different multi-hop reasoning formulations, their reported mixed-hop results should not be interpreted as measuring a common notion of explicit graph-navigation performance. Appendix C discusses this distinction when relating their published results to our reconstruction.

Multiple answers and reasoning paths. Answer multiplicity is already part of the original benchmark design: IRN evaluates predictions against a valid answer set for one-to-many relations (Zhou et al., 2018). MRP-QA (Wang et al., 2022) further studies alternative reasoning paths in PQL by enumerating paths of at most three hops from the topic entity to the answer, reporting multiple valid paths for substantial portions of PQL-2H and PQL-3H, 12.5% and 45.2% respectively. Our focus is therefore not the existence of multiple answers or paths, but how their graph-realizable multiplicity changes when the released task graph is replaced by the larger source graph while the released relationchain annotations remain fixed.

Incomplete-KG and robustness studies. Prior work has also changed the graph supporting PQ/PQL, but mainly by deleting information from the released task graph. IRN evaluates an incomplete-KG condition after removing half of the PQ-2H triples (Zhou et al., 2018), and QA2MN (Li et al., 2022) similarly evaluates robustness when only half of the original taskgraph triples are retained. These interventions ask whether a model can tolerate missing support. They are not equivalent to source restoration, which moves in the opposite direction and can introduce additional branches, intermediate entities, answer endpoints, and shortcuts that were suppressed by benchmark filtering.

Later PQ/PQL use and structural analysis. Later work continues to use the hop-specific and mixed variants. For example, HyperMR reports PQ-2H, PQ-3H, PQ-M and their PQL counterparts (Wang et al., 2024). Prior work on traceable multi-hop graph navigation (Hernandez et al., 2026b) established the structural calibration tools reused here: exact ${ \mathrm { R W - A n s } } _ { p } ,$ its Monte Carlo estimate RW-Ans<sub>MC</sub>, the answer-oracle Shortest Path reference, and the PED, RED, F1<sub>SG</sub>, and F1<sub>REL</sub> trajectory metrics. That study’s Appendix C already applies the random-walk diagnostics and local-navigation statistics to release-derived mixed PQ/PQL graphs. A concurrent study of small language models evaluates isolated iterative graph navigation beyond answer accuracy (Hernandez et al., 2026a). We reuse both the established calibration suite and the frozen-SLM navigation protocol, but apply them to a different experimental question: how navigation changes under a matched filtered-versus-source graph intervention with fixed released QA semantics.

Novelty boundary. Prior work therefore covers PQ/PQL construction, mixed-hop stopping, templated language, incomplete-KG robustness, answer multiplicity, alternative reasoning paths, and structural navigation diagnostics. To the best of our review, however, we did not find a study that holds the released questions, topic entities, relationchain annotations, split/family assignment, and released answer target fixed while replacing the released task-filtered graph with the distributed source/original knowledge graph. Our contribution is this matched environmental substitution and its effect on benchmark navigability, rather than a first general audit of PQ/PQL.

## 3 Problem Formulation

Question-conditioned graph navigation. Let $G = ( \mathcal { E } , \mathcal { R } , \mathcal { T } )$ be a directed knowledge graph with entities E, relations R, and labeled triples ${ \mathcal { T } } \subseteq { \mathcal { E } } \times { \mathcal { R } } \times { \mathcal { E } }$ . A QA instance $q$ contains a natural-language question, a topic entity $\boldsymbol { e } _ { s } ,$ a released valid-answer set $A _ { \mathrm { r e l e a s e d } } ( q )$ , and one or more released relation chains $\mathcal { R } ^ { \star } ( q )$ . A navigation policy starts at $e _ { s }$ and selects among the labeled outgoing actions exposed by the active graph until the fixed evaluation horizon is reached.

Filtered and source graphs. We denote the released task-filtered graph by $G _ { F }$ and the larger distributed source/original knowledge graph by $G _ { S }$ Our primary intervention keeps $q , e _ { s } , A _ { \mathrm { r e l e a s e d } } ( q )$ and $\mathcal { R } ^ { \star } ( q )$ fixed while replacing $G _ { F }$ with $G _ { S }$ Thus the primary comparison is

$$
( G _ { F } , A _ { \mathrm { r e l e a s e d } } ) \quad \longleftrightarrow \quad ( G _ { S } , A _ { \mathrm { r e l e a s e d } } ) ,\tag{1}
$$

with the same family-level train/dev/test assignment in both conditions. We deliberately avoid calling $G _ { S }$ “full Freebase,” because the released source files are benchmark artifacts rather than a claim to contain the complete original knowledge graph.

Graph-consistent answer and path sets. For an active graph $G ,$ let $A _ { \mathrm { g r a p h } } ( q )$ be the set of endpoints obtained by starting at $e _ { s }$ and following any released chain in $\mathcal { R } ^ { \star } ( q )$ under the benchmark’s unrestricted-walk semantics. Likewise, let $\mathcal { P } _ { \mathrm { g r a p h } } ( q )$ contain every entity-level realization of those chains in $G .$ The released answer set $A _ { \mathrm { r e l e a s e d } } ( q )$ remains the primary benchmark target, while $A _ { \mathrm { g r a p h } } ( q )$ and $\mathcal { P } _ { \mathrm { g r a p h } } ( q )$ are secondary structural quantities used to measure graph-induced answer and path expansion. This separation prevents source restoration from automatically promoting every newly reachable endpoint to natural-language semantic gold.

Adopted navigation diagnostics. We adopt the structural and trajectory-evaluation protocol of prior work (Hernandez et al., 2026b) rather than introduce a new metric suite. ${ \mathrm { R W - A n s } } _ { p }$ is the exact fixed-horizon probability that a uniform random walker over labeled legal actions terminates in the valid answer set, while RW-Ans<sub>MC</sub> is its Monte Carlo estimate based on sampled walks. The same work defines an answer-oracle Shortest Path structural reference that is given the topic entity, navigation graph, and valid answer set, but not the annotated reasoning path, and deterministically selects a shortest route to any valid answer. We likewise reuse Path Edit Distance (PED) and entity/subgraph overlap $\mathrm { F l } _ { \mathrm { S G } }$ for path fidelity: PED is the Levenshtein distance between the ordered predicted and reference edge sequences, while $F 1 _ { \mathrm { S G } }$ measures their order-invariant edge overlap. Together, these metrics capture complementary aspects of trajectory fidelity: ordered path agreement and order-invariant edge overlap. When multiple released entity-level paths or relation chains are valid, our multi-annotated evaluation takes the minimum edit distance or maximum overlap over the valid released references. This audit therefore changes the graph condition and valid-reference bookkeeping, not the definitions of RW-Ans<sub>p</sub>, RW-Ans<sub>MC</sub>, the Shortest Path reference, or the path-fidelity metrics. As previously noted (Hernandez et al., 2026b), the Shortest Path reference is not a path-fidelity upper bound because a graph-theoretic shortcut can reach a correct answer while disagreeing with the released reasoning chain.

Family-aware aggregation. Generated surface variants are grouped into structural question families for split control and aggregation. If family f contains $| f |$ evaluation instances with per-instance metric m<sub>i</sub>, the primary family-macro statistic is

$$
{ \overline { { m } } } _ { \mathrm { f a m } } = { \frac { 1 } { | { \mathcal { F } } | } } \sum _ { f \in { \mathcal { F } } } { \frac { 1 } { | f | } } \sum _ { i \in f } m _ { i } .\tag{2}
$$

Family-macro values are primary for the structural comparisons in this paper so that large surface-form families do not dominate the result.

Cycles and backtracking. Table 3 summarizes entity revisits and immediate backtracking in the original released annotations, before questionfamily aggregation. An entity revisit occurs when a path visits an entity more than once, whereas an immediate backtrack returns to the entity visited two positions earlier. Both behaviors are prevalent, particularly in PQL three-hop annotations, where nearly all reference paths revisit an entity. These behaviors expose a benchmark-design concern for future multihop KGQA datasets because they can weaken the alignment between the surface question, the annotated reasoning chain, and the navigation actually required to reach a valid answer. In particular, cyclic or self-returning annotations can make the nominal multi-hop trajectory unnecessary for answer retrieval, raising questions about whether the assigned hop count reflects required multi-hop reasoning. This concern is especially apparent when the topic entity itself is a released answer, since the benchmark can admit a valid zero-length solution despite providing a multi-hop reference trajectory. Appendix E separately examines wording-related irregularities that can further affect the interpretation of the released questions. For the present audit, however, these properties are part of the released benchmark and must remain unchanged. We therefore preserve the released walk semantics rather than imposing a no-repeated-entity constraint, which would alter the reference reasoning trajectories and the task being audited.

## 5.1 Structural references separate answer reachability from path fidelity

Tables 4 and 5 show that source restoration sharply reduces both released-answer reachability and trajectory fidelity for RW-Ans<sub>MC</sub> on PQ and PQL. The contrast is especially pronounced for PQL, where RW-Ans attains 54.1% released-answer

H@1 on the filtered graph despite using unguided uniform navigation, before falling to 7.8% under source restoration. Its path fidelity deteriorates in parallel, indicating that the filtered PQL graph makes both released endpoints and the released reasoning trajectories unusually accessible to unguided navigation. Under source restoration, random-walk trajectory fidelity also moves close to the low-fidelity end of both metrics, with PED approaching 3 and $\mathrm { F 1 } _ { \mathrm { S G } }$ approaching 0 under the fixed three-action horizon. ## 5.2 Frozen and learned policies remain sensitive to the graph condition

Tables 4 and 5 additionally report results for both frozen and trainable policies. Across all three frozen SLMs, source restoration reduces releasedanswer accuracy and trajectory fidelity on both benchmarks. The agreement in direction across independently frozen policies indicates that the effect is not specific to one SLM.

MINERVA shows the same qualitative sensitivity after training on each active graph. The PQL result is particularly informative because sourcegraph endpoint accuracy remains comparatively strong while agreement with the released reasoning trajectories deteriorates substantially. Selecting hyperparameters on the source development graph improves some source-graph metrics relative to the matched filtered-dev configuration but does not recover filtered-graph performance. The filtered-tosource change therefore persists after allowing the trainable policy a condition-matched tuning control.

Across the filtered conditions, PQL also yields higher released-answer H@1 than PQ for RW-${ \bf A n s _ { M C } } ,$ all three frozen SLMs, and MINERVA despite its larger graph and broader relation vocabulary. This consistent reversal shows that overall graph size and relation-vocabulary size are not reliable proxies for released-answer accessibility, which is shaped by the structure of the active navigation graph.

## 5.3 Graph-consistent evaluation explains only part of the degradation

Graph-consistent evaluation distinguishes disagreement with the released answer and path references from endpoints and trajectories that remain consistent with the released relation chains but become newly realizable after source restoration. Across random walking, the frozen policies, and MIN-ERVA, evaluating against $A _ { \mathrm { g r a p h } }$ recovers part of the released-answer loss on the source graph. This recovery shows that some predictions counted as incorrect under $A _ { \mathrm { r e l e a s e d } }$ nevertheless reach endpoints consistent with the same released relation chains in the restored graph. The effect is not uniform across models or benchmarks. For MIN-ERVA, the recovery is substantial on PQ but comparatively small on PQL, indicating that graphinduced answer expansion explains only part of the filtered-to-source performance gap.

The same distinction applies to trajectories. Evaluation against $P _ { \mathrm { g r a p h } }$ recovers part of the sourcegraph path-fidelity loss, particularly on PQ, while the recovery for MINERVA on PQL is much smaller. Appendix B.3 reports the complete graphconsistent trajectory evaluation. We therefore treat $A _ { \mathrm { g r a p h } }$ and $P _ { \mathrm { g r a p h } }$ as complementary graphrelative diagnostics rather than replacements for the fixed released benchmark targets.

## 5.4 Cross-graph transfer reveals environment specialization

Appendix D evaluates trained MINERVA checkpoints across graph conditions without destinationgraph retuning. Policies trained on $G _ { F }$ degrade substantially when transferred to $G _ { S }$ , whereas policies trained on $G _ { S }$ transfer more favorably to $G _ { F }$ Because the released targets remain available and the entity and relation vocabularies are fixed across conditions, this asymmetry cannot be explained by target disappearance or an out-of-vocabulary mismatch. The transfer results therefore provide additional evidence that learned navigation policies specialize to the graph environment in which they are trained.

Interpretation. The combined structural, frozenpolicy, trained-policy, graph-consistent, and transfer results do not imply that a larger graph is uniformly harder to navigate. Instead, they show that changing the active graph changes the decision problem induced by the same released QA task. Branching, reachable-state volume, answer and path multiplicity, unguided answer reachability, learned endpoint accuracy, and trajectory fidelity all respond to this intervention. The active graph should therefore be treated as part of the benchmark specification rather than as an interchangeable implementation artifact.

Community implications. The released PQ/PQL graphs remain useful controlled environments, but results obtained on them should be interpreted in light of their graph construction, generated language, answer annotations, and path conventions. In particular, high accuracy on the filtered graph does not establish equivalent navigation behavior on the distributed source KG or faithful recovery of the released reasoning trajectories. Appendix F summarizes cautions for interpreting and comparing results obtained on PQ/PQL.

## 6 Conclusion

We audited PathQuestion and PathQuestion-Large by treating source-graph restoration as a controlled intervention that changes the active navigation environment while keeping the released QA task fixed. Restoration substantially expands the effective navigation search space, increases graphconsistent answer and path multiplicity, reduces unguided reachability to released answers, and lowers shortest-path agreement with the released reasoning traces. These structural changes persist across three frozen SLM policies and trained MINERVA policies, showing that the effect is not limited to a model-free calibration.

The completed learned-policy experiments sharpen the distinction between endpoint success and trajectory fidelity. MINERVA retains relatively strong source-graph answer accuracy on PQL while its agreement with the released paths degrades substantially. Graph-consistent evaluation recovers part of the apparent answer and path loss by crediting newly realizable endpoints and trajectories that satisfy the same released relation chains, but the recovery is incomplete and strongly benchmarkdependent. Cross-graph transfer provides an additional control. Filtered-trained policies degrade sharply when moved to the restored source graph, whereas source-trained policies remain comparable or improve when the graph is contracted to the filtered environment. Because the released targets remain available in both KGs, this asymmetry isolates sensitivity to the surrounding graph structure rather than target disappearance.

These results show that benchmark graph construction is a consequential part of the navigation task specification. PQ/PQL remain useful controlled benchmarks, but their filtered graphs, cyclic path conventions, multiple valid references, and family structure must be made explicit when results are interpreted or compared. The central implication is not that source graphs are universally harder. It is that the same nominal multi-hop QA task can induce materially different navigation behavior when the graph defining the legal actions changes. Future KGQA benchmarks and evaluations should therefore report graph provenance and filtering, represent multiple released and graph-consistent answers and paths explicitly, and separate released-target performance from graphrelative structural validity.

## Limitations

This study focuses on PathQuestion (PQ) and PathQuestion-Large (PQL), and its findings may not generalize directly to other multi-hop KGQA benchmarks with different graph construction procedures, question distributions, or annotation conventions.

Our source-graph intervention uses the larger knowledge graphs distributed with the original benchmark artifacts. These graphs should not be interpreted as complete versions of Freebase. Consequently, the analysis measures the effects of restoring the available source graphs rather than those of removing all possible benchmark filtering.

Graph-consistent answers and paths are defined by the released relation-chain annotations. Although this provides a reproducible structural criterion, it does not guarantee that every newly reachable endpoint is semantically correct for the naturallanguage question. We therefore retain the released answers and paths as the primary evaluation targets.

Finally, our policy-based evaluation covers a limited selection of frozen small language models and trained MINERVA policies under a fixed navigation horizon. Other architectures, training procedures, or adaptive stopping strategies may respond differently to graph restoration.

## Ethical Considerations

This study uses publicly released KGQA benchmarks and does not collect new personal data. The underlying knowledge graphs may contain factual errors, omissions, or biases inherited from their sources. We distinguish graph-consistent answers from released benchmark answers to avoid overstating model correctness or semantic validity.

## A.2 Topic–answer identity and cyclic structure

Table 6 reports how often the topic entity is itself a released answer, broken down by annotated hop count. The phenomenon is relatively limited in PQ but is a substantial property of PQL, particularly among its 3-hop instances. It also persists after family aggregation, affecting 76 PQ families and 592 PQL families. For answer-based evaluation, the relevant case is whether the topic belongs to the released answer set, since any member of that set constitutes a valid endpoint. When this occurs, an answer-oracle shortest-path procedure can legitimately select the topic itself and return a zero-length trajectory even though the released annotation follows a 2- or 3-hop walk. For example, PQ Question 18 asks “who is the child of shah\_shuja’s parent?”, and its released reference path returns to the topic entity after 2 hops. Likewise, PQL Question 1168 asks “what is the recording of recording of Robin\_Hood’s recording?”, and its released 3-hop reference path remains at the topic entity throughout. These examples illustrate that shortest answer reachability and agreement with the annotated reasoning trajectory are distinct properties, especially in the presence of cyclic and immediate-backtracking structure.

Source restoration therefore does not replace the benchmark target. Instead, it reveals additional entities and paths that satisfy the released structural annotation in the restored KG.

## C Relation to Previously Reported Mixed-Hop Results

For historical context, Table 10 places evaluationinstance micro Hits@1 for MINERVA on our filtered mixed-hop reconstruction alongside previously reported mixed-hop PQ/PQL results. We use instance-micro aggregation in this table only to align as closely as possible with the conventional instance-weighted reporting in the earlier literature. The comparison is not controlled because UHop and SRN construct mixed-hop splits that differ from our family-controlled reconstruction, and their released implementations do not permit us to retrain the corresponding models under our split. We therefore provide these values only for historical orientation and do not use them to rank methods or support the conclusions of the graph-restoration audit.

The historical methods also differ in what their reported accuracy measures about multi-hop reasoning. IRN performs iterative relation reasoning rather than explicit graph navigation. At each hop, it predicts over a global relation vocabulary and uses the predicted relation representation to update a continuous reasoning state. Although it can also predict intermediate entities, those entities do not become graph states whose outgoing edges define the next action space. IRN therefore does not execute an entity-to-entity trajectory through the KG. UHop is closer to graph navigation because its candidate relations are obtained from the current graph context and a selected relation is used to traverse the KG. However, the model scores relation choices rather than individual outgoing relation– entity edges. When a selected relation leads to multiple entities, the decision therefore does not identify which destination entity constitutes the next model state. UHop consequently produces an explicit relation trajectory through the graph, but not necessarily a unique entity-by-entity trajectory of the form evaluated in our navigation setting. SRN is more directly comparable to MINERVA because its policy selects outgoing relation–entity actions and explicitly updates the current KG entity. Their PQ-to-PQL differences therefore should not be interpreted as measurements of a common notion of graph-navigation difficulty.

The prior studies also do not isolate a single cause for their lower PQL results. The original IRN work characterizes PQL as more challenging because it uses a larger KG with fewer training examples, while its broader relation vocabulary also changes the learned relation-prediction problem. UHop reports a different relation-candidate distribution on PQL and finds that most PQ/PQL errors arise from relation extraction rather than termination. SRN directly navigates outgoing KG actions, but its experiments do not separate the effects of graph structure, relation representation, trainingdata availability, and beam-search behavior. We therefore treat the historical PQ-to-PQL decline as an empirical property of those published model– benchmark configurations rather than evidence that PQL is intrinsically harder to navigate.

Our filtered reconstruction exhibits the opposite endpoint-accuracy trend. MINERVA obtains higher Hits@1 on PQL than on PQ, and the same direction appears for all three frozen SLM policies and the random-walk calibration in Tables 4 and 5. For example, RW-Ans<sub>MC</sub> rises from 0.175 on PQ to 0.541 on PQL. Because the historical results differ from our reconstruction in splits, preprocessing, training objectives, and evaluation protocols, this reversal cannot be attributed specifically to model architecture. Instead, it shows that benchmark name and nominal graph scale alone do not determine effective navigation difficulty. The instantiated graph and evaluation protocol can materially change the task presented to a navigation policy.

## D Cross-graph Transfer of Learned Navigation

The primary MINERVA comparison in Sec. 5 trains and evaluates each policy on the same active KG. A complementary question is whether a policy trained under one graph condition transfers to the other without additional training or destination-graph tuning. In particular, does the learned policy remain robust when the graph structure changes, or does it become specialized to its training environment even though the same released answers and annotated reference paths remain available in both KGs? As in Tables 4 and 5, the model entity and relation ID vocabularies are fixed across both graph conditions, so cross-graph evaluation does not introduce an out-of-vocabulary mismatch. The transfer intervention can nevertheless expose graph structure that was absent during training, particularly when a policy trained on the filtered graph is evaluated on the restored source graph.

For each training condition, hyperparameters are selected on the corresponding development graph and the resulting checkpoints are evaluated on both $G _ { F }$ and $G _ { S }$ . Thus, $G _ { F }  G _ { S }$ measures transfer under graph expansion, whereas $G _ { S }  G _ { F }$ measures transfer under graph contraction. The same trained seeds are reused across the paired evaluation conditions, so the comparison changes only the graph presented to a fixed trained policy.

Tables 11 and 12 show a consistent directional asymmetry across both benchmarks. Policies trained on $G _ { F }$ transfer poorly to $G _ { S }$ , with substantial degradation in both answer accuracy and trajectory fidelity. In contrast, when policies trained on $G _ { S }$ are transferred to $G _ { F }$ , their answer accuracy remains comparable to or improves over their in-domain $G _ { S }  G _ { S }$ performance, while their path fidelity improves substantially relative to the same source-graph baseline. The graph-expansion penalty is particularly pronounced for PQL, consistent with the substantially larger change in its effective navigation search space under source restoration. Because the released answers and reference paths remain available in both graph conditions, the degradation under graph expansion cannot be attributed to the target trajectory disappearing. Instead, the results indicate that successful navigation on $G _ { F }$ depends in part on the surrounding alternatives encountered during training: when additional graph structure is restored, the learned action preferences do not remain invariant. The reverse direction provides a useful control, since removing alternatives from a policy trained on $G _ { S }$ does not produce the same loss and instead tends to improve agreement with the released reference paths. The transfer asymmetry therefore isolates sensitivity to the graph environment itself, strengthening the audit conclusion that graph construction can change the learned navigation problem even when the nominal QA targets are held fixed. We treat this asymmetry as a transfer diagnostic for MINERVA rather than as a general claim that source-graph training necessarily improves cross-graph robustness for other navigation architectures.

## E Preliminary Wording Audit

During reconstruction, we observed cases in which the generated natural-language question did not faithfully reflect the semantics of its released reasoning path. To assess whether these examples were isolated, we conducted an exploratory LLM-assisted audit of the released PQ-2H.txt, PQ-3H.txt, PQL-2H.txt, and PQL-3H.txt files alongside our reconstructed QA representations, using OpenAI ChatGPT (GPT-5.6 Sol, accessed September 30, 2026). The model was instructed to preserve the original benchmark annotations rather than repair them, distinguish explicit semantic contradictions from unsupported lexical restrictions, and examine released reasoning paths and crossquestion evidence whenever possible. The prompt and outputs are provided as artifacts of this audit. Because the audit is LLM-assisted and does not constitute exhaustive human annotation, we do not interpret its aggregate flag rates as benchmark error rates or use them as evidence for the structural claims in the main paper. Furthermore, some classifications, particularly semantic underspecification and type-role anomalies, remain heuristic. Nevertheless, several directly inspectable examples reveal recurring inconsistencies between the natural-language wording and the annotated reasoning structure.

PQ: gender-specific template drift. PQ uses generic kinship relations, including children, parents, and spouse, but the corresponding questions sometimes replace these relations with gender-specific terms such as daughter, dad, or husband. Such lexicalizations impose semantic restrictions not encoded by the generic relation and can directly contradict the released annotations. For example, the Question 15 “the sex of claudius’s husband?” follows the annotated path claudius <sup>spouse</sup>−−−−→ aelia\_paetina a male spouse, whereas the annotated path explicitly identifies the intermediate entity as female. Similarly, Question 60 “what is the princess\_elizabeth\_of\_england’s dad’s sex?” follows princess\_elizabeth\_of\_england parents gender henrietta\_maria\_of\_france female. Here, the generic parents relation is rendered as dad, despite the annotated intermediate entity being female. Both contradictions are directly observable within their respective released reasoning paths, without requiring external biographical verification.

Other inconsistencies become apparent when comparing annotations across released questions. For example, Question 429 “the children of daughter of p\_j\_kennedy?” follows $\mathsf { p \mathrm { - } j \mathrm { - } k e n n e d y \quad \xrightarrow { c h i l d r e n } }$ joseph\_p\_kennedy\_sr <sup>children</sup>−−−−−→ rosemary\_kennedy. Although the question describes the intermediate entity as a daughter, other released PQ annotations explicitly identify joseph\_p\_kennedy\_sr as male. These examples indicate that the surface wording can introduce constraints absent from, or inconsistent with, the released graph annotations. They do not imply that every gender-specific lexicalization is incorrect, since some may agree with the corresponding entities even when the underlying relation remains generic.

PQL: predicate lexicalization collapse. PQL exhibits a different, mechanically identifiable phenomenon: distinct Freebase-style predicates can share the same visible relation phrase. In the inspected released annotations, 125 distinct full predicates are represented by 111 surface relation phrases, with 10 phrases corresponding to more than one predicate. For example, genre represents five distinct predicates spanning books, broadcast content, films, music albums, and television programs. Likewise, releases represents the distinct predicates \_\_music\_\_album\_\_releases, \_\_music\_\_record\_label\_\_releases, and \_\_music\_\_recording\_\_releases. Consequently, the generated question does not always preserve the predicate identity encoded in its released relation chain.

A concrete example is PQL Question 1663: “what is the releases of releases of Amsterdam’s artist?” The reconstructed instance contains two released relation chains, r2272→r2204→r2279 and r2272→r2204→r2204, which differ in their final predicate. These final predicates correspond to \_\_music\_\_recording\_\_releases and \_\_music\_\_album\_\_releases, respectively, but both are rendered as releases. The released answers include The\_Muffs and Another\_Day. All eight reconstructed PQL instances containing multiple released relation chains for the same question and answer set exhibit this particular final-hop lexicalization collision. Thus, these cases demonstrate a reproducible loss of relation-specific information in the question wording rather than merely awkward grammatical construction.

PQL: semantic type and argument-role mismatches. The exploratory audit also identifies compositions in which successive predicates imply incompatible semantic roles. For example, the released question “what is the tracks of Alfred\_Philippe\_Roll’s place\_of\_death?” follows the relation chain \_\_people\_\_deceased\_person\_\_place\_of\_death → \_\_music\_\_recording\_\_tracks, with the intermediate entity Paris. The first predicate identifies a location, whereas the second belongs to a music-recording namespace and ordinarily expects a different source-entity role. This discrepancy is observable from the released relation names and their composition, although it does not by itself establish that the underlying KG edges are invalid. We therefore treat such cases as possible semantic mismatches in the graph-to-language interface, rather than independently verified factual errors.

Scope and implications. These findings identify a separate source of ambiguity in PQ/PQL: the correspondence between natural-language questions and their annotated reasoning structures. In PQ, gender-specific lexicalizations can impose constraints that are absent from, or contradict, the underlying relations and entity annotations. In PQL, predicate lexicalization can obscure distinctions between relation types, while some generated questions combine predicates with potentially incompatible semantic roles. For question-conditioned navigation, these inconsistencies matter because the question is expected to guide relation selection, yet its wording may not uniquely or faithfully specify the annotated relation chain. Consequently, a trajectory that follows the released annotations need not fully satisfy the natural-language question, while a linguistically plausible interpretation may disagree with the released reference.

This distinction also qualifies the interpretation of graph-consistent evaluation. Our graph-relative answer and path sets are defined by realizations of the released relation chains, not by independent semantic validation of the natural-language questions. Thus, an endpoint or trajectory can be structurally consistent with the annotated chain without necessarily constituting a semantically correct answer to the question as written. Although the exploratory audit quantifies the prevalence of flagged wording inconsistencies under its classification criteria, these flags remain to be independently validated through systematic human annotation. Consequently, the reported counts should not be interpreted as confirmed benchmark error rates, and the audit does not establish the causal contribution of these inconsistencies to navigation accuracy or trajectory fidelity. Importantly, the original question wording and annotations are held fixed across our filtered and source graph conditions. We therefore preserve the released questions and annotations rather than repairing or excluding flagged instances, maintaining the matched intervention that isolates the effect of graph construction. The wording findings remain auxiliary to this comparison and motivate future human validation of question–relation alignment, while the mechanically verifiable lexicalization collisions provide reproducible evidence of information loss in the generated questions.

## F Cautions for Interpreting PQ/PQL Results

PQ/PQL remain useful controlled benchmarks, but several properties of their released artifacts limit the conclusions that can be drawn from performance on them. This appendix summarizes those interpretive boundaries rather than restating the empirical comparisons reported in Section 5.

Filtered-graph results do not establish source-KG performance. A result obtained on the released task-filtered graph should be interpreted as performance within that particular navigation environment. It should not, without additional evidence, be extrapolated to navigation or retrieval over the larger source KG from which the benchmark was derived. For retrieval-based systems, this distinction is especially important because the released graph already restricts which entities, relations, and edges are available before retrieval begins. Accordingly, strong performance on PQ/PQL does not by itself demonstrate robustness to substantially larger candidate spaces or denser graph neighborhoods.

Graph consistency does not establish languagelevel correctness. Graph-consistent answers and paths certify consistency with the released relation chains under the active graph, not independent semantic correctness of the natural-language question. As Appendix E illustrates, mechanically generated PQ/PQL questions can express constraints or ambiguities that are not captured by those structural annotations. Released answers, graph-consistent answers, and answers justified by the full surface semantics should therefore not be treated as interchangeable notions of correctness.

Answer accuracy does not establish faithful reasoning. A correct endpoint should not be interpreted as evidence that the released reasoning trajectory was followed. Conversely, disagreement with one released path does not establish that a trajectory is structurally invalid when another graphconsistent realization exists. Endpoint correctness and trajectory agreement should therefore be evaluated separately when making claims about navigation or reasoning behavior.

Nominal hop count does not necessarily measure required reasoning depth. The annotated hop count describes the released reference walk rather than the minimum number of actions required to reach a valid answer. As Appendix A.2 shows, cyclic or self-returning references and topic– answer identity can admit shorter correct routes, including zero-action solutions. Claims about reasoning depth should therefore not be based on the nominal 2-hop or 3-hop label alone.

The benchmark name does not uniquely specify the experimental setting. Published PQ/PQL results may use different hop-specific or mixedhop reconstructions, graph artifacts, action definitions, stopping conventions, inverse relations, candidate limits, answer aggregation rules, and pathreference handling. Trainable navigation systems can additionally differ in which graph condition is used for training and hyperparameter selection. Consequently, results labeled simply as “PQ” or “PQL” should not be assumed directly comparable unless these choices are sufficiently aligned. Studies using these benchmarks should identify the graph artifact and preprocessing used and state how multiple answers, multiple paths, repeated entities, stopping actions, and aggregation are handled.

Scope of interpretation. These cautions do not invalidate results obtained on the released PQ/PQL benchmarks. They instead delimit what those results directly support. PQ/PQL remain useful controlled benchmarks for studying relation composition and graph navigation when their graph, annotation, and language conventions are made explicit. Claims about source-KG robustness, retrieval difficulty, unique reasoning explanations, required reasoning depth, or fine-grained natural-language understanding require additional evidence beyond performance on the released benchmark alone.
